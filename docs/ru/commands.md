# Команды

Командная поверхность целиком: где живут методы, что все они возвращают, как ответ сопоставляется с
вызвавшим его запросом, как отключить исключения и как отправить кадр, который библиотека не
моделирует.

## Где живут команды

Всё, что доступно после успешного `login()`, висит на четырёх свойствах-ресурсах и одном методе
клиента:

```python
client.domain     # доменные команды RFC 5731
client.contact    # команды контактов RFC 5733
client.host       # команды хостов RFC 5732
client.poll       # очередь сообщений
client.balance()  # собственный запрос счёта у реестра
```

Каждое свойство строится один раз и переиспользуется, так что `client.domain` — всегда один и тот же
объект, и держать на него ссылку нормально.

## Полный указатель команд

Каждый метод здесь отправляет ровно одну команду EPP и возвращает [`Response`](responses.md).
Подробности — аргументы, примеры, что приходит в ответ — на страницах объектов.

### Домены — [domains.md](domains.md)

| Метод | EPP |
|---|---|
| `check(names: List[str], fee: Optional[Dict[str, Any]] = None, currency: Optional[str] = None)` | `<check>` + `fee:check` из RFC 8748 |
| `info(name: str, auth_info: Optional[str] = None, hosts: str = "all")` | `<info>` |
| `create(name, *, years=None, registrant=None, contacts=None, nameservers=None, auth_info=None, license=None, sec_dns=None, fee=None)` | `<create>` |
| `update(name, *, add=None, rem=None, chg=None, restore=False, license=None, sec_dns=None, fee=None)` | `<update>` |
| `renew(name: str, cur_exp_date: str, years: int = 1, fee=None)` | `<renew>` |
| `restore(name: str, fee=None)` | `<update>` + `rgp:restore` из RFC 3915 |
| `delete(name: str)` | `<delete>` |
| `transfer(op: str, name: str, auth_info=None, years=None, fee=None)` | `<transfer op="…">` |
| `create_builder(name: str)` | [билдер](builders.md) для `create` |
| `update_builder(name: str)` | [билдер](builders.md) для `update` |

### Контакты — [contacts.md](contacts.md)

| Метод | EPP |
|---|---|
| `check(ids: List[str])` | `<check>` |
| `info(contact_id: str, auth_info: Optional[str] = None)` | `<info>` |
| `create(contact_id, *, name=None, org=None, street=None, city=None, sp=None, pc=None, cc=None, type="int", postal_infos=None, voice=None, fax=None, email=None, auth_info=None, disclose=None)` | `<create>` |
| `create_auto(**options)` | `<create>` с `Contact.AUTO_ID` в качестве идентификатора — идентификатор выдаёт реестр |
| `update(contact_id, *, add_statuses=None, rem_statuses=None, chg=None)` | `<update>` |
| `delete(contact_id: str)` | `<delete>` |
| `transfer(op: str, contact_id: str, auth_info: Optional[str] = None)` | `<transfer op="…">` |
| `create_builder(contact_id: str, email: str)` | [билдер](builders.md) для `create` |
| `update_builder(contact_id: str)` | [билдер](builders.md) для `update` |

`Contact.AUTO_ID` — зарезервированный идентификатор, которым вы просите реестр выбрать идентификатор
контакта вместо вас. Выданный идентификатор приходит в ответе, и **этот ответ — единственное место,
где он появляется**: прочитайте его через `object_name()` и сохраните.

## Что возвращает команда

Каждая команда возвращает `Response` — никогда `None` и никогда голый словарь. Объект оборачивает
разобранный ответ и отвечает на вопросы о нём; [Ответы](responses.md) описывают каждый аксессор.

```python
response = client.domain.create("example.com.ua", years=1, registrant="acme-01")
response.code()          # 1000
response.is_success()    # True для любого 1xxx
response.is_pending()    # True для 1001
response.object_name()   # "example.com.ua"
response.sv_trid()       # идентификатор этой операции у реестра — сохраните его
```

| Код | Значение | Что делает библиотека | Что делаете вы |
|---|---|---|---|
| `1000` | выполнено | возвращает `Response` | продолжайте |
| `1001` | принято, завершается офлайн | возвращает `Response`; `is_success()` и `is_pending()` оба `True` | **не отправляйте повторно.** Итог придёт позже как poll-уведомление |
| `1300` / `1301` | poll: пусто / ожидает сообщение | возвращает `Response` | см. [Poll](poll.md) |
| `1500` | сессия завершается | возвращает `Response` из `logout()` | отключитесь |
| `2xxx` | отказано; ничего не изменилось | бросает исключение, если вы это не отключили | см. [Ошибки](errors.md) |

**1001 — именно тот код, на котором спотыкаются.** Команда принята и обрабатывается офлайн: для
трансфера всегда, для прочих операций — в зависимости от зоны. Относитесь к этому как к успеху в
процессе: запишите svTRID, следите за очередью poll в ожидании итога и никогда не отправляйте
команду ещё раз «на всякий случай». Соответствующее уведомление несёт `pending_action_data()`, чей
`svTRID` и связывает его с отправленной вами командой.

Даты и деньги в ответе — это **собственные строки сервера** (`2027-04-01T09:15:00Z`, `"100.00"`),
никогда не `datetime` и никогда не `float`. Так сделано намеренно, и причины стоит знать, прежде чем
строить на этом: см. [Ответы](responses.md#даты-и-деньги).

## Клиентские идентификаторы транзакций
Каждая команда несёт `clTRID`, который выбираете вы и который сервер отражает обратно; каждый ответ
несёт `svTRID`, назначаемый реестром.

Библиотека штампует clTRID на каждом кадре автоматически:

```
PYTHON-SDK-20260816093012-4821-0001
│       │              │    └── счётчик, свой у каждого объекта клиента
│       │              └─────── идентификатор процесса
│       └────────────────────── метка времени UTC
└────────────────────────────── Config.cltrid_prefix
```

Идентификаторы из одного процесса делят один и тот же средний сегмент и остаются уникальными между
параллельными процессами. Меняйте префикс через `Config.cltrid_prefix`, чтобы свой трафик был узнаваем
в общем журнале, и держите его коротким: протокол ограничивает идентификатор целиком 64 символами.

**Сохраняйте svTRID рядом с объектом, которого касалась команда.** Это значение, по которому
поддержка находит операцию; clTRID не значит ничего ни для кого, кроме вас. Записывайте оба, на
каждой команде, включая удавшиеся: именно с ними вы сравниваете, когда какая-нибудь из последующих
не удастся.

### Ответы сопоставляются со своими командами

Каждый ответ проверяется по clTRID, который отправила его команда. Несовпадение означает, что поток
байтов рассинхронизирован — залетел незапрошенный кадр или две команды оказались в полёте
одновременно, — и библиотека бросает `ConnectionException` и закрывает соединение, вместо того чтобы
отдать вам чужой результат.

Так сделано ради того, чем оборачивается отсутствие проверки: ответ, принадлежащий предыдущей
команде, иначе не отличить от ответа на эту, а для продления это значит, что `renew("example2.com.ua")`
вернёт 1000 с датой окончания домена a — и оба будут затарифицированы. Как только смещения разошлись,
каждый следующий кадр в потоке тоже под подозрением, поэтому соединение закрывается, а не просто
отмечается как подозрительное. Переподключитесь и войдите снова.

Поэтому же на одном соединении команды отправляют по одной. Нужна пропускная способность —
открывайте больше сессий; не накладывайте команды внутри одной.

## Переключатель throw_on_failure

По умолчанию любой код ответа от 2000 и выше бросает исключение, а класс зависит от кода — см.
[Ошибки](errors.md). В сообщении назван предмет, если реестр его указал, поэтому отказ внутри пакета
из пяти имён говорит, о каком имени речь.

```python
client.throw_on_failure(False)      # возвращает клиент, поэтому вызовы сцепляются

response = client.domain.check(["example.com.ua"])
if not response.is_success():
    log.warning("EPP %d: %s", response.code(), response.message())
```

`throw_on_failure(False)` выключает исключения для объектных команд, а `throw_on_failure(True)`
включает их обратно. Две вещи бросают исключение в любом случае, потому что отдать вместо этого
осмысленный `Response` не получится:

- **`login()`** бросает при любом коде, кроме 1000. Продолжать не во что — сессии нет.
- **`poll.drain()`** бросает, когда ответ на poll — это ни уведомление, ни пустая очередь. Прочитать
  такое как «очередь разобрана» значило бы отчитаться об успехе, не прочитав ничего.

Выключив это, вы берёте обнаружение сбоя на себя. `create`, чей код 2104 вы не проверили, — это
домен, который ваша система считает зарегистрированным.

## Произвольные кадры

Всё, чего не моделирует высокоуровневый API, можно собрать через `Frame` и отправить через
`client.request()`. Это аварийный выход для расширения реестра, специфичного именно для вашей учётной
записи, а не то, что нужно обычной интеграции.

```python
from epptools import Frame, Namespaces

frame = client.frame()                       # <command> с уже проставленным clTRID
check = frame.ns(frame.verb("check"), Namespaces.DOMAIN, "domain:check")
frame.ns(check, Namespaces.DOMAIN, "domain:name", "example.com.ua")

response = client.request(frame)             # или client.request(raw_xml_string)
print(response.availability())
```

| Член | Что делает |
|---|---|
| `client.frame()` | Новый `Frame` с уже сгенерированным clTRID. |
| `Frame.command(cltrid)` | Кадр с clTRID, который выбираете вы. |
| `frame.verb(name)` | Добавляет глагол команды — `check`, `info`, `create`, `update`, `renew`, `transfer`, `delete`, `poll`, `login`, `logout` — и возвращает его. |
| `frame.extension()` | Добавляет `<extension>` один раз и возвращает его; вызывайте сколько угодно. |
| `frame.epp(parent, name, text=None, attrs=None)` | Добавляет элемент в базовом пространстве имён `epp-1.0`. |
| `frame.ns(parent, ns_uri, qname, text=None, attrs=None)` | Добавляет элемент с пространством имён, например `frame.ns(parent, Namespaces.DOMAIN, "domain:name", "example.com.ua")`. |
| `frame.to_xml()` | Сериализует кадр. Вызывать можно не раз — запишите его в журнал, потом отправьте. |
| `frame.root` | Нижележащий элемент `ElementTree` — на всё, чего не покрывают помощники. |
| `client.request(frame_or_xml)` | Отправляет `Frame` или сырую XML-строку и возвращает разобранный `Response`. |

Сборщик кадров гарантирует порядок дочерних элементов из RFC 5730 — содержимое команды, затем
необязательный `<extension>`, затем `<clTRID>` последним — и задаёт текст на узлах элементов, а не
склеивает строки, поэтому значение с `&` или `<` экранируется, а не порождает кадр, на который
сервер ответит 2001.

`Namespaces` держит константы URI, чтобы ни один из них не пришлось набирать руками: `EPP`,
`DOMAIN`, `CONTACT`, `HOST`, `SECDNS` (RFC 5910), `RGP` (RFC 3915), `FEE` (RFC 8748), `LOGINSEC`
(RFC 8807), плюс `DEFAULT_OBJ_URIS` и `DEFAULT_EXT_URIS`.

С кадром, который вы собрали сами, обходятся так же, как с собранным библиотекой: отражённый clTRID
проверяется, ответ разбирается в `Response`, а код ошибки бросает исключение, если вы это не
отключили. Берите из `Namespaces` те URI, которые действительно объявлены в приветствии: расширение,
которого сервер не обслуживает, отклоняется кодом 2103.

### Собственные расширения вашего реестра

Каждый URI в `Namespaces` определён каким-нибудь RFC и одинаков у любого реестра в мире. С
СОБСТВЕННЫМИ расширениями реестра — лицензией на торговую марку, ценой, балансом учётной записи —
это уже не так, и константы для них там не будет: нет значения, которое было бы верным более чем для
одного реестра.

Они **определяются из `<greeting>`**. Любой сервер перечисляет то, что поддерживает, ещё до того как
вы что-то отправите, поэтому сразу после `connect()` клиент уже знает:

```python
client.connect()

client.registry_ext_uri()      # например 'http://registry.example/epp/registry-1.0', либо None
client.registry_balance_uri()  # например 'http://registry.example/epp/balance-1.0', либо None
```

`None` означает, что этот сервер такого расширения не объявляет, — это факт о сервере, а не ошибка.
Команды, которым расширение необходимо, об этом говорят, а не догадываются: `domain.create` с
`license`, `host.delete` с `force` и `balance()` бросают `ConfigException`, называя, что именно
понадобилось, и перечисляя, что сервер предложил. В этом отказе и есть смысл. Расширение, отправленное
в пространстве имён, которого сервер не знает, **игнорируется, а не отвергается**, — то есть догадка
вернулась бы как `1000 OK` с молча не установленной лицензией.

Определение сопоставляет последний сегмент объявленного URI — `.../registry-1.0`, `urn:…:balance`, —
и это соглашение, которому реестры следуют, а не правило, которое кто-то принуждает соблюдать. Если
реестр называет свои расширения иначе, задайте их сами — тогда приветствие не спрашивается:

```python
config = Config(
    host="epp.registry.example", clid="EXAMPLE", password="...",
    registry_ext_uri="urn:example:params:xml:ns:myreg-1.0",
    registry_balance_uri="urn:example:params:xml:ns:myreg-balance-1.0",
)
```
