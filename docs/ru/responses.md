# Ответы

Каждая команда возвращает `Response`. Он оборачивает ответ, присланный реестром, и отвечает на
вопросы о нём, так что чтение ответа никогда не означает поиск в словаре по строке, которую пришлось
угадать, и никогда не означает обход XML.

Поиск элементов не зависит от пространств имён — он идёт по локальному имени элемента, — поэтому
смена префиксов в ответе никогда не ломает аксессор.

Всюду действуют два соглашения:

- Аксессор, которому нечего сообщить, возвращает `None`, пустой список или пустой словарь. Он не
  бросает исключение. Что именно из трёх — сказано в таблицах ниже для каждого аксессора.
- **`None` означает «ответ ничего об этом не сказал»**, а это не то же самое, что отрицание. Больше
  всего разница важна для `is_available()`, и строка, регистрирующая домен, не должна обходиться с
  ними одинаково.

## Даты и деньги
- **Даты приходят собственной строкой реестра** — `2027-04-01T09:15:00Z` или со смещением, — никогда
  не `datetime`. Какой календарный день получит продление, решает реестр, а переформатирование через
  местный часовой пояс — это то, из-за чего клиент в итоге показывает вчерашнюю дату и по ней же
  продлевает.
- **Деньги приходят точной десятичной строкой**, никогда не `float`. `0.1 + 0.2` в двоичной
  плавающей точке не равно `0.3`, и просуммированный так баланс уплывает. Для арифметики берите
  `decimal.Decimal`, а для хранения оставляйте строку.

## Код ответа и идентификаторы транзакций

| Аксессор | Возвращает | Когда в ответе ничего нет |
|---|---|---|
| `code() -> int` | Код ответа EPP: 1000, 1001, 2303 … | `0` для приветствия и для любого кадра без `<result>` |
| `message() -> Optional[str]` | Понятный человеку `<result><msg>` | `None` |
| `message_lang() -> Optional[str]` | Язык этого сообщения: `en`, `uk`, `ua`, `ru` | `None` |
| `is_success() -> bool` | `True` для любого кода 1xxx | `False` |
| `is_pending() -> bool` | `True` только для 1001 — принято, завершается офлайн | `False` |
| `is_greeting() -> bool` | `True`, когда этот кадр — `<greeting>` | `False` |
| `cl_trid() -> Optional[str]` | Клиентский идентификатор транзакции, отражённый обратно | `None` |
| `sv_trid() -> Optional[str]` | Собственный идентификатор операции у реестра | `None` |

Сохраняйте `sv_trid()` рядом с объектом, которого касалась команда. Именно по нему поддержка находит
операцию. `message()` — это заголовок результата: в ответе на poll это каждый раз одно и то же
постоянное предложение, а текст уведомления лежит в `queue_message()`.

## Идентичность объекта — любой объект

Эти отвечают одинаково для домена, хоста и контакта.

| Аксессор | Возвращает | Когда в ответе ничего нет |
|---|---|---|
| `object_name() -> Optional[str]` | Объект, о котором этот ответ: доменное имя, имя хоста или **идентификатор** контакта | `None` |
| `roid() -> Optional[str]` | Собственный идентификатор объекта в реестре | `None` |
| `sponsor() -> Optional[str]` | `clID` — регистратор, которому объект принадлежит сейчас | `None` |
| `created_by() -> Optional[str]` | `crID` — регистратор, который его создал | `None` |
| `created_date() -> Optional[str]` | `crDate`, как его записал реестр | `None` |
| `updated_by() -> Optional[str]` | `upID` — кто изменял последним | `None`, когда объект ни разу не менялся или когда вы не владеете им как спонсор |
| `updated_date() -> Optional[str]` | `upDate` | `None`, когда ни разу не менялся |
| `transfer_date() -> Optional[str]` | `trDate` — когда объект последний раз сменил владельца | `None`, когда не менял ни разу |
| `auth_info() -> Optional[str]` | Секрет трансфера `<authInfo><pw>` | `None`, когда реестр его не отдал |
| `statuses() -> List[str]` | Значения статусов: `["ok"]`, `["clientHold", "pendingTransfer"]` … | `[]` |

`object_name()` берётся из самого блока объекта, поэтому в `contact:info` он даёт идентификатор
контакта, а не личное имя регистранта. Через него же читается идентификатор, который реестр выдал
контакту, созданному через `create_auto()`: этот ответ — единственное место, где такой идентификатор
появляется.

`auth_info()` — это секрет, который позволяет **любому** регистратору забрать у вас домен. Никогда
не пишите его в журнал, никогда не кладите в обращение в поддержку и меняйте его после того, как
передали клиенту.

`updated_by()` стоит сверять со своими записями: изменение, которого вы не делали, пришло со стороны
реестра или от действия поддержки, а не из вашей системы.

## Домен

| Аксессор | Возвращает | Когда в ответе ничего нет |
|---|---|---|
| `expiry_date() -> Optional[str]` | `exDate`, ровно как его записал реестр | `None` |
| `registrant() -> Optional[str]` | Идентификатор контакта-регистранта | `None` |
| `contacts() -> Dict[str, List[str]]` | Контакты по ролям: `{"admin": ["c-1"], "tech": ["c-1", "c-2"]}`. Регистрант **не** включён | `{}` |
| `contacts_for(role: str) -> List[str]` | Идентификаторы в одной роли, сопоставление без учёта регистра | `[]`, когда эту роль никто не занимает — законный ответ |
| `admin_contacts() -> List[str]` | Административные контакты | `[]` |
| `tech_contacts() -> List[str]` | Технические контакты | `[]` |
| `billing_contacts() -> List[str]` | Биллинговые контакты | `[]` |
| `all_contacts() -> List[str]` | Каждый идентификатор, привязанный в любом качестве, включая регистранта, без повторов | `[]` |
| `nameservers() -> List[str]` | Имена серверов имён, в нижнем регистре, какой бы моделью EPP реестр их ни выразил | `[]` |
| `nameserver_addresses() -> Dict[str, List[Dict[str, str]]]` | Встроенные glue-адреса по имени сервера имён: `{"ns1.example.com.ua": [{"ip": "192.0.2.1", "version": "v4"}]}` | `{}` |
| `subordinate_hosts() -> List[str]` | Объекты хостов, живущие **под** этим доменом, в нижнем регистре | `[]` |
| `rgp_status() -> List[str]` | Значения статуса RGP, например `["redemptionPeriod"]` (RFC 3915) | `[]` |
| `license() -> Optional[str]` | Номер товарного знака или лицензии из собственного расширения реестра | `None` |
| `prices() -> Dict[str, Dict[str, str]]` | Подсказки о цене продления и восстановления из `domain:info`, по операциям: `{"renewal": {"value": "…", "currency": "UAH"}}` | `{}` |
| `price_channel() -> Optional[str]` | Непрозрачный идентификатор, называющий строку опубликованного каталога цен реестра, из которой взяты эти цены | `None` |
| `registrar_of_record() -> Optional[str]` | Идентификатор, который WHOIS и RDAP реестра публикуют как регистратора | `None` |
| `transfer() -> Optional[Dict[str, str]]` | Трансфер целиком — см. ниже | `None`, когда в ответе нет `trnData` |
| `transfer_status() -> Optional[str]` | Только статус: `"pending"`, `"serverApproved"`, `"clientRejected"` … | `None` |
| `ds_records() -> List[Dict[str, object]]` | DS-записи DNSSEC: `[{"keyTag": …, "alg": …, "digestType": …, "digest": "…"}]` (RFC 5910) | `[]` |
| `key_records() -> List[Dict[str, object]]` | Ключи DNSSEC: `[{"flags": …, "protocol": …, "alg": …, "pubKey": "…"}]` | `[]` |
| `is_signed() -> bool` | Есть ли в ответе вообще какие-либо данные DNSSEC | `False` |

```python
info = client.domain.info("example.com.ua")

info.nameservers()              # ["ns1.example.com.ua", "ns2.example.com.ua"]
info.tech_contacts()            # ["acme-ns1"]
info.subordinate_hosts()        # ["ns1.example.com.ua"]
```

`nameservers()` покрывает обе модели EPP — и ссылку на объект хоста, и имя, встроенное вместе со
своим glue, — потому что клиент, читающий только одну из них, получит пустой список от реестра,
использующего другую, и заключит, что делегирования у домена нет вовсе. `nameserver_addresses()`
возвращает glue только там, где реестр его встроил; пустой результат **не** означает, что домен не
делегирован, — он означает, что адреса вы получаете через `host.info()` по каждому имени.

`subordinate_hosts()` — это то, что нужно проверить перед удалением: реестр отказывается удалять
домен, пока под ним живут объекты хостов.

`transfer()` отвечает, кто запросил, когда, кто должен действовать и до какого срока:

```python
t = client.domain.transfer("query", "example.com.ua")
t.transfer()
# {'status': 'pending', 'requested_by': 'ACME', 'requested_at': '2026-08-14T10:00:00Z',
#  'acting_client': 'EXAMPLE', 'act_by': '2026-08-19T10:00:00Z', 'expiry_date': '2028-04-01T09:15:00Z'}
```

Один только `transfer_status()` говорит, что трансфер в ожидании, но не говорит, чей и сколько у вас
времени, — а `act_by` это срок, после которого реестр решает за вас.

`registrar_of_record()` — это не `sponsor()`. `sponsor()` называет учётную запись, которой
принадлежит объект, — вашу, внутри вашей же реселлерской иерархии; `registrar_of_record()` называет
сторону, которую публикует реестр, а для реселлера это кто-то другой.

## Хост

| Аксессор | Возвращает | Когда в ответе ничего нет |
|---|---|---|
| `host_addresses() -> List[Dict[str, str]]` | glue-адреса самого этого объекта хоста: `[{"ip": "192.0.2.1", "version": "v4"}, …]` | `[]` |

glue есть только у хоста внутри той зоны, которую он обслуживает. Для внешнего сервера имён реестр
не возвращает ничего, и это норма, а не пропущенный ответ. Адреса относятся к самому объекту хоста,
поэтому glue домена по каждому серверу имён остаётся в `nameserver_addresses()`, где видно, какой
адрес какому имени принадлежит.

## Контакт

| Аксессор | Возвращает | Когда в ответе ничего нет |
|---|---|---|
| `email() -> Optional[str]` | Адрес электронной почты | `None` |
| `voice() -> Optional[str]` | Номер телефона в форме EPP `+CC.NNNN` | `None` |
| `fax() -> Optional[str]` | Номер факса, в той же форме | `None` |
| `postal_info() -> Dict[str, Dict[str, object]]` | Адреса по формам: `"int"` (ASCII) и `"loc"` (местное письмо). В каждой — `name`, `org`, `street` (список), `city`, `sp`, `pc`, `cc` | `{}` |
| `disclose() -> Optional[Dict[str, object]]` | `{"flag": True, "elements": ["email", "voice"]}` (RFC 5733) | `None`, когда контакт не выражает предпочтения и действует только политика реестра |

Контакт может нести одну почтовую форму или обе. Читайте `"int"`, когда нужно то, что безопасно
напечатать где угодно; читайте `"loc"`, чтобы получить адрес так, как его написал сам регистрант.

В `disclose()` `flag` со значением `True` означает, что перечисленные элементы **можно**
публиковать, а `False` — что их следует скрыть; ко всему неперечисленному применяется обратное.
Список без флага бессмыслен, поэтому никогда не читайте одно без другого. Почтовые `name`, `org` и
`addr` появляются по каждой форме — как `name:int` или `addr:loc`.

## Check и деньги

| Аксессор | Возвращает | Когда в ответе ничего нет |
|---|---|---|
| `availability() -> Dict[str, bool]` | Вся карта `*:check`: имя или идентификатор → доступность | `{}` |
| `is_available(name: str) -> Optional[bool]` | Доступность одного имени, сопоставление без учёта регистра | **`None`** — ответ ничего о нём не сказал, а это не «занято» |
| `unavailable_reason(name: str) -> Optional[str]` | Почему имя недоступно: `"In use"`, `"Reserved"` | `None`, когда оно доступно или когда реестр не назвал причины |
| `fees() -> Dict[str, object]` | Таблица цен RFC 8748 — см. ниже | `{}` |
| `fee_for(name: str, operation: str, years: int = 1) -> Optional[str]` | Одна названная цена, точной десятичной строкой | `None`, когда в ответе такой цены не было |
| `fee_class(name: Optional[str] = None) -> Optional[str]` | Тарифный класс реестра: `"premium"`, `"standard"` | `None`, когда ответ его не объявил |
| `is_premium(name: Optional[str] = None) -> bool` | Тарифицируется ли имя вне стандартного прайс-листа | `False` |
| `charged_fee() -> Optional[Dict[str, str]]` | Сколько изменяющая операция списала на самом деле: `{"currency": "UAH", "fee": "100.00"}` | `None` |
| `fee_amount() -> Optional[str]` | Только сумма из `charged_fee()` | `None` |
| `fee_currency() -> Optional[str]` | Только валюта из `charged_fee()` | `None` |
| `balance() -> Optional[Dict[str, str]]` | `{"creditLimit": …, "balance": …, "availableCredit": …}` | `None`, когда это не ответ на запрос баланса |
| `credit_limit() -> Optional[str]` | Кредит, предоставленный сверх нулевого баланса | `None` |
| `current_balance() -> Optional[str]` | Средства на счёте прямо сейчас | `None` |
| `available_credit() -> Optional[str]` | То, что вы действительно можете потратить, — баланс плюс остаток кредита | `None` |

`fees()` устроен по именам, плюс ключ `_currency` с валютой этих цен:

```python
r = client.domain.check(["example.com.ua"], fee={"create": [1, 2, 5]}, currency="UAH")
r.fees()
# {'_currency': 'UAH',
#  'example.com.ua': {
#      'avail': True,
#      'reason': None,
#      'class': 'premium',                       # присутствует, только если реестр его объявил
#      'commands': {'create': {'years': 1, 'fee': '100.00'}},
#      'periods': [{'op': 'create', 'years': 1, 'fee': '100.00'},
#                  {'op': 'create', 'years': 2, 'fee': '195.00'},
#                  {'op': 'create', 'years': 5, 'fee': '480.00'}]}}

r.fee_for("example.com.ua", "create", 5)      # '480.00'
```

Запрос одной операции на несколько периодов приносит по одной цене на период. `commands` сохраняет
первую из них, поэтому вызывающий, читающий `commands["create"]`, всё равно получает ответ; в
`periods` лежат все, а `fee_for()` — способ выбрать нужную. `transfer` и `restore` читайте на одном
годе: это одногодичные операции, о скольких бы годах вы ни спрашивали. Суммы здесь иллюстративные, а
не тариф реестра.

`avail` со значением `False` у записи приходит вместе с `reason`: зона не обслуживается или валюта,
о которой вы спросили, — не та, в которой реестр назначает цены; пересчитанной догадки не будет
никогда.

`is_premium()`, вернувший `False`, не обещает стандартной цены: он означает лишь, что ответ не
объявил особого класса. Тарифицируйте по `fees()`, а саму операцию ограничивайте соглашением о цене,
чтобы имя с другой ценой было отклонено кодом 2004, а не выставило вам разницу в счёт. См.
[Баланс](balance.md).

## Poll

| Аксессор | Возвращает | Когда в ответе ничего нет |
|---|---|---|
| `message_id() -> Optional[str]` | Идентификатор сообщения в очереди, который передаётся в `poll.ack()` | `None` — в этом ответе уведомления нет |
| `message_count() -> int` | Сколько сообщений остаётся в очереди | `0` |
| `queue_message() -> Optional[str]` | **Текст уведомления**, из `<msgQ><msg>` | `None` |
| `queue_message_lang() -> Optional[str]` | Язык уведомления: `uk`, `ru`, `en` | `None` |
| `queue_date() -> Optional[str]` | Когда уведомление было поставлено в очередь | `None` |
| `pending_action_data() -> Optional[Dict[str, object]]` | Итог операции, которую реестр обработал офлайн | `None`, когда уведомление его не несёт |

**Уведомление — это `queue_message()`, а не `message()`.** `message()` возвращает заголовок
результата команды — «Command completed successfully; ack to dequeue», — одинаковый в каждом ответе
на poll. Прочитав уведомление через `message()`, вы получите эту постоянную строку, настоящее
содержимое будет отброшено, а следующее за этим подтверждение уничтожит его в реестре навсегда.

`pending_action_data()` — это то, как отчитывается отложенная команда. Вы отправляете `create`,
получаете 1001 с svTRID, а ответ приходит позже в очередь:

```python
notice = client.poll.request()
pan = notice.pending_action_data()
# {'object': 'example.com.ua', 'success': True,
#  'clTRID': 'PYTHON-SDK-20260814101500-4821-0007',
#  'svTRID': 'SRV-19700101103512-24191-00007',
#  'date': '2026-08-14T10:20:00Z'}
```

| Ключ | Почему он важен |
|---|---|
| `success` | **Единственное, что говорит, сработало ли.** Окружающий 1301 означает «вот сообщение», а не «ваша операция удалась» |
| `svTRID` / `clTRID` | Идентификаторы транзакции **исходной** команды. Сопоставьте svTRID с тем, который вам выдали вместе с 1001, чтобы понять, какой именно отложенной операции это ответ: poll — это очередь, и не обязательно самая свежая |
| `date` | Когда действие завершилось, а не когда вы опросили очередь |
| `object` | Доменное имя или идентификатор контакта, которого оно касалось |

О самой очереди и о порядке действий, который не даёт потерять уведомление, см. [Poll](poll.md).

## Безопасность сессии и приветствие

| Аксессор | Возвращает | Когда в ответе ничего нет |
|---|---|---|
| `security_events() -> List[Dict[str, str]]` | Предупреждения RFC 8807 об **этой сессии** — у каждого есть `text` и те из `type`, `name`, `level`, `exDate`, `value`, `duration`, `lang`, которые несёт событие | `[]` на здоровой сессии |
| `service_obj_uris() -> List[str]` | Приветствие: объектные сервисы, которые объявляет сервер | `[]` |
| `service_ext_uris() -> List[str]` | Приветствие: сервисы расширений, которые объявляет сервер | `[]` |

```python
greeting = client.connect()
if Namespaces.FEE in greeting.service_ext_uris():
    ...                                  # эта точка подключения называет цены
```

Пустой `security_events()` — это чистая сессия, поэтому любую запись считайте поводом действовать.
Сервер возвращает их только клиенту, который принял участие в расширении, — см.
[Сессия → Безопасность входа](session.md#безопасность-входа-rfc-8807).

## Диагностика при отказе

| Аксессор | Возвращает | Когда в ответе ничего нет |
|---|---|---|
| `ext_values() -> List[Dict[str, object]]` | Каждый `<extValue>`, разобранный на части: `element`, `namespace`, `text`, `values`, `xml`, `reason`, `lang` | `[]` |
| `error_reasons() -> List[str]` | Только тексты `<extValue><reason>` | `[]` |

`error_reasons()` даёт формулировку; `ext_values()` даёт **предмет**, а в команде с пятью именами это
как раз то, что нужно: «EPP 2302: Object exists» оставляет вас гадать, какое из пяти, а ответ лежит в
`<extValue>`.

```python
for ext in response.ext_values():
    print(ext["element"], ext["text"], "—", ext["reason"])
# name bad..name — Invalid label
```

Ошибочный элемент обычно листовой, и тогда ответ — это `text`. Там, где это контейнер, `text` пуст,
потому что у контейнера нет собственных символьных данных: `values` несёт дочерние элементы по
именам, а `xml` — элемент в том виде, в каком он пришёл, если вы предпочтёте разобрать его сами.

Та же информация доходит до вас через исключение: `CommandException.subject()` и `.reasons()`. См.
[Ошибки](errors.md).

## Сырой доступ

| Аксессор | Возвращает | Когда в ответе ничего нет |
|---|---|---|
| `value(local_name: str) -> Optional[str]` | Первый элемент с таким локальным именем где угодно в кадре, с обрезанными пробелами | `None` |
| `values(local_name: str) -> List[str]` | Каждый элемент с таким локальным именем, с обрезанными пробелами | `[]` |
| `res_data() -> Optional[ET.Element]` | Элемент `<resData>`, для собственного разбора | `None` |
| `raw -> str` | Свойство: XML ответа ровно в том виде, в каком он пришёл | кадр есть всегда |
| `root -> ET.Element` | Свойство: разобранный корень `ElementTree` | есть всегда |
| `Response.from_xml(xml: str) -> Response` | Метод класса: разобрать кадр, полученный вами самостоятельно | бросает `ConnectionException` на некорректном XML |

`value()` и `values()` — это общая форма, на которой построены именованные аксессоры; берите их,
когда расширение реестра несёт то, чего это руководство не называет:

```python
response.value("exDate")        # то же, что expiry_date()
response.values("hostObj")      # каждый <domain:hostObj> в ответе
```

`Response.from_xml()` отказывает кадру с DOCTYPE сразу, через `ConnectionException`. У ответа EPP его
не бывает, а парсер, разворачивающий внутренние сущности, — это то, как враждебная точка подключения
превращает кадр, укладывающийся в бюджет 1 МиБ, в клиента, у которого кончилась память.
