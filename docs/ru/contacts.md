# Контакты

Всё, что находится под `client.contact`. Объекты контактов следуют **RFC 5733**, и каждый метод здесь
соответствует одной команде EPP на проводе.

Контакты идут первыми в любом порядке подготовки: домен ссылается на идентификаторы, которые уже
должны существовать, поэтому обычная последовательность такова — создать регистранта и ролевые
контакты, а затем [создать домен](domains.md#create), который на них указывает.

Каждый метод возвращает [`Response`](responses.md), а код ответа 2000 и выше поднимается как
исключение — см. [Ошибки](errors.md).

## Методы

| Метод | Команда EPP |
|---|---|
| `check` | `<check><contact:check>` |
| `info` | `<info><contact:info>` |
| `create` | `<create><contact:create>` |
| `create_auto` | то же самое, но с зарезервированным идентификатором, по которому реестр генерирует его сам |
| `update` | `<update><contact:update>` |
| `delete` | `<delete><contact:delete>` |
| `transfer` | `<transfer op="…"><contact:transfer>` |

`create_builder(id, email)` и `update_builder(id)` собирают те же команды шаг за шагом; см.
[Билдеры](builders.md).

## check

```python
client.contact.check(ids: List[str]) -> Response
```

Спрашивает, свободны ли идентификаторы контактов. По одному `<contact:id>` на идентификатор, **не
более 10 в одной команде** — одиннадцатый отклоняется с кодом 2001.

```python
r = client.contact.check(["C1", "EXAMPLE-C2"])

r.availability()                    # {'C1': False, 'EXAMPLE-C2': True}
r.is_available("EXAMPLE-C2")       # True
r.unavailable_reason("C1") # 'in use' либо None
```

`is_available()` возвращает `None`, когда ответ ничего не сказал об этом идентификаторе, — это не то
же самое, что «занят», и различать их стоит до того, как вы построите вокруг ответа схему
идентификаторов.

Проверка оправдывает обмен с сервером, только если вы придумываете идентификаторы сами. Если нет,
[`create_auto()`](#create_auto) снимает вопрос целиком.

| Код | Значение |
|---|---|
| 1000 | ответ получен; читайте `availability()` |
| 2001 | больше 10 идентификаторов в одной команде |

## info

```python
client.contact.info(contact_id: str, auth_info: Optional[str] = None) -> Response
```

Читает контакт. Как владелец вы видите полную запись; как не-владелец — публичное подмножество, либо
полную запись, если передадите `auth_info` контакта. *Неверный* код это 2202; отсутствие кода
ошибкой не является.

```python
c = client.contact.info("C1")

c.object_name()     # 'C1' — ИДЕНТИФИКАТОР, а не имя человека
c.roid()            # собственный идентификатор объекта в реестре
c.email()           # 'contact@example.com'
c.voice()           # '+380.441234567'
c.fax()             # либо None
c.statuses()        # ['linked'], как только на контакт сошлётся домен
c.sponsor()         # clID
c.created_by()      # crID          c.created_date()   # crDate
c.updated_by()      # upID или None c.updated_date()   # upDate или None
c.auth_info()       # код авторизации трансфера — никогда не пишите его в журнал
c.disclose()        # {'flag': False, 'elements': ['email', 'voice']} либо None

postal = c.postal_info()
postal["int"]["name"]     # 'Ivan Petrenko'          — ASCII-форма
postal["int"]["street"]   # ['vul. Khreshchatyk 1']  — список, до 3 строк
postal["loc"]["city"]     # 'Київ'                   — форма в локальном письме, если она есть
```

`object_name()` — это идентификатор контакта. Различие существенно: поиск элемента `<name>` по всему
ответу контакта первым найдёт имя *человека*, и подстановка его обратно как идентификатора даёт 2303
со сбивающим с толку сообщением.

| Код | Значение |
|---|---|
| 1000 | ответ получен |
| 2202 | вы не владелец, а переданный `auth_info` неверен |
| 2303 | такого контакта нет |

## create

```python
client.contact.create(contact_id: str, *,
                      name: Optional[str] = None,
                      org: Optional[str] = None,
                      street: Optional[List[str]] = None,
                      city: Optional[str] = None,
                      sp: Optional[str] = None,
                      pc: Optional[str] = None,
                      cc: Optional[str] = None,
                      type: str = "int",
                      postal_infos: Optional[List[Dict[str, Any]]] = None,
                      voice: Optional[str] = None,
                      fax: Optional[str] = None,
                      email: Optional[str] = None,
                      auth_info: Optional[str] = None,
                      disclose: Optional[Dict[str, Any]] = None) -> Response
```

Создаёт контакт. Не тарифицируется.

Форма с одним адресом принимает поля адреса напрямую — это короткий способ записать обычный случай:

```python
r = client.contact.create(
    "C1",
    name="Ivan Petrenko",
    org="Pryklad LLC",
    street=["vul. Khreshchatyk 1"],
    city="Kyiv",
    pc="01001",
    cc="UA",
    voice="+380.441234567",
    email="contact@example.com",
    auth_info="C0ntact-Pw!",
)

r.object_name()    # 'C1'
r.created_date()   # crDate
```

| Параметр | Уходит на провод как |
|---|---|
| `name`, `org`, `street`, `city`, `sp`, `pc`, `cc`, `type` | один блок `<contact:postalInfo type="…">` |
| `postal_infos` | несколько таких блоков — см. ниже |
| `voice`, `fax` | `<contact:voice>` / `<contact:fax>`, в форме EPP `+CC.NNNNNNNNN` |
| `email` | `<contact:email>` — **обязателен** |
| `auth_info` | `<contact:authInfo><contact:pw>` |
| `disclose` | `<contact:disclose flag="0\|1">` (приватность по RFC 5733) |

`email` проверяется до отправки чего-либо: пустой или отсутствующий поднимает `ValidationException`,
потому что RFC 5733 требует его, а реестр всё равно отверг бы кадр — сообщением, которое читается
дольше, чем это.

`<contact:authInfo>` уходит всегда. Передайте код — и он станет кодом авторизации трансфера
контакта; опустите — и уйдёт пустой `<contact:pw/>`.

Реестр требует, чтобы идентификатор состоял из 3–16 символов: латинских букв, цифр и `-`; всё прочее
это 2005.

### Обе почтовые формы

Контакт несёт один или два блока `<contact:postalInfo>`, и то, какие вы отправляете, — настоящее
решение, а не формальность:

| `type` | Содержимое | Примечания |
|---|---|---|
| `"int"` | **только ASCII / латиница** | кириллица здесь отклоняется с кодом 2005. Именно эту форму реестр может предъявить любой стороне, поэтому нужна хотя бы одна ASCII-форма |
| `"loc"` | локальное письмо — кириллица для украинского регистранта | необязательна и дополнительна |

Присылайте обе, если у вас есть обе. Ничего не отбрасывается, и `contact.info()` возвращает всё, что
вы прислали. Для этого используйте `postal_infos`:

```python
client.contact.create(
    "C1",
    postal_infos=[
        {"type": "int", "name": "Ivan Petrenko", "org": "Pryklad LLC",
         "street": ["vul. Khreshchatyk 1"], "city": "Kyiv", "pc": "01001", "cc": "UA"},
        {"type": "loc", "name": "Іван Петренко", "org": "ТОВ «Приклад»",
         "street": ["вул. Хрещатик 1"], "city": "Київ", "pc": "01001", "cc": "UA"},
    ],
    voice="+380.441234567",
    email="contact@example.com",
)
```

**`postal_infos` заменяет собой аргументы с одним адресом.** Когда вы передаёте его, `name`, `city`,
`cc` и остальные не читаются вообще — смешение двух форм в одном вызове отправит только те блоки,
что лежат в списке.

Каждый блок принимает до 3 строк `street`, а `city` и `cc` требует сама схема.

### Блок disclose

RFC 5733 позволяет контакту указать, какие из его элементов можно публиковать. Блок — это флаг плюс
список элементов, к которым флаг применяется; всё не перечисленное получает противоположное
обращение, поэтому без флага список ничего не значит.

```python
# Скрыть e-mail и телефон; всё остальное — по политике реестра.
disclose={"flag": False, "email": True, "voice": True}

# Скрыть адрес и организацию в ОБЕИХ почтовых формах.
disclose={"flag": False, "addr": ["int", "loc"], "org": ["int", "loc"]}

# Согласиться на публикацию имени в обеих формах.
disclose={"flag": True, "name": ["int", "loc"]}
```

| Ключ | Значение | Провод |
|---|---|---|
| `flag` | истинностное значение | `flag="1"` (публиковать) или `flag="0"` (скрыть) |
| `name`, `org`, `addr` | список почтовых форм: `["int"]`, `["loc"]` или обе | по одному элементу на форму |
| `voice`, `fax`, `email` | истинностное значение | голый элемент, когда истина |

`name`, `org` и `addr` существуют по одному разу на каждую почтовую форму, поэтому выбор делается
**для каждой формы отдельно**. Указав только `["int"]`, вы скрываете ASCII-адрес, а адрес в локальном
письме остаётся публичным — настройка приватности, которая выглядит применённой и таковой не
является.

Каждый флаг разбирается как *значение*, а не по истинности в Python: строки `"0"`, `"false"` и `""`
здесь означают ложь. Они попадают к интегратору из HTML-форм и сохранённого JSON, и в Python все три
истинны как строки, поэтому `disclose={"flag": "0"}` означает СКРЫТЬ — ровно так, как и было
написано.

Читайте настройку обратно через `disclose()`, где почтовые элементы уточнены формой:

```python
client.contact.info("C1").disclose()
# {'flag': False, 'elements': ['addr:int', 'addr:loc', 'email']}
```

| Код | Значение |
|---|---|
| 1000 | создан |
| 2003 | нет почтового блока либо нет e-mail |
| 2005 | значение сформировано неверно: кириллица в блоке `int`, плохой e-mail, идентификатор вне 3–16 символов |
| 2302 | такой идентификатор уже существует |
| 2306 | правило реестра отклоняет значение (слабый `auth_info`) |

## create_auto

```python
client.contact.create_auto(**options: Any) -> Response
Contact.AUTO_ID = "autonic"
```

Создаёт контакт и позволяет **реестру выбрать идентификатор**. Метод принимает те же именованные
параметры, что и `create()`; разница только в том, что вместо вашего идентификатора он отправляет
зарезервированное значение `autonic`.

```python
handle = client.contact.create_auto(
    name="Ivan Petrenko", city="Kyiv", cc="UA", email="contact@example.com",
).object_name()          # 'c-9f4b2ad10e'

# Используйте его везде, где нужен идентификатор контакта.
client.domain.create("example.com.ua", years=1, registrant=handle)
```

Сгенерированный идентификатор появляется **в этом ответе и больше нигде**. Сохраняйте его сразу, как
прочитали: команды «как ты назвал контакт, который я создал минуту назад» не существует.

Это ответ сразу на две задачи. Если схемы именования у вас нет, её не придётся придумывать. А если
есть, вам больше не нужно ходить по кругу вокруг 2302, когда идентификатор занял кто-то другой:
`autonic` — это запрос, а не имя, он никогда не сохраняется как идентификатор, и **каждый вызов даёт
новое значение**, поэтому повторение того же запроса создаёт второй контакт, а не столкновение.
Сгенерированные идентификаторы состоят из строчных латинских букв, цифр и `-`, в пределах 3–16
символов, которые допускает протокол.

Зарезервированное значение доступно как `Contact.AUTO_ID`, если вы предпочитаете передать его в
`create()` самостоятельно или в [билдер создания контакта](builders.md), который принимает
идентификатор аргументом:

```python
from epptools import Contact

client.contact.create(Contact.AUTO_ID, name="Ivan Petrenko", city="Kyiv",
                      cc="UA", email="contact@example.com")
```

Коды ответа те же, что у `create`, минус 2302 — в чём и смысл.

## update

```python
client.contact.update(contact_id: str, *,
                      add_statuses: Optional[List[str]] = None,
                      rem_statuses: Optional[List[str]] = None,
                      chg: Optional[Dict[str, Any]] = None) -> Response
```

Изменяет контакт. Статусы идут в собственных аргументах; любое изменение полей идёт в `chg`.

```python
client.contact.update(
    "C1",
    chg={"email": "new-contact@example.com",
         "postal_info": {"name": "Ivan Petrenko", "city": "Lviv", "cc": "UA", "org": ""}},
    add_statuses=["clientUpdateProhibited"],
)
```

`chg` принимает ровно эти ключи, причём и в написании snake_case, и в camelCase из RFC:

| Ключ | Действие |
|---|---|
| `postal_info` / `postalInfo` | один почтовый блок |
| `postal_infos` / `postalInfos` | несколько почтовых блоков |
| `voice` | заменить номер телефона; `""` очищает его |
| `fax` | заменить номер факса; `""` очищает его |
| `email` | заменить e-mail; он обязателен, поэтому очистить его нельзя |
| `auth_info` / `authInfo` | заменить код авторизации трансфера |
| `disclose` | заменить предпочтения раскрытия — форма та же, что при создании |

Любой другой ключ поднимает `ValidationException`, с подсказкой, когда он похож на опечатку. Ключ,
который никто не читает, — это изменение, которого не произошло, спрятанное за кодом 1000, и в ответе
об этом ничего не будет сказано.

Убрать у контакта код авторизации трансфера нельзя никак. RFC 5731 даёт домену форму с обнулением, а
RFC 5733 ничего равнозначного для контакта не определяет, поэтому код контакта можно заменить, но не
очистить. Пустой пароль заменой не является: пустое значение — это по-прежнему значение, которое
держатель может предъявить.

### Правило изменения: почтовый блок ЗАМЕЩАЕТСЯ, а не сливается

Отправьте почтовый блок в `chg` — и реестр **заместит** им тот, что хранит. Их не сливают поле за
полем, поэтому всё, чего вы не передали, исчезает.

RFC 5733 можно прочитать и иначе: в `chgPostalInfoType` каждая из составляющих — name, org, addr —
необязательна, и это выглядит как «не передавайте её, и реестр сохранит то, что хранит». Это чтение
небезопасно: против реестра, который замещает блок, **каждая из этих команд отвечает 1000**:

| Что нёс `chg` | Что осталось у контакта |
|---|---|
| полный блок с `"org": ""` | организация убрана, адрес нетронут |
| полный блок без ключа `org` | организация **тоже убрана** |
| один лишь `{"org": ""}` | **почтового блока нет вообще** — ни имени, ни улицы, города, индекса и страны |

То есть изменить одно поле адреса невозможно, и сбой молчаливый: команда успешна, а данных нет.
`name`, `city` и `cc` обязательны в любом почтовом изменении, и этот SDK без них отказывает, — но
эта проверка лишь удерживает кадр валидным и вернуть `org`, `sp` или `pc`, которого вы не передали,
не может.

**Прочитайте блок, примените своё изменение и отправьте его целиком:**

```python
current = client.contact.info("C1").postal_info()["int"]
client.contact.update("C1", chg={"postal_info": {**current, "type": "int", "org": ""}})
```

Чего замещение не достаёт — так это второй почтовой формы: `int` и `loc` адресуются раздельно,
поэтому замена одной оставляет другую ровно такой, какой она была.

Внутри блока, который вы отправляете, пустая строка по-прежнему очищает необязательное поле:

| Что вы пишете | Что происходит |
|---|---|
| ключ несёт значение | поле принимает это значение |
| ключ несёт `""` | поле отправляется пустым, что его **очищает** |
| ключа нет | поле не отправляется — и реестр удаляет то, что хранил |

Со строками улицы всё иначе, и в вашу пользу: блок адреса, отправленный без `street`, оставляет
существующие строки нетронутыми.

Если вы меняете только имя, организацию или телефон, не упоминайте `street`, `city`, `sp`, `pc` и
`cc` вовсе — тогда блок адреса не отправляется и ничто внутри него не может пострадать:

```python
# Адрес не затронут, потому что к нему никто не обращался.
client.contact.update("C1", chg={"postal_info": {"name": "Ivan Petrenko"}})
```

### Статусы

`add_statuses` и `rem_statuses` строят по одному блоку, в котором лежат все названные вами статусы.
Клиент может устанавливать `clientDeleteProhibited`, `clientUpdateProhibited` и
`clientTransferProhibited`; парные `server*` принадлежат реестру, и команда, пытающаяся установить
такой статус, отклоняется с кодом 2306.

`clientUpdateProhibited` закрывает контакт от дальнейших изменений — включая то, которое сняло бы сам
статус, с одним намеренным исключением: команда, *единственным* содержимым которой является снятие
`clientUpdateProhibited`, принимается. Значит, выход — отдельная команда:

```python
client.contact.update("C1", rem_statuses=["clientUpdateProhibited"])
# ...и только затем правка
client.contact.update("C1", chg={"email": "new-contact@example.com"})
```

Совмещение разблокировки с правкой в одной команде это 2304.

| Код | Значение |
|---|---|
| 1000 | применено |
| 2303 | такого контакта нет |
| 2304 | статус запрещает — см. правило разблокировки выше |
| 2305 | связь объекта запрещает |
| 2306 | правило реестра отклоняет значение либо статус, который клиент устанавливать не может |

## delete

```python
client.contact.delete(contact_id: str) -> Response
```

```python
client.contact.delete("C1")
```

**Контакт, на который всё ещё ссылается домен, удалить нельзя** — реестр отвечает 2305, и контакт
несёт статус `linked`. Сначала отвяжите его: переведите домены на другой идентификатор через
[`domain.update`](domains.md#update), а затем удаляйте.

`all_contacts()` в ответе домена — быстрый способ узнать, какие из ваших контактов ещё используются,
поскольку метод перечисляет все идентификаторы, включая регистранта:

```python
in_use = set(client.domain.info("example.com.ua").all_contacts())
if "C1" not in in_use:
    client.contact.delete("C1")
```

| Код | Значение |
|---|---|
| 1000 | удалён |
| 2303 | такого контакта нет |
| 2304 | статус запрещает (`clientDeleteProhibited`) |
| 2305 | всё ещё связан с доменом |

## transfer

```python
client.contact.transfer(op: str,
                        contact_id: str,
                        auth_info: Optional[str] = None) -> Response
```

`op` — одно из `request`, `approve`, `reject`, `cancel`, `query`; уходит атрибутом `op` элемента
`<transfer>`. Ни периода, ни платы здесь нет: трансфер контакта переносит владение и ничего больше.

```python
# Принимающая сторона, с кодом от текущего владельца.
r = client.contact.transfer("request", "C1", "the-code")
r.code()                    # 1000, либо 1001, когда решение принимается позже
r.transfer_status()         # 'pending'

# Теряющая сторона, после poll-уведомления о том, что кто-то запросил ваш контакт.
client.contact.transfer("approve", "C1")
client.contact.transfer("reject", "C1")

# Принимающая сторона отзывает собственный запрос.
client.contact.transfer("cancel", "C1")

# Любая сторона: на какой стадии запрос?
t = client.contact.transfer("query", "C1").transfer()
t["status"], t["requested_by"], t["acting_client"], t["act_by"]
```

`transfer()` возвращает уведомление целиком — кто запросил, когда, кто обязан ответить и до какого
срока. `act_by` — это крайний срок, после которого реестр решает за вас, поэтому уведомление о
трансфере, пришедшее через [poll](poll.md), — это то, на что отвечают, а не то, что подшивают.

| Код | Значение |
|---|---|
| 1000 / 1001 | принято; 1001 означает, что итог придёт позже через [poll](poll.md) |
| 2201 | вы не та сторона, которой можно отправлять эту операцию |
| 2202 | `auth_info` неверен |
| 2300 | трансфер уже в ожидании (на повторный `request`) |
| 2301 | трансфер не в ожидании (на `approve`/`reject`/`cancel`/`query`) |
| 2303 | такого контакта нет |
| 2304 | статус запрещает |
