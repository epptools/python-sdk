# Домены

Всё, что находится под `client.domain`. Объекты доменов следуют **RFC 5731**, и каждый метод на этой
странице соответствует ровно одной команде EPP на проводе, поэтому собственное руководство реестра и
сам RFC описывают тот же обмен со стороны сервера.

Каждый метод возвращает [`Response`](responses.md). По умолчанию код ответа 2000 и выше поднимается
как исключение ещё до того, как вы увидите ответ, — см. [Ошибки](errors.md) о классификации и о
`throw_on_failure(False)`, если вы предпочитаете читать `code()` сами.

Сначала законченная программа, чтобы фрагментам ниже было на чём держаться:

```python
from epptools import Client, Config
from epptools.exceptions import EppException

client = Client(Config(
    host="epp.registry.example",
    clid="EXAMPLE",
    password="your-secret",
    ca_file="/etc/ssl/registry-ca.pem",
))

try:
    client.connect()
    client.login()

    check = client.domain.check(["example.com.ua"])
    if check.is_available("example.com.ua"):
        created = client.domain.create("example.com.ua", years=1, registrant="C1")
        print("registered until", created.expiry_date())
    else:
        print("taken:", check.unavailable_reason("example.com.ua"))

    client.logout()
except EppException as exc:
    print("EPP error:", exc)
finally:
    client.disconnect()
```

## Методы

| Метод | Команда EPP |
|---|---|
| `check` | `<check><domain:check>` |
| `info` | `<info><domain:info>` |
| `create` | `<create><domain:create>` |
| `update` | `<update><domain:update>` |
| `delete` | `<delete><domain:delete>` |
| `renew` | `<renew><domain:renew>` |
| `transfer` | `<transfer op="…"><domain:transfer>` |
| `restore` | `<update><domain:update>` + `<rgp:restore op="request"/>` |

`create_builder()` и `update_builder()` собирают те же две команды шаг за шагом; они описаны в
разделе [Билдеры](builders.md) и дают точно такой же кадр.

## check

```python
client.domain.check(names: List[str],
                    fee: Optional[Dict[str, Any]] = None,
                    currency: Optional[str] = None) -> Response
```

Спрашивает, доступны ли имена для регистрации. По одному `<domain:name>` на имя и, при желании,
довесок `<fee:check>` из RFC 8748 в `<extension>`, который заодно спрашивает цену, — денежная
половина полностью разобрана на странице [Баланс и цены](balance.md).

**Не более 10 имён в одной команде.** Одиннадцатое реестр отклоняет с кодом 2001, поэтому разбивайте
на десятки.

```python
r = client.domain.check(["example.com.ua", "taken.com.ua"])

r.availability()          # {'example.com.ua': True, 'taken.com.ua': False}
r.is_available("example.com.ua")        # True
r.unavailable_reason("taken.com.ua")    # 'in use'
```

`is_available()` возвращает `None`, когда ответ вообще ничего не сказал об этом имени. Это не то же
самое, что «занято», и строка, которая регистрирует домен, не должна считать это одним и тем же:

```python
free = r.is_available("example.com.ua")
if free is None:
    raise RuntimeError("the check said nothing about this name — ask again before registering")
if free:
    client.domain.create("example.com.ua", years=1, registrant="C1")
```

| Код | Значение |
|---|---|
| 1000 | ответ получен; читайте `availability()` — недоступное имя это обычный 1000, а не ошибка |
| 2001 | больше 10 имён в одной команде |
| 2004 | довесок с ценой запросил операцию, которую реестр не тарифицирует |
| 2306 | больше 20 ценовых позиций в одной команде |
| 2307 | зона не обслуживается |

## info

```python
client.domain.info(name: str,
                   auth_info: Optional[str] = None,
                   hosts: str = "all") -> Response
```

Читает домен. Как регистратор-владелец вы получаете полную запись. Как не-владелец вы получаете
публичное подмножество (имя, roid, статусы, даты, владельца) — и полную запись, если передадите
`auth_info` домена. *Неверный* код это 2202; отсутствие кода ошибкой не является.

`hosts` задаёт атрибут `hosts` элемента `<domain:name>` и выбирает, какие сведения о серверах имён
вернутся (RFC 5731 §3.1.2):

| Значение | Что возвращается |
|---|---|
| `"all"` | и делегированные серверы имён, и подчинённые хосты (по умолчанию) |
| `"del"` | только серверы имён, которым делегирован этот домен |
| `"sub"` | только хосты, живущие под этим доменом |
| `"none"` | ни те, ни другие |

```python
info = client.domain.info("example.com.ua")

info.object_name()          # 'example.com.ua'
info.roid()                 # собственный идентификатор объекта в реестре
info.expiry_date()          # '2027-04-01T09:15:00.0Z' — собственная строка реестра
info.created_date()         # crDate            info.created_by()   # crID
info.updated_date()         # upDate или None   info.updated_by()   # upID или None
info.transfer_date()        # trDate или None, если домен ни разу не менял владельца
info.sponsor()              # clID — учётная запись, которой он принадлежит
info.registrar_of_record()  # идентификатор, который публикуют WHOIS/RDAP, когда это другая сторона

info.registrant()           # 'C1'
info.contacts()             # {'admin': ['EXAMPLE-C2'], 'tech': ['EXAMPLE-C3']}
info.tech_contacts()        # ['EXAMPLE-C3']  — а также admin_contacts(), billing_contacts()
info.contacts_for("Tech")   # тот же список; роль сопоставляется без учёта регистра
info.all_contacts()         # все идентификаторы, включая регистранта, без повторов

info.statuses()             # ['ok'] либо ['clientHold', 'clientTransferProhibited', ...]
info.nameservers()          # ['ns1.example.com.ua', 'ns2.example.com.ua']
info.nameserver_addresses() # встроенный glue по именам серверов (пусто в модели hostObj)
info.subordinate_hosts()    # хосты, живущие ПОД этим доменом
info.auth_info()            # код авторизации трансфера — никогда не пишите его в журнал
info.license()              # номер товарного знака или лицензии, либо None
info.rgp_status()           # ['redemptionPeriod'], пока домен удалён, но восстановим
info.is_signed()            # True, когда пришли данные DNSSEC
info.ds_records()           # [{'keyTag': 12345, 'alg': 13, 'digestType': 2, 'digest': '…'}]
info.key_records()          # [{'flags': 257, 'protocol': 3, 'alg': 13, 'pubKey': '…'}]
info.prices()               # {'renewal': {'value': '180.00', 'currency': 'UAH'}, …}
info.price_channel()        # непрозрачный идентификатор каталога, к которому относятся эти цены
```

Три вещи, неверное прочтение которых стоит денег или данных:

- **Даты — это собственные строки реестра**, а не `datetime`. Именно реестр решает, на какой
  календарный день приходится продление; пересчёт через локальный часовой пояс — это то, как клиент
  начинает показывать (и продлевать) день, который был вчера.
- **Выкуп живёт в `rgp_status()`**, а не в `statuses()`. Домен, до безвозвратного удаления которого
  остались считанные дни, может показывать в `statuses()` обычный `ok`, и клиент, читающий только
  это, ничего не заметит, пока имя не пропадёт.
- **Пустой `nameserver_addresses()` не означает, что домен не делегирован.** Там лежит только
  встроенный glue. В модели объектов хостов имена приходят сами по себе; берите список из
  `nameservers()`, а адреса — из [`host.info`](hosts.md#info) по каждому имени.

| Код | Значение |
|---|---|
| 1000 | ответ получен |
| 2202 | вы не владелец, а переданный `auth_info` неверен |
| 2303 | такого домена нет |

## create

```python
client.domain.create(name: str, *,
                     years: Optional[int] = None,
                     registrant: Optional[str] = None,
                     contacts: Optional[Dict[str, str]] = None,
                     nameservers: Optional[List[Nameserver]] = None,
                     auth_info: Optional[str] = None,
                     license: Optional[str] = None,
                     sec_dns: Optional[Dict[str, Any]] = None,
                     fee: Optional[FeeAgreement] = None) -> Response
```

Регистрирует домен. **Это платная команда**: при успехе списывается плата за регистрацию.

Все параметры после `name` передаются только по имени, поэтому опечатка станет `TypeError` прямо в
вашем редакторе, а не отсутствующим элементом на проводе.

| Параметр | Тип | Уходит на провод как |
|---|---|---|
| `years` | `int` | `<domain:period unit="y">`; если вы его не передали, элемент не отправляется вовсе, и реестр применяет собственное значение по умолчанию |
| `registrant` | `str` | `<domain:registrant>` |
| `contacts` | `{роль: идентификатор}` или `{роль: [идентификатор, …]}` | по одному `<domain:contact type="роль">` на идентификатор |
| `nameservers` | `[имя, …]` или `[{"name": …, "addresses": [...]}, …]` | `<domain:ns>` с `<domain:hostObj>` или `<domain:hostAttr>` |
| `auth_info` | `str` | `<domain:authInfo><domain:pw>` |
| `license` | `str` | `<extension><registry:create><registry:license>` |
| `sec_dns` | `dict` | `<extension><secDNS:create>` (RFC 5910) |
| `fee` | `str` или `{"amount", "currency"}` | `<extension><fee:create>` (RFC 8748) |

Полная регистрация со всеми параметрами сразу:

```python
created = client.domain.create(
    "example.com.ua",
    years=2,
    registrant="C1",
    contacts={"admin": "EXAMPLE-C2", "tech": ["EXAMPLE-C3", "EXAMPLE-C4"]},
    nameservers=["ns1.example.com.ua", "ns2.example.com.ua"],
    auth_info="D0main-Pw!",
    license="TM-2026-000123",                       # если ваш реестр его требует
    sec_dns={"ds_data": [{"key_tag": 12345, "alg": 13,
                          "digest_type": 2, "digest": "49FD46E6C4B45C55D4AC"}]},
    fee="200.00",                                 # предел, а не цена
)

created.code()          # 1000, либо 1001, когда реестр ставит регистрацию в очередь
created.object_name()   # 'example.com.ua'
created.created_date()  # crDate
created.expiry_date()   # exDate — сохраните: renew() обязан вернуть её обратно
created.fee_amount()    # '200.00' — что было списано на самом деле
```

### years

Целые годы в пределах диапазона зоны (по умолчанию 1–10), и полученная дата истечения срока не может
выйти за горизонт реестра. Период вне диапазона это 2004; период ниже минимума зоны это 2306.

### registrant и contacts

`contacts` принимает **либо один идентификатор на роль, либо несколько**:

```python
contacts={"admin": "EXAMPLE-C2", "tech": ["EXAMPLE-C3", "EXAMPLE-C4"]}
```

Каждый идентификатор становится отдельным элементом `<domain:contact type="tech">` — именно это
разрешает RFC 5731 и именно это реестр разбирает обратно в список по каждой роли. Пустые
идентификаторы и `None` отбрасываются, а не отправляются пустыми элементами. Реестр принимает не
более 8 идентификаторов в одной роли (сверх того 2306) и 16 всего.

Какие роли зона *требует* — правило самой зоны; создание без обязательной роли это 2003.

### Серверы имён, обе модели

RFC 5731 делает `<domain:ns>` выбором между двумя способами назвать сервер имён, и реестр принимает
один из них. Спросите у своего, какой:

```python
# Объекты хостов: имя ссылается на хост, который вы создали заранее (см. hosts.md).
nameservers=["ns1.example.com.ua", "ns2.example.com.ua"]

# Встроенный glue: имя приходит вместе с адресами, без всякого объекта хоста.
nameservers=[
    {"name": "ns1.example.com.ua", "addresses": ["203.0.113.10", "2001:db8::10"]},
    {"name": "ns2.example.com.ua", "addresses": ["203.0.113.11"]},
]
```

IPv4 и IPv6 различаются по самому написанию адреса, поэтому каждый получает правильный атрибут
`ip="v4"` / `ip="v6"` без ваших указаний.

**Смешивать обе модели в одной команде нельзя.** Список, где рядом лежат обычная строка и словарь,
поднимает `ValidationException` ещё до отправки — схема всё равно отвергла бы такой кадр, причём
голым 2001, который не называет ни одного поля, а это заметно хуже для отладки.

Домен, созданный вообще без серверов имён, допустим и получает вычисляемый статус `inactive`. Это не
ошибка: это значит, что домен ещё не делегирован.

### auth_info

`<domain:authInfo>` обязателен в `domain:create`, поэтому элемент уходит всегда. Передайте код — и он
станет кодом авторизации трансфера; опустите — и уйдёт пустой `<domain:pw/>`, что просит реестр
применить политику зоны и сгенерировать код. Прочитать сгенерированный код обратно можно через
`client.domain.info(name).auth_info()`.

Код, который вы задаёте сами, обязан удовлетворять политике стойкости зоны — минимальной длине и
числу классов символов, — иначе создание отклоняется с кодом 2306.

Любой, у кого есть этот код, может увести домен к другому регистратору. Относитесь к нему как к
учётным данным: никогда не пишите его в журнал и задавайте новый после того, как передали его
клиенту.

### Лицензия

Некоторые реестры не регистрируют отдельные имена без номера товарного знака или лицензии — чаще
всего это короткие и дорогие имена непосредственно под доменом верхнего уровня. Он передаётся в
**собственном** расширении реестра, и его пространство имён клиент читает из `<greeting>`, поэтому
реестру, который такого расширения не объявляет, вместо кадра, который тот бы проигнорировал, будет
брошено `ConfigException`. См. [Команды](commands.md#собственные-расширения-вашего-реестра).

Каким именно именам он нужен — это политика реестра, а не протокола, поэтому спрашивайте у своего.
Отсутствие обязательной лицензии обычно это 2003; лицензия, отправленная туда, где её не ждут, —
2306.

### DNSSEC при create

`sec_dns` строит блок `<secDNS:create>` (RFC 5910). Форм записи две, и присутствовать могут обе:

```python
sec_dns={
    "ds_data": [
        {"key_tag": 12345, "alg": 13, "digest_type": 2, "digest": "49FD46E6C4B45C55D4AC"},
        # DS-запись может нести DNSKEY, из которого она вычислена, если реестр это принимает:
        {"key_tag": 54321, "alg": 13, "digest_type": 2, "digest": "A1B2C3D4E5F60718293A",
         "key_data": {"flags": 257, "protocol": 3, "alg": 13, "pub_key": "AwEAAb…"}},
    ],
    "key_data": [{"flags": 257, "protocol": 3, "alg": 13, "pub_key": "AwEAAb…"}],
    "max_sig_life": 1209600,
}
```

Каждый ключ принимается и в camelCase-написании из RFC: `dsData`, `keyData`, `keyTag`, `digestType`,
`pubKey`, `maxSigLife`. **Всё остальное поднимает `ValidationException`** с указанием ближайшего
знакомого ему ключа. Этот отказ и есть смысл проверки: ключ, который никто не читает, молча
отсутствует в кадре, реестр отвечает 1000 на ту команду, которую действительно получил, — и у вас неподписанный
домен, который вся ваша система считает подписанным.

Один только `max_sig_life` не даёт ничего: `<secDNS:create>` требует хотя бы одну DS-запись или
запись ключа, поэтому `sec_dns` без записей просто не попадает в кадр, а не уходит недопустимым
пустым блоком.

Реестр принимает SHA-256 (`digest_type` 2) и SHA-384 (`digest_type` 4), до 6 DS-записей на домен, и
отклоняет дубликаты. Команда DNSSEC в зоне, которая DNSSEC не предлагает, это 2103 или 2306.

### fee

Необязателен и является **пределом, а не ценой**: «я согласен заплатить не больше этого». Без него
реестр спишет свою цену и команда выполнится. С ним более высокая реальная цена отклонит команду с
кодом 2004 и не спишет ничего. См.
[Баланс и цены](balance.md#ограничение-суммы-которую-вы-согласны-платить).

| Код | Значение |
|---|---|
| 1000 | зарегистрирован |
| 1001 | поставлено в очередь; итог придёт как [poll-уведомление](poll.md) |
| 2003 | отсутствует обязательный элемент — роль, которую требует зона, или лицензия, которую она требует |
| 2004 | период вне диапазона либо согласованная сумма не покрывает цену |
| 2005 | значение сформировано неверно (плохая метка, плохой адрес) |
| 2103 | DNSSEC в этой зоне не предлагается |
| 2104 | недостаточно средств — поднимается как `InsufficientFundsError`; остановите пакет |
| 2302 | уже зарегистрирован |
| 2306 | правило реестра отклоняет значение: слабый `auth_info`, слишком много контактов в роли, лицензия там, где её нет |
| 2307 | зона не обслуживается |

## update

```python
client.domain.update(name: str, *,
                     add: Optional[Dict[str, Any]] = None,
                     rem: Optional[Dict[str, Any]] = None,
                     chg: Optional[Dict[str, Any]] = None,
                     restore: bool = False,
                     license: Optional[str] = None,
                     sec_dns: Optional[Dict[str, Any]] = None,
                     fee: Optional[FeeAgreement] = None) -> Response
```

Update в EPP — это **дельта, а не замена**. Всё, что вы не упомянули, остаётся ровно таким, как было,
а то, в какой из трёх блоков попадает изменение, и составляет всю семантику команды.

### add и rem

Оба принимают одни и те же три ключа и оба строят блок, только если вы что-то в него положили:

| Ключ | Тип | Действие |
|---|---|---|
| `ns` | список в любой из моделей серверов имён | делегировать этим серверам имён / прекратить делегирование |
| `contacts` | `{роль: идентификатор}` или `{роль: [идентификатор, …]}` | привязать / отвязать контакты в роли |
| `statuses` | `[str, …]` | установить / снять клиентский статус |

```python
client.domain.update(
    "example.com.ua",
    add={"ns": ["ns3.example.com.ua"],
         "contacts": {"tech": "EXAMPLE-C4"},
         "statuses": ["clientHold"]},
    rem={"ns": ["ns2.example.com.ua"],
         "statuses": ["clientTransferProhibited"]},
)
```

Клиентские статусы, которые вы можете устанавливать: `clientHold`, `clientDeleteProhibited`,
`clientUpdateProhibited`, `clientTransferProhibited` и `clientRenewProhibited`. Парные `server*`
принадлежат реестру, и команда, пытающаяся установить такой статус, отклоняется. `clientHold` убирает
домен из DNS — имя перестаёт разрешаться, — так что это изменение, которое стоит подтвердить, а не
флажок, который стоит переключать.

### chg

`chg` меняет два поля домена, у которых единственное значение:

| Ключ | Действие |
|---|---|
| `registrant` | передать домен другому владельцу |
| `auth_info` (или `authInfo`) | заменить код авторизации трансфера |
| `clear_auth_info` (или `clearAuthInfo`) | убрать код авторизации трансфера полностью |

```python
client.domain.update("example.com.ua",
                     chg={"registrant": "EXAMPLE-C9", "auth_info": "New-Str0ng!"})
```

Любой другой ключ поднимает `ValidationException`, с подсказкой, когда ошибка похожа на опечатку.
Тихо проигнорированный ключ — это изменение, которого не произошло, спрятанное за кодом 1000: по
ответу вы этого никак не определите, ведь с точки зрения реестра вы ни о чём и не просили.

Смену регистранта многие зоны считают сменой владельца со своими правилами, поэтому отказ здесь — это
обычно политика (2306), а не неверно сформированная команда.

### Отзыв утёкшего кода трансфера

Если код авторизации трансфера утёк, установка пустого кода вам не поможет: пустой пароль — это
по-прежнему значение, которое держатель может предъявить, и домен остаётся ровно настолько же
подвижным. В протоколе для удаления есть отдельная форма — `<domain:authInfo><domain:null/>` — и
именно её отправляет `clear_auth_info`:

```python
# Кода больше нет. Никакой код не уведёт этот домен, пока вы не зададите новый.
client.domain.update("example.com.ua", chg={"clear_auth_info": True})

# Позже, когда клиенту снова законно понадобится код:
client.domain.update("example.com.ua", chg={"auth_info": "Fresh-C0de!"})
```

Задать и очистить в одной команде — противоречие, которое схема выразить не может, поэтому передача
и `auth_info`, и `clear_auth_info` поднимает `ValidationException`, а не выбирает молча одно из двух.

Учтите также, что реестр считает возраст кода: он годен для трансфера 30 дней с момента, когда был
**задан**, а не с момента начала трансфера. Код, выданный сегодня и предъявленный через пять недель,
отклоняется с кодом 2202, даже если совпадает, и придётся задать новый.

### DNSSEC при update

Update несёт `<secDNS:update>` — дельту, форма которой отличается от блока create:

```python
# Заменить один ключ другим одной командой, без промежутка, когда домен не подписан.
client.domain.update("example.com.ua", sec_dns={
    "rem": {"ds_data": [{"key_tag": 12345, "alg": 13,
                         "digest_type": 2, "digest": "49FD46E6C4B45C55D4AC"}]},
    "add": {"ds_data": [{"key_tag": 54321, "alg": 13,
                         "digest_type": 2, "digest": "A1B2C3D4E5F60718293A"}]},
})

# Полностью снять подпись.
client.domain.update("example.com.ua", sec_dns={"rem_all": True})

# Заменить весь набор ключей: удалить всё и добавить новый набор одной командой.
client.domain.update("example.com.ua", sec_dns={
    "rem_all": True,
    "add": {"ds_data": [{"key_tag": 54321, "alg": 13,
                         "digest_type": 2, "digest": "A1B2C3D4E5F60718293A"}]},
})

# Изменить только время жизни подписи.
client.domain.update("example.com.ua", sec_dns={"max_sig_life": 1209600})
```

| Ключ | Действие |
|---|---|
| `add` | отображение с `ds_data` и/или `key_data`, добавляемое к тому, что у домена уже есть |
| `rem` | та же форма; каждое поле обязано совпасть с записью, которую хранит реестр |
| `rem_all` (или `remAll`) | удалить все ключи |
| `max_sig_life` (или `maxSigLife`) | задать время жизни подписи в секундах; может идти отдельно |

В update записи лежат **внутри `add` и `rem`**. `ds_data` на верхнем уровне — это написание для
create, и в дельте оно ничего не значит.

`sec_dns={}` не отправляет `<secDNS:update>` вовсе. Пустой блок был бы 2003 для того, что читается
как «ничего не делать», а это ровно тот случай, в который попадает клиент, строящий блок безусловно и
заполняющий его лишь иногда.

Удалить конкретную запись и удалить всё в одной команде выразить нельзя; то же относится и к
[билдеру update](builders.md), который отказывает в такой комбинации, называя её.

### Лицензия и плата в update

`license=` отправляет `<registry:update><registry:license>`, чтобы сменить номер товарного знака. `fee=`
ограничивает платный update ровно так же, как и в create.

| Код | Значение |
|---|---|
| 1000 | применено |
| 1001 | поставлено в очередь; итог придёт через [poll](poll.md) |
| 2003 | отсутствует обязательный параметр либо команда вообще не несёт изменений |
| 2004 | значение вне диапазона либо согласованная сумма не покрывает цену |
| 2005 | значение сформировано неверно |
| 2303 | такого домена нет |
| 2304 | статус запрещает (`clientUpdateProhibited`, `serverUpdateProhibited`, ожидающий трансфер) |
| 2305 | связь объекта запрещает |
| 2306 | правило реестра отклоняет значение: слабый `auth_info`, смена регистранта, которую зона не допускает |

## delete

```python
client.domain.delete(name: str) -> Response
```

```python
info = client.domain.info("example.com.ua")
if info.subordinate_hosts():
    raise RuntimeError("hosts still live under this domain: %s" % info.subordinate_hosts())

client.domain.delete("example.com.ua")
```

Что именно *делает* удаление, зависит от того, когда вы его отправили. Внутри окна add-grace (5 дней
с регистрации) домен убирается немедленно. После этого он уходит в `redemptionPeriod` на 30 дней —
это видно в `rgp_status()`, а не в `statuses()`, — и в течение этого срока его можно вернуть через
[restore](#restore). Затем он проводит 5 дней в `pendingDelete`, и имя высвобождается.

Сначала проверяйте `subordinate_hosts()`, как выше: реестр отказывается удалять домен, пока под ним
живут объекты серверов имён, а 2305 постфактум — это лишний обмен с сервером.

| Код | Значение |
|---|---|
| 1000 | удалён либо переведён в выкуп |
| 1001 | поставлено в очередь; итог придёт через [poll](poll.md) |
| 2303 | такого домена нет |
| 2304 | статус запрещает (`clientDeleteProhibited`, `serverDeleteProhibited`) |
| 2305 | под доменом всё ещё существуют подчинённые хосты |

## renew

```python
client.domain.renew(name: str,
                    cur_exp_date: str,
                    years: int = 1,
                    fee: Optional[FeeAgreement] = None) -> Response
```

Продлевает регистрацию. **Платно.** `cur_exp_date` уходит как `<domain:curExpDate>` и обязана
равняться текущей дате истечения срока домена — это защита самого протокола от продления домена,
который кто-то уже продлил, пока ваше представление о нём устаревало.

Берите её из ответа реестра, а не из собственной арифметики по календарю:

```python
info = client.domain.info("example.com.ua")
current = info.expiry_date()            # например, '2027-04-01T09:15:00.0Z'

renewed = client.domain.renew("example.com.ua", current, 1, fee="180.00")   # уйдёт '2027-04-01'

renewed.expiry_date()   # НОВАЯ дата истечения срока — сохраните её
renewed.fee_amount()    # '180.00'
renewed.fee_currency()  # 'UAH'
```

`<domain:exDate>` — это отметка времени, а `<domain:curExpDate>` — дата, и дневную часть библиотека
берёт за вас: так, как её написал сервер, без разбора и без перевода часовых поясов. Это сделано
намеренно: отметки времени в EPP — в UTC, и дата истечения у реестра тоже в UTC, поэтому клиент,
который переформатирует её через местный пояс, для каждого домена, истекающего около полуночи,
попадает на сутки в ту или другую сторону и затем продлевает по дате, которой у реестра нет.
Переводите в местное время там, где показываете, а не перед отправкой обратно.

Новая дата истечения срока не может выйти за собственный горизонт реестра — обычно это десять лет.

Несовпадение это 2105, и 2105 стоит обрабатывать отдельно: он означает, что дата истечения срока
домена не такая, как вы думали, а это задача сверки, а не то, что чинится повтором.

| Код | Значение |
|---|---|
| 1000 | продлён |
| 2004 | период вне диапазона либо согласованная сумма не покрывает цену |
| 2104 | недостаточно средств — `InsufficientFundsError` |
| 2105 | `cur_exp_date` не совпадает либо домен не подлежит продлению |
| 2303 | такого домена нет |
| 2304 | статус запрещает (`clientRenewProhibited`, ожидающий трансфер) |
| 2306 | правило реестра отклоняет запрос |

## transfer

```python
client.domain.transfer(op: str,
                       name: str,
                       auth_info: Optional[str] = None,
                       years: Optional[int] = None,
                       fee: Optional[FeeAgreement] = None) -> Response
```

`op` — одно из `request`, `approve`, `reject`, `cancel`, `query`; на провод оно уходит атрибутом `op`
элемента `<transfer>`. Какие из них вам можно отправлять, зависит от того, на какой стороне трансфера
вы находитесь.

```python
# Принимающая сторона: запросить домен, предъявив код, который клиент получил у теряющего регистратора.
r = client.domain.transfer("request", "example.com.ua", "the-code", 1, fee="180.00")

r.code()                # 1001 — трансфер решается позже, а не сейчас
t = r.transfer()
t["status"]             # 'pending'
t["requested_by"]       # reID — регистратор, который запросил
t["requested_at"]       # reDate
t["acting_client"]      # acID — регистратор, который обязан ответить
t["act_by"]             # acDate — КРАЙНИЙ СРОК
t["expiry_date"]        # дата истечения срока, которая будет действовать после завершения
```

```python
# Теряющая сторона: poll-уведомление сообщило, что кто-то хочет домен, которым вы владеете.
client.domain.transfer("approve", "example.com.ua")
client.domain.transfer("reject", "example.com.ua")

# Принимающая сторона передумала, пока запрос ещё в ожидании:
client.domain.transfer("cancel", "example.com.ua")

# Любая сторона в любой момент — сообщает, на какой стадии запрос, ничего не меняя:
client.domain.transfer("query", "example.com.ua").transfer_status()   # 'pending'
```

Три вещи про `act_by`, от которых зависит, останется ли домен у вас:

- **Молчание завершает трансфер.** По истечении срока реестр *подтверждает* его, а не отменяет.
  Теряющий регистратор, который подшил уведомление вместо того, чтобы ответить на него, лишится
  домена, а окно составляет 5 дней.
- Оба регистратора узнают о каждом шаге через [poll](poll.md). Уведомление о трансфере — это то, на
  что отвечают, а не то, что записывают.
- Пока установлен `pendingTransfer`, никакая другая операция с доменом не принимается.

`years` отправляет `<domain:period>` и относится к делам зоны, а не к вашему выбору: в регламентных
зонах трансфер включает обязательное продление на один год, поэтому `1` (или отсутствие значения) —
единственное принимаемое значение, а всё прочее это 2004. В зонах с бесплатным трансфером не
указывайте его вовсе: литеральный `0` — это не меньший период, а нарушение схемы, потому что тип
элемента начинается с 1, и кадр отклоняется как 2001 ещё до всякой политики.

`auth_info` несёт код. В зоне, где коды трансфера не используются, не передавайте его.

| Код | Значение |
|---|---|
| 1000 / 1001 | принято; 1001 означает, что итог придёт позже через [poll](poll.md) |
| 2004 | значение `years`, которое зона не принимает |
| 2106 | объект не может быть перенесён (заблокирован или запрещён по статусу) |
| 2201 | вы не та сторона, которой можно отправлять эту операцию |
| 2202 | `auth_info` неверен либо просрочен по 30-дневному сроку годности |
| 2300 | трансфер уже в ожидании (на повторный `request`) |
| 2301 | трансфер не в ожидании (на `approve`/`reject`/`cancel`/`query`) |
| 2303 | такого домена нет |
| 2304 | статус запрещает |

## restore

```python
client.domain.restore(name: str, fee: Optional[FeeAgreement] = None) -> Response
```

Возвращает домен, находящийся в `redemptionPeriod` (RFC 3915). **Платно**, и цена восстановления
обычно в несколько раз выше регистрации.

Это удобная обёртка над `update`: `restore(name, fee)` — это в точности
`update(name, restore=True, fee=fee)`, который отправляет `domain:update` без блоков add, rem и chg
и с расширением `<rgp:update><rgp:restore op="request"/>`.

```python
info = client.domain.info("example.com.ua")
if "redemptionPeriod" not in info.rgp_status():
    raise RuntimeError("not in redemption; nothing to restore")

r = client.domain.restore("example.com.ua", fee={"amount": "1200.00", "currency": "UAH"})

r.code()             # 1000 восстановлен сейчас, либо 1001 восстановлен позже
r.expiry_date()      # дата истечения срока после восстановления
r.fee_amount()       # во что это обошлось
```

**Восстановление должно быть единственным содержимым команды.** Сочетание `restore=True` с `add`,
`rem`, `chg`, лицензией или изменением DNSSEC в том же `update` отклоняется с кодом 2306;
перенаправляйте серверы имён второй командой, когда домен уже вернулся.

1001 здесь нормален для части зон: реестр откладывает восстановление, помечает домен
`pendingUpdate`, и итог приходит как poll-уведомление. Не отправляйте команду повторно — вторая
команда, пока первая в работе, это то, как плата за восстановление списывается дважды.

| Код | Значение |
|---|---|
| 1000 | восстановлен |
| 1001 | поставлено в очередь; итог придёт через [poll](poll.md) |
| 2104 | недостаточно средств — `InsufficientFundsError` |
| 2303 | такого домена нет |
| 2304 | домен не в периоде выкупа, окно закрылось, либо статус запрещает update |
| 2306 | восстановление было не единственной операцией в команде |

## Когда операция не удалась, а вы не знаете, произошла ли она

Разорванное соединение или тайм-аут чтения посреди `create`, `renew`, `transfer` или `restore`
оставляет исход по-настоящему неизвестным: реестр мог выполнить команду и списать деньги ещё до
того, как ответ потерялся.

**Не повторяйте команду вслепую.** Слепой повтор — это то, как домен регистрируется (и оплачивается)
дважды. Спросите у реестра, как обстоят дела: `domain.info()` после create, а после renew сравните
`expiry_date()` с тем, что вы ожидали. Повторяйте, только если объект действительно в том состоянии,
из которого вы начинали. Полностью это разобрано в разделе [Ошибки](errors.md).
