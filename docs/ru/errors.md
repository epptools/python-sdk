# Ошибки

Любой сбой, который поднимает эта библиотека, наследует `EppException`, поэтому один `except` ловит
всё:

```python
from epptools.exceptions import EppException

try:
    client.domain.create("example.com.ua", years=1, registrant="C1")
except EppException as exc:
    log.error("EPP failed: %s", exc)
```

Дальше **класс существует там, где отличается правильный следующий шаг, и больше нигде**. Класса на
каждый код ответа нет, потому что для большинства кодов вы не стали бы писать разный код; класс есть
там, где ответ звучит как «пополнить счёт», «переподключиться», «взять другое имя» или «починить
развёртывание», — потому что это четыре разные программы.

`EppException` наследует `RuntimeError`, поэтому голый `except ValueError` его не ловит — с двумя
намеренными исключениями, отмеченными ниже.

## Иерархия исключений

```
EppException                     (RuntimeError)
├── ConnectionException          transport: TLS, timeout, framing
├── ConfigException              (also ValueError) this client is set up wrong
├── ValidationException          (also ValueError) this call's arguments are wrong
└── CommandException             the registry refused (a result code >= 2000)
    ├── AuthenticationException  2200 — the login itself failed
    ├── InsufficientFundsError   2104
    ├── AuthorizationError       2201, 2202
    ├── ObjectExistsError        2302
    ├── ObjectDoesNotExistError  2303
    ├── ObjectStatusError        2304, 2305
    ├── PolicyError              2306, 2308
    └── SessionError             2500, 2501, 2502
```

| Что ловить | Когда поднимается | Коды | Что делать дальше |
|---|---|---|---|
| `ValidationException` | значение в **этом вызове** использовать нельзя; ничего не отправлено | — | Исправьте аргументы. Следующий вызов с другими аргументами сработает. |
| `ConfigException` | **клиент** настроен неверно: нет хоста, нет учётных данных, пароль, который этот сервер не может принять | — | Чините развёртывание. До тех пор каждый вызов будет падать одинаково. |
| `ConnectionException` | TLS, тайм-аут, кадрирование, рассинхронизированный поток, некорректный XML от сервера | — | Соединение закончено. Выполните `connect()` и `login()` заново — и прочтите [Когда исход неизвестен](#когда-исход-неизвестен), прежде чем что-либо отправлять повторно. |
| `AuthenticationException` | `login()` отклонён | 2200 | clID или пароль неверны. Не зацикливайтесь: за повторные неудачи адрес блокируют. |
| `InsufficientFundsError` | счёт не может оплатить эту операцию | 2104 | **Остановите пакет.** Сообщите тому, кто пополняет счёт, пополните, продолжите. Каждая следующая платная команда упадёт точно так же. |
| `AuthorizationError` | объект существует, но не для вас, либо `authInfo` не совпадает | 2201, 2202 | Это не повод для повтора. Проверьте, что вы владелец объекта и что код трансфера действующий — он стареет. |
| `ObjectExistsError` | уже зарегистрирован | 2302 | Возьмите другое имя или идентификатор. Повтор не сделает его свободным. Чтобы полностью снять столкновения идентификаторов, используйте `create_auto()`. |
| `ObjectDoesNotExistError` | такого домена, идентификатора или хоста нет | 2303 | Устаревший идентификатор или опечатка. Перечитайте свои записи; не создавайте вслепую. |
| `ObjectStatusError` | мешает статус или связь объекта | 2304, 2305 | Снимите то, что мешает, — `clientHold`, связанный контакт, подчинённый хост — и отправьте ту же команду снова. |
| `PolicyError` | собственные правила реестра отклоняют значение | 2306, 2308 | Команда сформирована верно и отправлять её можно; недопустимо значение. Измените запрос. |
| `SessionError` | сервер завершает сессию | 2500, 2501, 2502 | Переподключитесь и войдите заново. Сама команда может быть безупречной — 2502 это предел числа сессий, а не неверный пароль. |
| `CommandException` | любой другой код 2000 и выше | — | Ветвитесь по `.epp_code`. |

Каждый из частных классов остаётся `CommandException`, поэтому `except CommandException`, поставленный
последним, ловит всё, что вы не назвали.

```python
from epptools.exceptions import (
    CommandException, InsufficientFundsError, ObjectExistsError, SessionError,
)

try:
    client.domain.create(name, years=1, registrant="C1")
except InsufficientFundsError:
    stop_the_batch()
except ObjectExistsError as exc:
    taken.append(exc.subject() or name)
except SessionError:
    reconnect()
except CommandException as exc:
    log.warning("EPP %d on %s: %s", exc.epp_code, name, exc)
```

`AuthenticationException` — это то, что `login()` поднимает на код 2200. Вход, отклонённый по любой
другой причине, поднимает подходящий класс: 2502 при пределе числа сессий, 2501 при остановке
сервера, 2307 при URI сервиса, которого сервер не предлагает, 2002 при повторном входе на одном
соединении, — потому что называть всё это сбоем аутентификации значит отправить вас менять пароль,
который никогда не был причиной.

## Плохой аргумент — не плохая конфигурация

`ValidationException` и `ConfigException` похожи и требуют противоположных действий, поэтому это
разные классы:

| | `ValidationException` | `ConfigException` |
|---|---|---|
| Что не так | аргументы одного вызова | клиент, развёртывание, учётные данные |
| Чья ошибка | обычно обслуживаемого запроса | обычно оператора |
| Кто должен об этом узнать | вызывающая сторона — 400 вашему API-клиенту, сообщение в форме | оповещение тому, кто отвечает за сервис |
| Сработает ли следующий вызов | да, с другими аргументами | нет. Каждый вызов будет падать, пока не изменится развёртывание |

Общий класс на двоих оставляет сервис гадать, а неверная догадка сообщает клиенту о собственной
ошибке оператора как о его ошибке — или прячет полный простой за «неверным запросом» в чужом журнале.

Оба являются к тому же `ValueError`, поэтому уже написанный вами `except ValueError` продолжает их
ловить — так же, как `json.JSONDecodeError` тоже является `ValueError`.

### Что поднимает ValidationException

Когда поднимается что-то из этого, ничего ещё не отправлено — сокет не тронут, и клиент по-прежнему
пригоден к работе:

| Что поднимает | Почему |
|---|---|
| неизвестный ключ в `chg` или `sec_dns` | ключ, который никто не читает, — это изменение, которого не произошло, спрятанное за кодом 1000. Сообщение называет ближайший знакомый ключ |
| сумма платы, не являющаяся простым десятичным числом | `'100,00'`, `'$100'` — см. [Баланс](balance.md#ограничение-суммы-которую-вы-согласны-платить) |
| больше 20 ценовых позиций в одном `check` | предел на кадр |
| смешение моделей серверов имён в одной команде | RFC 5731 делает `<domain:ns>` выбором |
| `host.update(new_name=...)` | в этом реестре переименования нет; сообщение говорит, что делать вместо него |
| `contact.create()` без e-mail | RFC 5733 требует его |
| `auth_info` и `clear_auth_info` в одном `chg` | схема не может выразить оба сразу |
| `remove_all_dnssec()` вместе с `rem_ds_record()` | то же самое |
| второй `send()` у билдера | один билдер несёт одну команду |
| обработчик `async def`, переданный в `poll.drain()` | он подтвердил бы все уведомления до того, как обработано хоть одно |
| пустая роль контакта, пустой дайджест, пустой открытый ключ, имя нераскрываемого поля | значение не может уйти на провод |

Иначе каждое из этого стало бы невнятным отказом реестра — часто голым 2001, не называющим ни одного
поля, — который приходит уже после попытки выполнить команду, или, что хуже, кодом 1000 на команду,
которая тихо сделала меньше, чем вы просили.

### Что поднимает ConfigException

| Что поднимает | Почему |
|---|---|
| `Config(host="")` при `connect()` | подключаться некуда |
| пустой `clid` или `password` при `login()` | сообщение говорит, какое из двух пусто, не печатая ни одного |
| пароль вне диапазона 6–128 символов | проверяется до открытия сокета |
| пароль длиннее 16 символов на сервере, который не предлагает RFC 8807 | базовый элемент `<pw>` его не унесёт; сервер ответил бы голым 2001 |
| `Config.from_dict()` с неизвестным ключом | настройка с опечаткой — это настройка, которая не применена |

См. [Сессия → Config](session.md).

## Что несёт CommandException

| Член | Тип | Что это |
|---|---|---|
| `.epp_code` | `int` | Код ответа, который прислал реестр |
| `.response` | `Response` | Весь разобранный ответ — `sv_trid()`, `ext_values()`, всё |
| `.subject()` | `Optional[str]` | Объект, к которому у реестра претензия, если он его назвал |
| `.reasons()` | `List[str]` | Дополнительный текст `<extValue><reason>` сверх однострочного сообщения |
| `.is_retryable()` | `bool` | Может ли повтор ровно той же команды сработать |
| `str(exc)` | `str` | `EPP 2302: Object exists ('taken.com.ua')` |

```python
try:
    client.domain.check(["example1.com.ua", "example2.com.ua", "taken.com.ua"])
except CommandException as exc:
    exc.epp_code               # 2302
    exc.subject()              # 'taken.com.ua' — какое из трёх
    exc.reasons()              # ['Already registered']
    exc.response.sv_trid()     # идентификатор, по которому поддержка найдёт операцию
```

`subject()` — это то, что делает команду с несколькими именами пригодной к обработке: «EPP 2302:
Object exists» оставляет вас гадать, какое из трёх, а ответ лежит в `<extValue>`. Он равен `None`,
когда реестр ничего не назвал, а это бывает часто, поэтому держите собственный запасной вариант —
`exc.subject() or name`.

Сохраняйте `exc.response.sv_trid()` вместе со сбоем. Это значение, которое может найти у себя служба
поддержки реестра; ваш clTRID не значит ничего ни для кого, кроме вас.

## Повторы

```python
exc.is_retryable()
```

**Истинно ровно для четырёх кодов** и ложно для всех остальных:

| Код | Класс | Почему повтор может сработать |
|---|---|---|
| 2400 | `CommandException` | команда не удалась по причине на стороне сервера, именно в тот момент |
| 2500 | `SessionError` | сервер закрывает соединение — повторяйте после переподключения |
| 2501 | `SessionError` | то же самое |
| 2502 | `SessionError` | достигнут предел числа сессий — повторяйте после переподключения или с меньшим числом сессий |

Всё остальное ложно намеренно. Повтор 2302 не сделает имя свободным; повтор 2104 не оплатит его;
повтор 2306 не изменит политику реестра. Цикл, считающий любой сбой временным, превращает один отказ
в блокировку по частоте запросов, а адрес, заблокированный за долбёжку, — это простой хуже того сбоя,
с которого всё началось.

Три из этих четырёх кодов, которые являются `SessionError`, повторяемы **после** переподключения.
Повтор на соединении, которое уже отказало, отправляет данные в сокет, с которым сервер закончил:

```python
for name in names:
    try:
        client.domain.create(name, years=1, registrant="C1")
    except SessionError:
        client.disconnect()
        client.connect()
        client.login()
        retry_later.append(name)          # сначала сверка — см. ниже
    except CommandException as exc:
        if not exc.is_retryable():
            raise
        retry_later.append(name)
```

Делайте паузы между попытками и ограничивайте их число. Два повтора с интервалом в несколько секунд —
это восстановление; плотный цикл — это отказ в обслуживании, который вы устраиваете собственной
учётной записи.

## Чтение кодов вместо их перехвата

```python
client.throw_on_failure(False)     # возвращает клиент, поэтому вызовы можно сцеплять
response = client.domain.check(["example.com.ua"])
if not response.is_success():
    log.warning("EPP %d: %s", response.code(), response.message())
```

У `ResultCode` есть именованная константа на каждый код, поэтому ветвление не обязано записывать
число:

```python
from epptools import ResultCode

if response.code() == ResultCode.OBJECT_EXISTS:
    ...
```

Две вещи продолжают поднимать исключения даже с выключенным переключателем, потому что вернуть вместо
них осмысленный `Response` не из чего:

- **`login()`** на любом коде, кроме 1000. Продолжать не в чем: сессии нет.
- **`poll.drain()`**, когда ответ на poll — это ни уведомление, ни пустая очередь. Прочитать отказ как
  «очередь разобрана» значило бы сообщить об успехе, не прочитав ничего.

Выключить переключатель означает, что теперь каждый сбой замечать вам. Команда `create`, чей код 2104
никто не проверил, — это домен, который ваша система считает зарегистрированным.

## Полный перечень кодов ответа

`1xxx` — успех. `2xxx` — отказ, и, кроме описанного ниже случая с неизвестным исходом, ничего не
изменено и ничего не списано.

### Успех

| Код | `ResultCode` | Значение | Что делать |
|---|---|---|---|
| 1000 | `SUCCESS` | выполнено | продолжать |
| 1001 | `SUCCESS_PENDING` | принято, завершается асинхронно | **не отправляйте повторно.** Запишите svTRID; итог придёт как [poll-уведомление](poll.md#итог-отложенного-действия) |
| 1300 | `SUCCESS_NO_MESSAGES` | очередь poll пуста | прекратить разбор |
| 1301 | `SUCCESS_ACK_TO_DEQUEUE` | приложено poll-уведомление | обработать, затем подтвердить |
| 1500 | `SUCCESS_END_SESSION` | выход из сессии принят | отключиться |

### Протокол и синтаксис

| Код | `ResultCode` | Значение | Что делать |
|---|---|---|---|
| 2000 | `UNKNOWN_COMMAND` | сервер не знает такой команды | проверьте глагол; обычная причина — сырой кадр |
| 2001 | `COMMAND_SYNTAX_ERROR` | кадр не удовлетворяет схеме | сообщение не называет поля: сверьте кадр с RFC или с командой, которую строит библиотека |
| 2002 | `COMMAND_USE_ERROR` | верная команда не вовремя — повторный `login()` на одном соединении | исправьте последовательность |
| 2003 | `REQUIRED_PARAMETER_MISSING` | отсутствует обязательный элемент либо команда вообще не несёт изменений | добавьте его |
| 2004 | `PARAMETER_VALUE_RANGE_ERROR` | значение вне диапазона — период либо согласованная сумма, не покрывающая цену | см. [Баланс](balance.md#что-означает-отказ-2004) |
| 2005 | `PARAMETER_VALUE_SYNTAX_ERROR` | значение сформировано неверно: плохая метка, плохой адрес, кириллица в почтовом блоке `int` | исправьте значение |

### Нереализованное и биллинг

| Код | `ResultCode` | Значение | Что делать |
|---|---|---|---|
| 2100 | `UNIMPLEMENTED_PROTOCOL_VERSION` | `<version>` при входе обязана быть 1.0 | через собственный вход этой библиотеки недостижимо |
| 2101 | `UNIMPLEMENTED_COMMAND` | сервер не реализует эту команду | спросите реестр, что он обслуживает |
| 2102 | `UNIMPLEMENTED_OPTION` | параметр, который сервер не реализует, например неподдерживаемый `lang` | измените `Config.lang` |
| 2103 | `UNIMPLEMENTED_EXTENSION` | вы использовали расширение, которое эта точка подключения не обслуживает | проверьте приветствие: `service_ext_uris()` |
| 2104 | `BILLING_FAILURE` | недостаточно средств — **`InsufficientFundsError`** | остановите пакет, пополните счёт, продолжите |
| 2105 | `NOT_ELIGIBLE_FOR_RENEWAL` | `cur_exp_date` не совпадает либо домен не подлежит продлению | перечитайте `expiry_date()`; это сверка, а не повтор |
| 2106 | `NOT_ELIGIBLE_FOR_TRANSFER` | объект не может быть перенесён | проверьте его статусы и правила зоны |

### Безопасность

| Код | `ResultCode` | Значение | Что делать |
|---|---|---|---|
| 2200 | `AUTHENTICATION_ERROR` | вход не удался — **`AuthenticationException`** | исправьте учётные данные; не зацикливайтесь |
| 2201 | `AUTHORIZATION_ERROR` | объект не ваш — **`AuthorizationError`** | вы не владелец либо вам нельзя отправлять эту операцию трансфера |
| 2202 | `INVALID_AUTHORIZATION` | `authInfo` неверен — **`AuthorizationError`** | возьмите действующий код; код трансфера стареет через 30 дней после того, как был задан |

### Жизненный цикл объекта

| Код | `ResultCode` | Значение | Что делать |
|---|---|---|---|
| 2300 | `OBJECT_PENDING_TRANSFER` | трансфер уже в ожидании | дождитесь его либо `approve`/`reject`/`cancel` |
| 2301 | `OBJECT_NOT_PENDING_TRANSFER` | нечего одобрять, отклонять, отменять или запрашивать | трансфер уже решён |
| 2302 | `OBJECT_EXISTS` | уже зарегистрирован — **`ObjectExistsError`** | возьмите другое имя или идентификатор |
| 2303 | `OBJECT_DOES_NOT_EXIST` | такого объекта нет — **`ObjectDoesNotExistError`** | устаревший идентификатор, опечатка либо уже подтверждённый идентификатор poll-сообщения |
| 2304 | `OBJECT_STATUS_PROHIBITS_OPERATION` | статус запрещает — **`ObjectStatusError`** | снимите статус, затем повторите |
| 2305 | `OBJECT_ASSOCIATION_PROHIBITS_OPERATION` | связь объекта запрещает — **`ObjectStatusError`** | сначала отвяжите связанный контакт, хост или домен |
| 2306 | `PARAMETER_VALUE_POLICY_ERROR` | правило реестра отклоняет значение — **`PolicyError`** | измените запрос |
| 2307 | `UNIMPLEMENTED_OBJECT_SERVICE` | объектный сервис или зона здесь не обслуживаются | проверьте приветствие |
| 2308 | `DATA_MANAGEMENT_POLICY_VIOLATION` | правило управления данными отклоняет операцию — **`PolicyError`** | измените запрос |

### Сервер

| Код | `ResultCode` | Значение | Что делать |
|---|---|---|---|
| 2400 | `COMMAND_FAILED` | команда не удалась на стороне сервера | **повторяемо**; выдержите паузу, затем попробуйте раз или два |
| 2500 | `COMMAND_FAILED_SERVER_CLOSING` | не удалась, и соединение закрывается — **`SessionError`** | переподключитесь, войдите, затем повторите |
| 2501 | `AUTHENTICATION_SERVER_CLOSING` | сервер закрывает соединение — **`SessionError`** | переподключитесь и войдите |
| 2502 | `SESSION_LIMIT_EXCEEDED_SERVER_CLOSING` | слишком много одновременных сессий — **`SessionError`** | закройте сессии, которыми не пользуетесь; всегда вызывайте `logout()` |

## Когда исход неизвестен

Тайм-аут чтения, разорванное соединение или `ConnectionException` посреди `create`, `renew`,
`transfer` или `restore` оставляет исход по-настоящему неизвестным. Реестр мог выполнить команду и
списать деньги ещё до того, как ответ потерялся. Эта библиотека отличить одно от другого не может, и
вы по исключению тоже: читать нечего, ответа нет.

> **Не повторяйте команду вслепую.** Слепой повтор — это то, как домен регистрируется (и
> оплачивается) дважды.

Вместо этого спросите у реестра, как обстоят дела, на новом соединении, и сведите данные по ответу:

| Какая команда сорвалась | Как выяснить, что произошло | Повторять, только если |
|---|---|---|
| `domain.create` | `domain.info(name)` | домена не существует либо он существует под другим владельцем |
| `domain.renew` | `domain.info(name)`, сравнить `expiry_date()` с ожидаемой | дата истечения срока всё ещё прежняя |
| `domain.transfer("request", …)` | `domain.transfer("query", name)` | никакой трансфер не в ожидании |
| `domain.restore` | `domain.info(name)`, прочитать `rgp_status()` | домен всё ещё в `redemptionPeriod` |
| `contact.create` | `contact.info(id)` — или ничего, если это был `create_auto()` | идентификатора не существует |

```python
from epptools.exceptions import ConnectionException, ObjectDoesNotExistError

try:
    created = client.domain.create(name, years=1, registrant="C1", fee=price)
except ConnectionException:
    # Соединение закончено; судьба команды неизвестна.
    client.disconnect()
    client.connect()
    client.login()

    try:
        info = client.domain.info(name)
    except ObjectDoesNotExistError:
        created = client.domain.create(name, years=1,          # действительно не произошло
                                       registrant="C1", fee=price)
    else:
        if info.sponsor() == my_clid:
            book_as_registered(name, info.expiry_date())       # произошло; не отправляйте снова
        else:
            alert_operator("%s exists and belongs to %s" % (name, info.sponsor()))
```

Три вещи, которые здесь показаны, и каждая намеренна:

- **Проверка идёт на новом соединении.** `ConnectionException` означает, что поток байтов находится на
  неизвестном смещении; сокет закончен, и всякий следующий вызов на нём поднимет исключение.
- **`create_auto()` — единственный случай, который свести нельзя.** Каждый вызов даёт новый
  идентификатор, поэтому вторая попытка — это второй контакт, а не столкновение; ровно поэтому
  идентификатор появляется только в том ответе, который вы потеряли. Потерянный `create_auto()`
  сводите вручную.
- **Сбой, исход которого вы определить не можете, заслуживает внимания оператора**, а не
  автоматической второй попытки. Оповещайте о нём; не заворачивайте его в очередь повторов.

То же рассуждение относится и к **1001**: команда принята и завершается асинхронно. Это не сбой и это
не повод отправлять её снова. Запишите svTRID и дождитесь
[poll-уведомления](poll.md#итог-отложенного-действия), которое несёт результат.

## Пакет, который падает правильно

```python
from epptools.exceptions import (
    CommandException, InsufficientFundsError, ObjectExistsError, ValidationException,
)

taken, retry_later, refused = [], [], []

for name in names_to_register:
    try:
        client.domain.create_builder(name).years(1).registrant("C1").send()
    except InsufficientFundsError as exc:
        # Проблема не этого имени, а счёта. Каждое оставшееся имя упадёт точно так же.
        alert_billing(str(exc))
        break
    except ObjectExistsError as exc:
        taken.append(exc.subject() or name)
    except ValidationException as exc:
        refused.append((name, str(exc)))        # наш собственный ввод; ничего не отправлено
    except CommandException as exc:
        if not exc.is_retryable():
            refused.append((name, "EPP %d: %s" % (exc.epp_code, exc)))
            continue
        retry_later.append(name)
```

Смысл в самой форме. Один сбой останавливает прогон, потому что продолжать бесполезно; другой — это
исход по конкретному имени, который надо записать; третий вовсе не дошёл до провода; и только
по-настоящему временные попадают в очередь повторов.

## Как сообщить о проблеме

Приложите **svTRID** из ответа (`exc.response.sv_trid()`) и **clTRID**, который отправил ваш клиент.
Вместе они определяют конкретную транзакцию в журналах реестра, а это то, что позволяет ответить на
обращение без лишнего круга вопросов. Приложите и сами кадры, если можете, но сначала скройте `<pw>`,
`<newPW>` и `<authInfo>`: это действующие учётные данные, и библиотека маскирует их в собственных
журналах по той же причине.

Вопросы о библиотеке, о кадре, который отверг реестр, или об ошибке: **https://github.com/epptools/python-sdk/issues**.
