# Баланс и цены

На этой странице живут две вещи, и они отвечают на два денежных вопроса любой интеграции: **сколько
я могу потратить** и **во что это обойдётся**.

Первое — это `client.balance()`, собственный запрос состояния счёта у реестра. Второе — **расширение
тарифов из RFC 8748**, которое едет на тех же командах, что вы и так отправляли: `check` может
спросить цену, а `create`, `renew`, `transfer` или `restore` — нести предел того, на что вы
соглашаетесь.

Все суммы в этом руководстве иллюстративны. Тариф реестра публикует сам реестр.

## Деньги — это строка

**Каждый показатель на этой странице приходит точной десятичной строкой, а не числом `float`.**
`0.1 + 0.2` в двоичной плавающей арифметике не равно `0.3`, и баланс, который так суммируют или
сравнивают, уплывает — тихо и в ту сторону, которую никто не замечает до сверки. Храните строку и
считайте через `decimal.Decimal`:

```python
from decimal import Decimal

spendable = Decimal(client.balance().available_credit() or "0")
if spendable < Decimal("500.00"):
    stop_the_batch()
```

## Команда баланса

```python
client.balance() -> Response
```

Отправляет команду `<info>` в собственном пространстве имён баланса реестра, которое читается из
`<greeting>` — см. [`client.registry_balance_uri()`](commands.md#собственные-расширения-вашего-реестра).
Она не тарифицируется, ничего не меняет и её безопасно выполнять по расписанию.

```python
money = client.balance()

money.balance()            # {'creditLimit': '1000.00', 'balance': '250.50',
                           #  'availableCredit': '1250.50'}
money.credit_limit()       # '1000.00'
money.current_balance()    # '250.50'
money.available_credit()   # '1250.50'
```

| Метод | Что возвращает | Когда в ответе ничего нет |
|---|---|---|
| `balance() -> Optional[Dict[str, str]]` | Все три показателя сразу, с ключами `creditLimit`, `balance`, `availableCredit` | `None`, когда это не ответ о балансе |
| `credit_limit() -> Optional[str]` | Кредит, который реестр даёт **сверх** нулевого баланса | `None` |
| `current_balance() -> Optional[str]` | Средства на счёте прямо сейчас | `None` |
| `available_credit() -> Optional[str]` | Что вы действительно можете потратить — баланс плюс неиспользованный кредит | `None` |

Все три не взаимозаменяемы, и пакет операций стоит сверять с третьим:

- `current_balance()` может быть нулевым, а вы всё ещё способны регистрировать домены, потому что
  кредитная линия никуда не делась.
- `credit_limit()` — это потолок, а не деньги. По мере трат он не уменьшается.
- `available_credit()` — то число, которое обращается в ноль в тот момент, когда следующая платная
  команда начинает отказывать с кодом 2104.

`balance()` возвращает `None` на любом ответе, который не является ответом о балансе, поэтому
случайный вызов на чужом ответе даст вам `None`, а не неверное число.

| Код | Значение |
|---|---|
| 1000 | ответ получен |
| 2103 | эта точка подключения не обслуживает расширение баланса |

Запрос баланса не описан ни в одном RFC, поэтому реестр может его и не предлагать — и клиент знает
об этом ещё до отправки, из приветствия. `balance()` бросает `ConfigException`, а не отправляет кадр,
который сервер проигнорирует, так что можно и просто спросить:

```python
client.connect()
if client.registry_balance_uri() is None:
    ...                     # запроса счёта здесь нет; спросите реестр
```

### Как за ним следить

Читайте баланс до пакета операций, а не после того, как он сорвался. Код 2104 посреди прогона
поднимает [`InsufficientFundsError`](errors.md#иерархия-исключений), и каждая следующая платная
команда в этом прогоне отказывает точно так же, поэтому цикл будет перемалывать очередь, выдавая
одинаковые отказы, пока вы его не остановите.

Реестр к тому же предупреждает вас до того, как счёт опустеет, и это предупреждение приходит как
[poll-уведомление](poll.md#предупреждение-о-низком-балансе). Значит, разбор очереди относится к
биллингу, а не только к подготовке доменов.

## Откуда берётся цена

Три разных ответа на три разных вопроса:

| Вопрос | Как спросить | Что читать |
|---|---|---|
| Во что мне обойдётся это имя? | `domain.check(names, fee={...})` | `fees()`, `fee_for()` |
| По какой цене продлевается домен, который у меня уже есть? | `domain.info(name)` | `prices()`, `price_channel()` |
| Сколько списала эта команда? | любая изменяющая команда | `charged_fee()`, `fee_amount()` |

Первый вопрос — это RFC 8748 и большая часть этой страницы. Расширение необязательно с обеих сторон:
без аргумента `fee=` ничего не меняется и реестр списывает собственную цену.

## Запрос цены при check

```python
client.domain.check(names: List[str],
                    fee: Optional[Dict[str, Any]] = None,
                    currency: Optional[str] = None) -> Response
```

`fee` сопоставляет **операцию** с **числом лет**, на которое её нужно оценить. Он добавляет довесок
`<fee:check>` в `<extension>`, поэтому доступность и цена приходят за один обмен с сервером:

```python
r = client.domain.check(["example.com.ua"], fee={"create": 1, "renew": 1})

r.is_available("example.com.ua")                 # True
r.fee_for("example.com.ua", "create", 1)         # '100.00'
r.fee_for("example.com.ua", "renew", 1)          # '90.00'
r.fees()["_currency"]                            # 'UAH'
```

Называть можно операции `create`, `renew`, `transfer`, `restore`, `update` и `delete` — по одному
`<fee:command name="…">` на каждую, с вложенным `<fee:period unit="y">`.

Период меньше года выразить нельзя: схемный тип периода начинается с 1, и переданный вами `0`
отправляется как `1`, а не как кадр, который реестр отвергнет.

Остальное про `check` — предел в десять имён на команду, `availability()`, `is_available()`,
возвращающий `None`, — на странице [Домены → check](domains.md#check).

### Целая таблица цен одной командой

**Список** лет спрашивает одну и ту же операцию на каждом периоде, поэтому таблица цен из пяти строк
обходится в один обмен с сервером вместо пяти:

```python
table = client.domain.check(["example.com.ua"],
                            fee={"create": [1, 2, 3, 5, 10], "renew": [1, 2]},
                            currency="UAH")

table.fee_for("example.com.ua", "create", 5)     # '480.00'
table.fee_for("example.com.ua", "create", 10)    # '940.00'
table.fee_for("example.com.ua", "renew", 2)      # '175.00'
```

**Кадр несёт не более 20 ценовых позиций.** Позиции считаются по всем операциям сразу, поэтому пример
выше использует семь: пять периодов create и два периода renew.

Сверх двадцати библиотека поднимает `ValidationException` и не отправляет ничего:

```python
client.domain.check(["example.com.ua"], fee={"create": list(range(1, 22))})
# ValidationException: a fee query carries at most 20 entries; this one has 21
```

Отказ здесь, а не на проводе, — это разница между сообщением, которое называет предел, и кодом 2306,
который не называет ничего. Предел доступен как `MAX_FEE_COMMANDS` в `epptools.commands`, если вы
предпочитаете разбивать запросы по константе, а не по числу.

### Трансфер и восстановление — операции на один год

Скажем прямо, потому что спрашивать иначе значит тратить позиции и неверно читать ответ:

> **`transfer` и `restore` тарифицируются за один год, сколько бы лет вы ни запросили.** В ответе
> отражается тот период, который действительно был оценён, то есть один год.

```python
r = client.domain.check(["example.com.ua"], fee={"transfer": [1, 2, 5]})

r.fee_for("example.com.ua", "transfer", 1)   # '180.00' — это и есть ответ
r.fee_for("example.com.ua", "transfer", 5)   # None — на пять лет ничего не оценивалось
```

Спрашивайте эти две операции на одном годе и читайте их обратно на одном годе. `fee_for()`
сопоставляет период из *ответа*, поэтому обращение к периоду, который реестр не котировал, вернёт
`None`, а не число из соседней строки.

В регламентных зонах трансфер к тому же несёт обязательное продление на год, и это отдельный от
периода тарификации вопрос — см. [Домены → transfer](domains.md#transfer).

### Указание валюты

`currency` просит котировку в названной вами валюте. Она уходит в верхнем регистре, в
`<fee:currency>`:

```python
r = client.domain.check(["example.com.ua"], fee={"create": 1}, currency="UAH")
r.fees()["_currency"]        # 'UAH'
```

Опустите его — и получите собственную валюту реестра. Валюта, в которой реестр **не** тарифицирует,
возвращается недоступной позицией с причиной, а не пересчитанной догадкой, потому что пересчёт,
которого реестр не делал, — это число, которое никто не подтвердит:

```python
r = client.domain.check(["example.com.ua"], fee={"create": 1}, currency="XXX")
entry = r.fees()["example.com.ua"]
entry["avail"]      # False
entry["reason"]     # 'Currency not supported'
```

Передавайте `currency` вместе с `fee`. Сам по себе он не даёт реестру ничего, что можно оценить.

## Чтение ответа

`fees()` возвращает всю таблицу с ключами по именам плюс ключ `_currency`:

```python
r.fees()
# {'_currency': 'UAH',
#  'example.com.ua': {
#      'avail': True,
#      'reason': None,
#      'class': 'premium',                      # присутствует, только если реестр её объявил
#      'commands': {'create': {'years': 1, 'fee': '100.00'},
#                   'renew':  {'years': 1, 'fee': '90.00'}},
#      'periods': [{'op': 'create', 'years': 1,  'fee': '100.00'},
#                  {'op': 'create', 'years': 5,  'fee': '480.00'},
#                  {'op': 'create', 'years': 10, 'fee': '940.00'},
#                  {'op': 'renew',  'years': 1,  'fee': '90.00'}]}}
```

| Ключ | Что в нём |
|---|---|
| `_currency` | Валюта, в которой даны все котировки таблицы |
| `avail` | Можно ли вообще оценить это имя; `False` приходит с `reason` |
| `reason` | Почему нет: зона не обслуживается, в этой валюте нет тарификации, операция не предлагается |
| `class` | Тарифный класс реестра, присутствует, только если реестр его объявил |
| `commands` | По одной записи на операцию — **первый** запрошенный период |
| `periods` | Все котировки в том порядке, в каком их нёс ответ |

`commands` имеет ключами одни лишь операции, поэтому там лежит по одной записи на операцию, сколько
бы периодов вы ни спросили. `periods` содержит их все. Когда вы спрашивали несколько периодов,
читайте `periods` — или пусть нужный выберет `fee_for()`:

| Метод | Что возвращает | Когда в ответе ничего нет |
|---|---|---|
| `fees() -> Dict[str, object]` | Таблицу выше | `{}`, когда ответ не нёс тарифных данных |
| `fee_for(name, operation, years=1) -> Optional[str]` | Одну котировку точной десятичной строкой | `None`, когда для этого сочетания ничего не котировалось |
| `fee_class(name=None) -> Optional[str]` | `'premium'`, `'standard'` … | `None`, когда ответ не объявил класса |
| `is_premium(name=None) -> bool` | Тарифицируется ли имя вне стандартного списка | `False` |

```python
r = client.domain.check(["rare.com.ua"], fee={"create": 1})

if r.is_premium("rare.com.ua"):
    price = r.fee_for("rare.com.ua", "create", 1)
    require_operator_approval("rare.com.ua", price, r.fee_class("rare.com.ua"))
```

**`is_premium()`, вернувший `False`, не обещает стандартной цены.** Он означает, что ответ не объявил
особого класса. Списывайте по `fees()` и ограничивайте саму изменяющую команду — об этом следующий
раздел.

Недоступное имя — это обычный 1000 с `avail: False`, а не ошибка. Тарифная позиция для имени, которое
реестр оценивать не станет, — то же самое: обычная, отвеченная и несущая свою причину.

## Ограничение суммы, которую вы согласны платить

Каждая изменяющая команда, за которую может списываться плата, принимает необязательный аргумент
`fee`. Это **не цена, которую вы назначаете**. Реестр списывает собственную цену; согласие — это
максимум, который вы готовы заплатить:

> Если реальная цена **выше** согласованной вами, команда отклоняется с кодом **2004** и **ничего не
> списывается**.

В этом весь смысл того, чтобы её отправлять. Изменение тарифа, премиальное имя, котировка, отставшая
в вашем кеше на сутки, — любое из этого молча спишет с вас разницу, если согласия нет, и полностью
отклонит команду, если оно есть.

```python
client.domain.create("example.com.ua", years=1, registrant="C1", fee="100.00")
client.domain.renew("example.com.ua", "2027-04-01", 1,
                    fee={"amount": "90.00", "currency": "UAH"})
client.domain.transfer("request", "example.com.ua", "the-code", 1, fee="180.00")
client.domain.restore("example.com.ua", fee="1200.00")
client.domain.update("example.com.ua", chg={"registrant": "EXAMPLE-C9"}, fee="50.00")
```

| Форма | Значение |
|---|---|
| `fee="100.00"` | до 100.00 в собственной валюте реестра |
| `fee={"amount": "100.00", "currency": "UAH"}` | до 100.00, и именно в этой валюте |

| Команда | Элемент, в котором едет согласие |
|---|---|
| `domain.create` | `<fee:create>` |
| `domain.renew` | `<fee:renew>` |
| `domain.transfer` | `<fee:transfer>` |
| `domain.update` | `<fee:update>` |
| `domain.restore` | `<fee:update>` — восстановление на проводе это `domain:update` (RFC 3915) |

Сумма должна быть простым десятичным числом: цифры, при желании точка и ещё одна-две цифры.
`'100,00'`, `'$100'` и `'1 000.00'` поднимают `ValidationException` до отправки чего-либо, потому что
альтернатива — голый 2001, который не называет ни одного поля и приходит уже после попытки выполнить
команду:

```python
client.domain.create("example.com.ua", years=1, registrant="C1", fee="100,00")
# ValidationException: fee amount must be a plain decimal like '100.00' (got '100,00')
```

`fee="0"` — законное согласие («эта операция бесплатна»), и оно отправляется как есть.

[Билдеры](builders.md) несут то же самое под именем, которое говорит, что это такое:

```python
(client.domain.create_builder("example.com.ua")
    .years(1)
    .registrant("C1")
    .max_fee("180.00", "UAH")            # предел, на который вы согласны, а не цена, которую вы задаёте
    .send())
```

### Что означает отказ 2004

2004 на изменяющей команде, несущей согласие о плате, означает: **цена реестра выше отправленной вами
суммы, поэтому он не сделал ничего.** Домен не зарегистрирован, продление не произошло, деньги не
двигались. Это безопасный отказ, и правильная реакция — выяснить реальную цену и принять решение, а
не снять предел и отправить снова:

```python
from epptools.exceptions import CommandException

try:
    client.domain.create("example.com.ua", years=1, registrant="C1", fee="100.00")
except CommandException as exc:
    if exc.epp_code != 2004:
        raise
    quote = client.domain.check(["example.com.ua"], fee={"create": 1})
    price = quote.fee_for("example.com.ua", "create", 1)
    if approved_by_operator("example.com.ua", price):
        client.domain.create("example.com.ua", years=1,
                             registrant="C1", fee=price)
```

2004 приходит и тогда, когда период вне диапазона, поэтому читайте сообщение и `exc.reasons()`, а не
считайте, что дело в плате.

Обратите внимание на форму этого сценария: предел задаётся заново из **свежей котировки** и только
после того, как кто-то решил, что новая цена приемлема. Повтор со снятым пределом полностью
обесценивает механизм — это то же самое, что не отправлять согласия вовсе.

## Что изменяющая команда списала на самом деле

Успешная изменяющая команда, нёсшая согласие о плате, отражает списанную сумму. Читайте её и
сохраняйте вместе с объектом и svTRID:

```python
r = client.domain.renew("example.com.ua", "2027-04-01", 1, fee="180.00")

r.fee_amount()      # '180.00'  — что было списано на самом деле
r.fee_currency()    # 'UAH'
r.charged_fee()     # {'currency': 'UAH', 'fee': '180.00'}
r.expiry_date()     # новая дата истечения срока
r.sv_trid()         # идентификатор этой операции в реестре
```

| Метод | Что возвращает | Когда в ответе ничего нет |
|---|---|---|
| `charged_fee() -> Optional[Dict[str, str]]` | `{'currency': …, 'fee': …}` | `None` |
| `fee_amount() -> Optional[str]` | Одну сумму | `None` |
| `fee_currency() -> Optional[str]` | Одну валюту | `None` |

`None` здесь не означает «было бесплатно»: реестр, который не отражает расширение, ответит `None`,
всё равно списав с вас деньги. Период сводится вашей собственной записью о том, сколько команда
должна была стоить, вместе с балансом счёта, — отражённая сумма это подтверждение, а не бухгалтерская
книга.

## По какой цене продлевается домен, который у вас уже есть

`domain:info` может нести собственные ценовые подсказки реестра для конкретно этого домена:

```python
info = client.domain.info("example.com.ua")

info.prices()          # {'renewal': {'value': '180.00', 'currency': 'UAH'}, …}
info.price_channel()   # '7' — из какой строки опубликованного каталога они взяты
```

Это привязано к **домену**, а не к зоне: имя, зарегистрированное годы назад, может сидеть на другом
ценовом канале, чем тот, по которому пойдёт новая регистрация в той же зоне, и `price_channel()` —
непрозрачный идентификатор, который сопоставляет его со строкой каталога. `prices()` равен `{}`,
когда ответ ничего такого не нёс.

## Котировка, предел, регистрация, сверка

```python
from decimal import Decimal

from epptools import Client, Config
from epptools.exceptions import CommandException, InsufficientFundsError

name = "example.com.ua"

client = Client(Config(host="epp.registry.example", clid="EXAMPLE",
                       password="your-secret", ca_file="/etc/ssl/registry-ca.pem"))
client.connect()
client.login()

# 1. Можем ли мы вообще что-то себе позволить?
if Decimal(client.balance().available_credit() or "0") < Decimal("500.00"):
    raise SystemExit("top up before running the batch")

# 2. Доступность и цена за один обмен с сервером.
quote = client.domain.check([name], fee={"create": [1, 2]}, currency="UAH")
if quote.is_available(name) is not True:
    raise SystemExit("%s: %s" % (name, quote.unavailable_reason(name) or "no answer"))

price = quote.fee_for(name, "create", 1)
if price is None:
    raise SystemExit("the registry quoted no create price for %s" % name)

# 3. Регистрируем, соглашаясь ровно на то, что было котировано, и ни на грош больше.
try:
    created = client.domain.create(name, years=1, registrant="C1", fee=price)
except InsufficientFundsError:
    raise SystemExit("out of credit — stop the batch, top up, resume")
except CommandException as exc:
    if exc.epp_code == 2004:
        raise SystemExit("price moved since the quote; re-quote before retrying")
    raise

# 4. Сверяем с тем, что было котировано.
charged = created.fee_amount()
if charged is not None and Decimal(charged) != Decimal(price):
    alert_billing(name, quoted=price, charged=charged, sv_trid=created.sv_trid())

client.logout()
client.disconnect()
```

Ветку с 2004 стоит сохранить: это работающий механизм. Ничего не зарегистрировано и ничего не
списано, а решение о новой цене принимает человек или правило, а не повтор.
