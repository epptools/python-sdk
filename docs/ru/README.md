# EppTools для Python — справочное руководство

**EppTools 1.0.0** · `pip install epptools`

Это руководство написано для разработчика у суб-регистратора, которому нужно регистрировать домены
и вести по ним расчёты в доменном реестре, который говорит на EPP, и который раньше не писал
EPP-клиент.

EppTools — это EPP-клиент. Он открывает TLS-сокет к реестру на порт 700, пишет кадры RFC 5734 и
читает ответы. Словарь здесь всюду собственный словарь протокола — сессия, приветствие, команда,
ответ, код ответа, объект, расширение, очередь poll, — и каждый метод библиотеки соответствует
чему-то, что уходит на провод. Там, где метод отображается на конкретную команду EPP или на
конкретный RFC, страница называет их, чтобы это руководство и собственное руководство реестра для
регистраторов можно было держать открытыми рядом.

Библиотеке нужна только стандартная библиотека Python (`ssl`, `socket`, `xml.etree`), и она работает
на Python 3.8 и новее.

## Поддержка

Вопросы о библиотеке, кадр, который реестр отклонил, ошибка в работе: **https://github.com/epptools/python-sdk/issues**.

Сообщая о проблеме, приложите **svTRID** из ответа (`sv_trid()`) и **clTRID**, который отправил ваш
клиент. Вместе они указывают на конкретную транзакцию в журналах реестра, и именно это делает
обращение таким, на которое можно ответить сразу, без уточняющего круга. Пришлите и сами кадры, если
можете, но сначала вычистите `<pw>`, `<newPW>` и `<authInfo>`: это действующие учётные данные, и
библиотека маскирует их в собственных журналах по той же причине.

Укажите заодно и версию библиотеки — `epptools.__version__`, ту же самую, которую этот клиент
сообщает серверу при входе (`<loginSec:app>` из RFC 8807), чтобы версия в вашем обращении и версия,
которую видел реестр, были одной и той же версией:

```python
import epptools

print(epptools.__version__)          # '1.0.0'
```

Вопросы по учётной записи, счетам и регистрациям адресуйте своему менеджеру в реестре, а не сюда:
этот адрес — про клиентскую библиотеку.
