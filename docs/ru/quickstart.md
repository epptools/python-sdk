# Быстрый старт

Одна законченная программа: подключиться к реестру, войти, задать два вопроса, которые ничего не
стоят, прочитать свой баланс и корректно закрыть сессию. Скопируйте её, подставьте свои учётные
данные, запустите. Разбор после неё объясняет каждую строку.

## Установка

```bash
pip install epptools
```

С привязкой к тегу релиза прямо с GitHub, если вы предпочитаете не зависеть от PyPI:

```bash
pip install "epptools @ git+https://github.com/epptools/python-sdk@v1.1.1"
```

Совсем без пакетов? Скопируйте папку пакета `epptools/` рядом со своим кодом и пишите
`import epptools`. Больше ставить нечего: библиотека использует только стандартную библиотеку Python.

## Что нужно перед началом

| Что | Откуда берётся |
|---|---|
| Хост и порт | Выдаются вместе с учётной записью. `epp.registry.example`, порт **700**. |
| Ваш clID | Ваш идентификатор регистратора, например `EXAMPLE`. |
| Пароль | Выдаётся с учётной записью. Меняется через `<login>`, никогда по почте. |
| Пакет CA реестра | Файл `.pem`. На порту 700 предъявляется сертификат собственного закрытого CA реестра, поэтому он обязателен — см. [Сессия](session.md#tls-и-сертификат). |
| IP-адрес в списке разрешённых | Подключаться можно только с адресов, зарегистрированных для этого clID. |

Отладьте всё на тестовой личности реестра, прежде чем направлять что-либо на боевую.

## Программа целиком

```python
"""Первая программа на EppTools: подключиться, спросить, выйти. Ничего здесь не тарифицируется."""

import logging
import os
from decimal import Decimal

from epptools import Client, Config
from epptools.exceptions import CommandException, EppException

logging.basicConfig(level=logging.INFO)

config = Config(
    host="epp.registry.example",
    clid="EXAMPLE",
    password="your-secret",
    port=700,                 # значение по умолчанию; меняйте, только если точка подключения переехала
    lang="en",                # сообщения о результате: en | uk | ua | ru
    ca_file=os.environ.get("EPP_CA", "/path/to/registry-ca.pem"),
)

client = Client(config, logger=logging.getLogger("epp"))

try:
    greeting = client.connect()
    print("server:", greeting.value("svID"))

    login = client.login()
    for event in login.security_events():
        print("session %s (%s): %s" % (event["level"], event["type"], event["text"]))

    name = "example.com.ua"
    check = client.domain.check([name], fee={"create": 1})
    available = check.is_available(name)
    if available is None:
        print("the registry said nothing about", name)
    elif available:
        print("%s is free; a create would cost %s %s" % (
            name, check.fee_for(name, "create", 1), check.fees().get("_currency")))
    else:
        print("%s is taken: %s" % (name, check.unavailable_reason(name)))

    info = client.domain.info(name)
    print("expires:", info.expiry_date())
    print("nameservers:", info.nameservers())
    print("svTRID:", info.sv_trid())

    money = client.balance()
    print("available credit:", Decimal(money.available_credit() or "0"))

    client.logout()
except CommandException as exc:
    print("the registry refused: EPP %d — %s" % (exc.epp_code, exc))
except EppException as exc:
    print("client-side failure:", exc)
finally:
    client.disconnect()
```

Ожидаемый вывод для имени, которым уже владеет кто-то другой:

```
server: Registry EPP Server
example.com.ua is taken: In use
the registry refused: EPP 2201 — EPP 2201: Authorization error
```

Третья строка — это правильно работающая программа: `domain.info` по домену, который вам не
принадлежит, отклоняется, исключение несёт код, а `finally` всё равно закрывает сокет. Направьте её
на имя, которым владеете вы, и вместо неё напечатаются две строки от `info`.

## Построчно

**1 — Импорты.** `Client` и `Config` — это вся точка входа; оба экспортируются из корня пакета.
Исключения живут в `epptools.exceptions`. `CommandException` — это то, как выглядит отказ реестра
выполнить команду; `EppException` — его базовый класс, он ловит всё, что бросает библиотека, так что
два `except` вместе не оставляют ничего необработанным. См. [Ошибки](errors.md).

**2 — `logging.basicConfig`.** Необязательно и полезно с самого первого запуска. Логгер, который вы
передаёте клиенту, печатает по строке на команду — с кодом ответа и обоими идентификаторами
транзакций, — а на уровне `DEBUG` ещё и кадр целиком. Пароли и `authInfo` маскируются до того, как
хоть что-нибудь будет записано, — см. [Сессия → Журналирование](session.md#журналирование).

**3 — `Config(...)`.** Неизменяемые настройки подключения. `host`, `clid` и `password` обязательны и
не имеют значений по умолчанию; у всего остального они есть. `port=700` и так значение по умолчанию,
здесь оно выписано только ради явности. `lang` задаёт язык всех сообщений о результате, которые
сервер пришлёт в этой сессии. `ca_file` — то самое поле, на котором спотыкаются при первом запуске:
точка подключения предъявляет сертификат закрытого CA, в системном хранилище доверия этого CA нет, и
без пакета рукопожатие не проходит проверку. Каждое поле описано в
[Сессия → Config](session.md#config-поле-за-полем).

**4 — `Client(config, logger=...)`.** Создание клиента ничего не открывает. Его можно безопасно
построить на этапе импорта и подключиться позже.

**5 — `client.connect()`.** Открывает TLS-сокет и читает незапрошенное `<greeting>` сервера,
возвращая его как `Response`. Приветствие перечисляет пространства имён объектов и расширений,
которые обслуживает эта точка подключения; следующий за ним вход объявляет ровно их, поэтому вашей
сессии никогда не откажут за просьбу об услуге, которой сервер не предоставляет.
`greeting.value("svID")` достаёт из него один элемент по локальному имени.

**6 — `client.login()`.** Отправляет `<login>` с вашим clID и паролем (RFC 5730). Возвращает
`Response` этого входа; всё, кроме 1000, бросает исключение — `AuthenticationException` для 2200 и
более точный класс для остального: 2502 — это лимит сессий, а не неверный пароль, и лечатся эти два
случая противоположными действиями.

**7 — `login.security_events()`.** RFC 8807. Сервер возвращает то, что он хочет видеть исправленным
в этой сессии: клиентский сертификат, до истечения которого остались недели, устаревшую версию TLS,
слабый набор шифров. На здоровой сессии список пуст, поэтому любую запись в нём считайте поводом
действовать. Альтернатива тому, чтобы узнать об истекающем сертификате здесь, — узнать о нём утром,
когда он перестанет работать. См. [Сессия → Безопасность входа](session.md#безопасность-входа-rfc-8807).

**8 — `client.domain.check([name], fee={"create": 1})`.** Одна команда `<check>` (RFC 5731), несущая
расширение цен RFC 8748, так что доступность и цена приходят за один круг. `check` ничего не меняет и
ничего не стоит, что и делает его безопасной первой командой на боевой учётной записи.

**9 — `check.is_available(name)`.** Намеренно трёхзначный: `True`, `False` или `None`, когда ответ
ничего об этом имени не сказал. `None` — это не «занято», и строка, которая следом регистрирует имя,
не должна считать его таковым.

**10 — `check.fee_for(name, "create", 1)`.** Названная цена одной операции на один период —
собственной точной десятичной строкой реестра, никогда не числом с плавающей точкой, потому что
`0.1 + 0.2` в двоичной плавающей точке не равно `0.3`, и просуммированные так деньги уплывают.
`check.fees()` возвращает всю таблицу по именам вместе с ключом `_currency`. Цены в этом руководстве
иллюстративные. См. [Баланс](balance.md).

**11 — `client.domain.info(name)`.** `<info>` по одному домену. `expiry_date()` отдаёт дату окончания
ровно так, как её записал реестр (`2027-04-01T09:15:00Z`), строкой, а не `datetime`: какой
календарный день получит продление, решает реестр, а переформатирование через местный часовой пояс —
это то, из-за чего клиент в итоге продлевает по вчерашней дате. `nameservers()` возвращает имена
независимо от того, какой из двух моделей EPP пользуется реестр, чтобы их выразить.

**12 — `info.sv_trid()`.** Собственный идентификатор этой операции у реестра. Сохраняйте его рядом с
объектом, которого касалась команда. Это значение, по которому поддержка находит операцию; ваш clTRID
не значит ничего ни для кого, кроме вас.

**13 — `client.balance()`.** Собственный запрос баланса у реестра. `available_credit()` — это то, что
вы действительно можете потратить: баланс плюс остаток кредита, точной десятичной строкой, поэтому
она и проходит через `Decimal`, а не через `float`. См. [Баланс](balance.md).

**14 — `client.logout()`.** Вежливо завершает сессию; сервер отвечает 1500 и закрывает связь. Если
его пропустить, сессия будет занимать один из ваших слотов одновременных сессий, пока сервер не
закроет её по тайм-ауту, а следующему соединению могут отказать кодом 2502 из-за слота, которым вы
уже не пользуетесь.

**15 — `except CommandException`.** Реестр ответил кодом ошибки. `exc.epp_code` — это сам код, а
`exc.response` — полный разобранный ответ. Ловите более узкие подклассы там, где дальше нужно
поступать по-разному: `InsufficientFundsError` должен останавливать пакет, а не пропускать одно имя.

**16 — `finally: client.disconnect()`.** Закрывает сокет, что бы ни случилось. `Client` — ещё и
контекстный менеджер (`with Client(config) as client:`), который отключается на выходе; он не
подключается, не входит и не отправляет `<logout>` за вас, поэтому вызов `logout()` держите внутри
блока.
