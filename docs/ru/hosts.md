# Хосты

Всё, что находится под `client.host`. Объекты хостов — серверов имён — следуют **RFC 5732**, и каждый
метод здесь соответствует одной команде EPP на проводе.

Объект хоста существует для того, чтобы домены могли ссылаться на него по имени. Там, где реестр
использует модель объектов хостов, сервер имён обязан существовать как объект, прежде чем
[`domain.create`](domains.md#серверы-имён-обе-модели) или `domain.update` сможет сослаться на него
через `<domain:hostObj>`. Там, где реестр принимает встроенный glue, эта страница может вам вовсе не
понадобиться — адреса едут вместе с доменной командой.

Каждый метод возвращает [`Response`](responses.md), а код ответа 2000 и выше поднимается как
исключение — см. [Ошибки](errors.md).

## Подчинённые и внешние хосты

Различие определяет, что реестр примет, поэтому разобраться в нём стоит до первого `create`:

| | Живёт | Glue-адреса |
|---|---|---|
| **Подчинённый** | под доменом в зоне, которую обслуживает реестр, например `ns1.example.com.ua` | **обязательны** — создание без адреса это 2003 |
| **Внешний** | под доменом, которого у реестра нет, например `ns1.provider.net` | **отклоняются** — его адреса живут в его собственном реестре, поэтому отправка любого из них это 2306 |

Адреса должны быть публичными адресами Интернета, и хост несёт не более 13 из них; четырнадцатый это
2001.

Клиент, который всегда отправляет адрес, обязан перестать это делать для внешних хостов. Адрес не
игнорируется — он приводит к отказу.

## Методы

| Метод | Команда EPP |
|---|---|
| `check` | `<check><host:check>` |
| `info` | `<info><host:info>` |
| `create` | `<create><host:create>` |
| `update` | `<update><host:update>` |
| `delete` | `<delete><host:delete>` (при желании с собственным расширением реестра для принудительного удаления) |

`update_builder(name)` собирает update шаг за шагом; см. [Билдеры](builders.md).

## check

```python
client.host.check(names: List[str]) -> Response
```

По одному `<host:name>` на имя, **не более 10 в одной команде** — одиннадцатое отклоняется с кодом
2001.

```python
r = client.host.check(["ns1.example.com.ua", "ns2.example.com.ua"])

r.availability()                          # {'ns1.example.com.ua': False, 'ns2.example.com.ua': True}
r.is_available("ns2.example.com.ua")      # True
r.unavailable_reason("ns1.example.com.ua")# 'in use' либо None
```

`is_available()` возвращает `None`, когда ответ ничего не сказал об этом имени, а это не то же самое,
что «занято».

| Код | Значение |
|---|---|
| 1000 | ответ получен; читайте `availability()` |
| 2001 | больше 10 имён в одной команде |

## info

```python
client.host.info(name: str) -> Response
```

Читает объект хоста. Аргумента `auth_info` здесь нет: RFC 5732 не даёт хосту собственного кода
авторизации, потому что хост авторизуется через домен, под которым живёт.

```python
h = client.host.info("ns1.example.com.ua")

h.object_name()      # 'ns1.example.com.ua'
h.roid()             # собственный идентификатор объекта в реестре
h.statuses()         # ['linked'], когда хост использует домен, иначе ['ok']
h.host_addresses()   # [{'ip': '203.0.113.10', 'version': 'v4'},
                     #  {'ip': '2001:db8::10',  'version': 'v6'}]
h.sponsor()          # clID
h.created_by()       # crID           h.created_date()   # crDate
h.updated_by()       # upID или None  h.updated_date()   # upDate или None
```

**Внешний хост не возвращает адресов**, и это правильный ответ, а не пропущенный: glue несёт только
хост внутри обслуживаемой зоны.

Статус `linked` означает, что как минимум один домен использует этот хост сервером имён. Именно этот
статус блокирует [`delete`](#delete).

| Код | Значение |
|---|---|
| 1000 | ответ получен |
| 2303 | такого хоста нет |

## create

```python
client.host.create(name: str, addresses: Optional[List[str]] = None) -> Response
```

Создаёт объект хоста. Не тарифицируется.

```python
# Подчинённый хост: glue обязателен.
client.host.create("ns1.example.com.ua", ["203.0.113.10", "2001:db8::10"])

# Внешний хост: никаких адресов вовсе.
client.host.create("ns1.provider.net")
```

IPv4 и IPv6 различаются по самому написанию адреса, поэтому каждый уходит с правильным атрибутом
`ip="v4"` или `ip="v6"` без ваших указаний. Адрес, который клиент не может разобрать ни как тот, ни
как другой, отправляется помеченным `v4` и отклоняется реестром с кодом 2005 — значение и так было
неверным, а отказ его называет.

Прочитать ответ стоит даже здесь, потому что он подтверждает, какое имя записал реестр:

```python
r = client.host.create("ns1.example.com.ua", ["203.0.113.10"])
r.object_name()     # 'ns1.example.com.ua'
r.created_date()    # crDate
```

| Код | Значение |
|---|---|
| 1000 | создан |
| 2001 | больше 13 адресов |
| 2003 | подчинённый хост без адреса |
| 2005 | неверно сформированный адрес или имя |
| 2302 | такой хост уже существует |
| 2306 | адреса у внешнего хоста либо другое правило реестра |

## update

```python
client.host.update(name: str, *,
                   add_addresses: Optional[List[str]] = None,
                   rem_addresses: Optional[List[str]] = None,
                   add_statuses: Optional[List[str]] = None,
                   rem_statuses: Optional[List[str]] = None,
                   new_name: Optional[str] = None) -> Response
```

Update — это **дельта**: адреса и статусы, которых вы не упомянули, остаются нетронутыми. `add_*` и
`rem_*` строят между собой по одному блоку `<host:add>` и `<host:rem>`, причём блок строится, только
если вы что-то в него положили.

```python
# Перевести сервер имён на новый адрес без разрыва: сначала добавить новый, затем снять старый.
client.host.update("ns1.example.com.ua",
                   add_addresses=["203.0.113.11", "2001:db8::11"],
                   rem_addresses=["203.0.113.10"])

# Закрыть объект от изменений.
client.host.update("ns1.example.com.ua", add_statuses=["clientUpdateProhibited"])
```

Клиент может устанавливать статусы `clientDeleteProhibited` и `clientUpdateProhibited`; парные
`server*` принадлежат реестру.

Правила из [create](#create) действуют и в update: внешний хост не может получить адреса (2306), а
подчинённый не может остаться ни с одним (2003). Удаление последнего адреса хоста — это изменение,
которое будет отклонено, а не то, которое тихо снимет делегирование.

### Переименования не существует

**Хост переименовать нельзя.** Реестр читает только `<host:add>` и `<host:rem>`; блок `<host:chg>` с
новым именем не применяется. Кадр, который просит и смену адреса, и переименование, применил бы смену
адреса, отбросил бы переименование — и всё равно ответил бы 1000, а на таком «успехе» можно строить
работу неделями, прежде чем заметить, что имя никуда не переехало.

Поэтому `new_name` существует только для того, чтобы отказать:

```python
client.host.update("ns1.example.com.ua", new_name="ns9.example.com.ua")
# ValidationException: host rename is not supported by this registry (host:chg is ignored) —
# create the new host, re-point the domains with domain:update, then delete the old one
```

Ничего не отправляется. Ответ приходит из вашего же кода, где он может сказать, что делать вместо
этого, — а вместо этого нужны три команды:

```python
old, new = "ns1.example.com.ua", "ns9.example.com.ua"

# 1. Создать замену с тем же glue.
addresses = [a["ip"] for a in client.host.info(old).host_addresses()]
client.host.create(new, addresses)

# 2. Перевести на неё каждый домен, который использует старый хост. Команды «какие домены
#    используют этот хост» не существует, поэтому список берётся из ваших собственных записей.
for domain in domains_using(old):
    client.domain.update(domain, add={"ns": [new]}, rem={"ns": [old]})

# 3. Только теперь удалить старый хост — пока на него ссылается домен, удаление это 2305.
client.host.delete(old)
```

Добавляйте до того, как удалять, именно в таком порядке и одной командой на домен: домен, оставшийся
в промежутке без серверов имён, перестаёт разрешаться, а `<host:add>` и `<host:rem>` в одном
`domain:update` применяются как одно изменение.

| Код | Значение |
|---|---|
| 1000 | применено |
| 2001 | больше 13 адресов |
| 2003 | подчинённый хост остался бы без адреса |
| 2303 | такого хоста нет |
| 2304 | статус запрещает |
| 2306 | адреса у внешнего хоста либо статус, который клиент устанавливать не может |

## delete

```python
client.host.delete(name: str, force: bool = False) -> Response
```

```python
client.host.delete("ns1.example.com.ua")
```

**Хост, который всё ещё используется каким-либо доменом как сервер имён, удалить нельзя** — реестр
отвечает 2305, а `info()` показывает статус `linked`. Сначала отвяжите его от этих доменов через
[`domain.update`](domains.md#update).

### Принудительное удаление

`force=True` добавляет собственное расширение реестра `<registry:delete><registry:deleteNS confirm="yes"/>`,
которое убирает хост из набора серверов имён **каждого домена, который на него ссылался**, и затем
удаляет его — одной командой:

```python
client.host.delete("ns1.example.com.ua", force=True)
```

Это удобство, цену которого стоит назвать прямо: оно меняет делегирование доменов, которые вы в
команде не называли. Домен, у которого осталось меньше серверов имён, чем требует минимум зоны,
перестаёт быть делегированным, и реестр не переспрашивает — `confirm="yes"` и есть подтверждение.
Пользуйтесь этим, чтобы вывести из работы сервер имён, который вы уже везде заменили, и после этого
прочитайте [`domain.info`](domains.md#info) по затронутым доменам, чтобы убедиться, с чем они
остались.

Принудительное удаление, которому не удалось завершить отвязку, отвечает 2400.

| Код | Значение |
|---|---|
| 1000 | удалён |
| 2303 | такого хоста нет |
| 2304 | статус запрещает (`clientDeleteProhibited`) |
| 2305 | всё ещё используется доменом как сервер имён (при обычном удалении) |
| 2400 | принудительная отвязка не завершилась — может быть временным; `is_retryable()` истинно |
