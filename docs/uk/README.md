# EppTools для Python — довідковий посібник

**EppTools 1.0.0** · `pip install epptools`

Цей посібник призначено для розробника в субреєстратора, якому треба реєструвати домени та
виставляти за них рахунки в доменному реєстрі, який говорить EPP, і який ще не писав EPP-клієнта.

EppTools — це EPP-клієнт. Він відкриває TLS-сокет до реєстру на порт 700, пише кадри за RFC 5734
і читає відповіді. Словник усюди — власний словник протоколу: сесія, привітання, команда,
відповідь, код відповіді, об'єкт, розширення, черга poll — і кожен метод бібліотеки відповідає
чомусь, що йде в канал передачі. Там, де метод відповідає конкретній команді EPP або конкретному
RFC, сторінка це називає, тож ви можете тримати цей посібник і власний посібник реєстратора від
реєстру відкритими поруч.

Бібліотеці потрібна лише стандартна бібліотека Python (`ssl`, `socket`, `xml.etree`), і працює
вона на Python 3.8 та новіших.

## Підтримка

Питання про бібліотеку, про кадр, який реєстр відхилив, або про помилку:
**https://github.com/epptools/python-sdk/issues**.

Коли повідомляєте про проблему, наведіть **svTRID** із відповіді (`sv_trid()`) і **clTRID**, який
надіслав ваш клієнт. Разом вони ідентифікують саме цю транзакцію в журналах реєстру, а це те, що
робить звернення таким, на яке можна відповісти без зайвого кола листування. Надішліть і кадри,
якщо можете, але спершу вилучіть із них `<pw>`, `<newPW>` та `<authInfo>`: це живі облікові дані, і
бібліотека приховує їх у власних журналах із тієї самої причини.

Наведіть також версію бібліотеки — `epptools.__version__`, ту саму версію, яку цей клієнт повідомляє
серверу під час входу (RFC 8807 `<loginSec:app>`), щоб версія у вашому зверненні і версія, яку бачив
реєстр, були однією версією:

```python
import epptools

print(epptools.__version__)          # '1.0.0'
```

Питання про обліковий запис, рахунки та реєстрацію йдуть до вашого менеджера в реєстрі, а не сюди —
ця адреса стосується клієнтської бібліотеки.
