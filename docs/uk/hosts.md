# Хости

Усе під `client.host`. Об'єкти хостів — серверів імен — відповідають **RFC 5732**, і кожен метод тут
відповідає рівно одній команді EPP у каналі передачі.

Об'єкт хоста існує для того, щоб домени могли вказувати на нього за іменем. Там, де реєстр
використовує модель об'єктів хостів, сервер імен має існувати як об'єкт, перш ніж
[`domain.create`](domains.md#nameservers-в-обох-моделях) чи `domain.update` зможуть послатися на
нього через `<domain:hostObj>`. Там, де реєстр натомість приймає вбудовані glue-адреси, ця сторінка
може вам ніколи й не знадобитися — адреси подорожують разом з доменною командою.

Кожен метод повертає [`Response`](responses.md), а код відповіді 2000 або вищий викидається як
виняток — див. [Помилки](errors.md).

## Підпорядковані та зовнішні хости

Ця різниця вирішує, що реєстр прийме, тож її варто з'ясувати ще до першого `create`:

| | Живе | Glue-адреси |
|---|---|---|
| **Підпорядкований** | під доменом у зоні, яку обслуговує реєстр, напр. `ns1.example.com.ua` | **обов'язкові** — create без них це 2003 |
| **Зовнішній** | під доменом, якого реєстр не тримає, напр. `ns1.provider.net` | **відхиляються** — його адреси живуть у власному реєстрі, тож надсилання будь-яких це 2306 |

Адреси мають бути публічними інтернет-адресами, і хост несе щонайбільше 13 з них; чотирнадцята
це 2001.

Отже, клієнт, який завжди надсилає адресу, має припинити це робити для зовнішніх хостів. Її не
ігнорують — її відхиляють.

## Методи

| Метод | Команда EPP |
|---|---|
| `check` | `<check><host:check>` |
| `info` | `<info><host:info>` |
| `create` | `<create><host:create>` |
| `update` | `<update><host:update>` |
| `delete` | `<delete><host:delete>` (за бажанням з розширенням примусового видалення від реєстру) |

`update_builder(name)` збирає update крок за кроком; див. [Білдери](builders.md).

## check

```python
client.host.check(names: List[str]) -> Response
```

По одному `<host:name>` на ім'я, **щонайбільше 10 на команду** — одинадцяте відхиляється з 2001.

```python
r = client.host.check(["ns1.example.com.ua", "ns2.example.com.ua"])

r.availability()                          # {'ns1.example.com.ua': False, 'ns2.example.com.ua': True}
r.is_available("ns2.example.com.ua")      # True
r.unavailable_reason("ns1.example.com.ua")# 'in use', або None
```

`is_available()` повертає `None`, коли відповідь нічого не сказала про це ім'я, а це не те саме, що
«зайняте».

| Код | Значення |
|---|---|
| 1000 | відповідь отримано; читайте `availability()` |
| 2001 | понад 10 імен в одній команді |

## info

```python
client.host.info(name: str) -> Response
```

Читає об'єкт хоста. Аргумента `auth_info` тут немає: RFC 5732 не дає хосту власного коду
авторизації, бо хост авторизується через домен, під яким він живе.

```python
h = client.host.info("ns1.example.com.ua")

h.object_name()      # 'ns1.example.com.ua'
h.roid()             # власний ідентифікатор об'єкта в реєстрі
h.statuses()         # ['linked'], щойно його використовує домен, інакше ['ok']
h.host_addresses()   # [{'ip': '203.0.113.10', 'version': 'v4'},
                     #  {'ip': '2001:db8::10',  'version': 'v6'}]
h.sponsor()          # clID
h.created_by()       # crID           h.created_date()   # crDate
h.updated_by()       # upID, або None  h.updated_date()   # upDate, або None
```

**Зовнішній хост не повертає адрес**, і це правильна відповідь, а не відсутня — лише хост усередині
обслуговуваної зони несе glue-адреси.

Статус `linked` означає, що принаймні один домен використовує цей хост як сервер імен. Саме цей
статус блокує [`delete`](#delete).

| Код | Значення |
|---|---|
| 1000 | відповідь отримано |
| 2303 | такого хоста немає |

## create

```python
client.host.create(name: str, addresses: Optional[List[str]] = None) -> Response
```

Створює об'єкт хоста. Не платна.

```python
# Підпорядкований хост: glue-адреси обов'язкові.
client.host.create("ns1.example.com.ua", ["203.0.113.10", "2001:db8::10"])

# Зовнішній хост: жодних адрес.
client.host.create("ns1.provider.net")
```

IPv4 та IPv6 розрізняються за самим записом адреси, тож кожна вирушає з правильним атрибутом
`ip="v4"` чи `ip="v6"` без ваших вказівок. Адресу, яку клієнт не може розібрати як жодну з них,
буде надіслано з позначкою `v4` і відхилено реєстром з 2005 — значення й так було хибним, а відмова
його називає.

Читати відповідь варто навіть тут, бо вона підтверджує, яке ім'я записав реєстр:

```python
r = client.host.create("ns1.example.com.ua", ["203.0.113.10"])
r.object_name()     # 'ns1.example.com.ua'
r.created_date()    # crDate
```

| Код | Значення |
|---|---|
| 1000 | створено |
| 2001 | понад 13 адрес |
| 2003 | підпорядкований хост без адреси |
| 2005 | некоректна адреса або ім'я |
| 2302 | такий хост уже існує |
| 2306 | адреси на зовнішньому хості або інше правило реєстру |

## update

```python
client.host.update(name: str, *,
                   add_addresses: Optional[List[str]] = None,
                   rem_addresses: Optional[List[str]] = None,
                   add_statuses: Optional[List[str]] = None,
                   rem_statuses: Optional[List[str]] = None,
                   new_name: Optional[str] = None) -> Response
```

Update — це **дельта**: адреси й статуси, яких ви не згадали, лишаються недоторканими. `add_*` та
`rem_*` разом будують один блок `<host:add>` і один `<host:rem>`, і блок будується лише тоді, коли
ви йому щось дали.

```python
# Перевести сервер імен на нову адресу без розриву: додати нову, потім прибрати стару.
client.host.update("ns1.example.com.ua",
                   add_addresses=["203.0.113.11", "2001:db8::11"],
                   rem_addresses=["203.0.113.10"])

# Заморозити об'єкт від змін.
client.host.update("ns1.example.com.ua", add_statuses=["clientUpdateProhibited"])
```

Статуси, які може встановлювати клієнт, — це `clientDeleteProhibited` та `clientUpdateProhibited`;
відповідники `server*` належать реєстру.

Правила з [create](#create) діють і в update: зовнішній хост не може отримати адреси (2306), а
підпорядкований не може лишитися без жодної (2003). Тож прибирання останньої адреси хоста — це
зміна, яку буде відхилено, а не така, що тихо скасує делегування.

### Перейменування не існує

**Хост неможливо перейменувати.** Реєстр читає лише `<host:add>` та `<host:rem>`; блок
`<host:chg>` з новим іменем не застосовується. Кадр, який просить і зміну адреси, і перейменування,
застосував би зміну адреси, відкинув перейменування — і все одно відповів би 1000: успіх, на
підставі якого можна діяти тижнями, перш ніж помітити, що ім'я нікуди не поділося.

Тож `new_name` існує лише для того, щоб відмовити:

```python
client.host.update("ns1.example.com.ua", new_name="ns9.example.com.ua")
# ValidationException: host rename is not supported by this registry (host:chg is ignored) —
# create the new host, re-point the domains with domain:update, then delete the old one
```

Нічого не надсилається. Відповідь приходить з вашого власного коду, де вона може сказати, що робити
натомість, — а робити натомість треба три команди:

```python
old, new = "ns1.example.com.ua", "ns9.example.com.ua"

# 1. Створити заміну з тими самими glue-адресами.
addresses = [a["ip"] for a in client.host.info(old).host_addresses()]
client.host.create(new, addresses)

# 2. Переспрямувати кожен домен, що використовує старий. Команди «які домени використовують
#    цей хост» не існує, тож цей список береться з ваших власних записів.
for domain in domains_using(old):
    client.domain.update(domain, add={"ns": [new]}, rem={"ns": [old]})

# 3. Лише тепер видаляти старий хост — поки на нього посилається домен, delete дає 2305.
client.host.delete(old)
```

Додавайте перед тим, як прибирати, саме в такому порядку і однією командою на домен: домен, що
лишився в проміжку без серверів імен, перестає розв'язуватися, а `<host:add>` і `<host:rem>` в
одному `domain:update` застосовуються як одна зміна.

| Код | Значення |
|---|---|
| 1000 | застосовано |
| 2001 | понад 13 адрес |
| 2003 | підпорядкований хост лишився б без адреси |
| 2303 | такого хоста немає |
| 2304 | статус це забороняє |
| 2306 | адреси на зовнішньому хості або статус не з тих, що встановлює клієнт |

## delete

```python
client.host.delete(name: str, force: bool = False) -> Response
```

```python
client.host.delete("ns1.example.com.ua")
```

**Хост, який усе ще є сервером імен для будь-якого домену, видалити неможливо** — реєстр відповідає
2305, а `info()` показує статус `linked`. Спершу відкріпіть його від цих доменів через
[`domain.update`](domains.md#update).

### Примусове видалення

`force=True` додає власне розширення реєстру `<registry:delete><registry:deleteNS confirm="yes"/>`, яке
прибирає хост із набору серверів імен **кожного домену, що на нього посилався**, а потім видаляє
його — однією командою:

```python
client.host.delete("ns1.example.com.ua", force=True)
```

Це зручність із ціною, яку варто назвати прямо: вона змінює делегування доменів, яких ви в команді
не називали. Домен, що лишився з меншою кількістю серверів імен, ніж мінімум зони, перестає бути
делегованим, і реєстр не перепитує — `confirm="yes"` і є підтвердженням. Використовуйте це, щоб
вивести з обігу сервер імен, який ви вже скрізь замінили, а потім прочитайте
[`domain.info`](domains.md#info) для зачеплених доменів, щоб підтвердити, з чим вони лишилися.

Примусове видалення, яке не змогло завершити відкріплення, відповідає 2400.

| Код | Значення |
|---|---|
| 1000 | видалено |
| 2303 | такого хоста немає |
| 2304 | статус це забороняє (`clientDeleteProhibited`) |
| 2305 | досі використовується доменом як сервер імен (звичайне видалення) |
| 2400 | примусове відкріплення не змогло завершитися — може бути тимчасовим; `is_retryable()` дає true |
