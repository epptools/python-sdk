# Відповіді

Кожна команда повертає `Response`. Він загортає відповідь, яку надіслав реєстр, і відповідає на
запитання про неї, тож прочитати відповідь ніколи не означає лізти в dict за рядком, який довелося
вгадати, і ніколи не означає ходити по XML.

Пошук елементів не зважає на простори імен — він збігається за локальним іменем елемента, — тож
зміна префіксів, які використовує відповідь, ніколи не ламає метод доступу.

Наскрізно діють дві домовленості:

- Метод доступу, якому нема чого повідомити, повертає `None`, порожній список або порожній dict. Він
  не підіймає виняток. Що саме з трьох для кожного методу — у таблицях нижче.
- **`None` означає «відповідь про це нічого не сказала»**, а це не те саме, що заперечення. Найбільше
  ця різниця важить для `is_available()`, і рядок, який реєструє домен, не має ставитися до цих двох
  однаково.

## Дати та гроші

- **Дати повертаються власним рядком реєстру** — `2027-04-01T09:15:00Z` або зі зсувом, — ніколи не
  `datetime`. Саме реєстр вирішує, на який календарний день припадає продовження, а переформатування
  через локальний часовий пояс — це те, як клієнт починає показувати попередній день і продовжувати
  з розрахунку на нього.
- **Гроші повертаються точним десятковим рядком**, ніколи не `float`. `0.1 + 0.2` у двійковій
  рухомій комі не дорівнює `0.3`, і баланс, підсумований так, розповзається. Для арифметики беріть
  `decimal.Decimal`, а для зберігання лишайте рядок.

## Результат та ідентифікатори транзакцій

| Метод доступу | Повертає | Коли відповідь нічого не несе |
|---|---|---|
| `code() -> int` | Код відповіді EPP: 1000, 1001, 2303 … | `0` для привітання або будь-якого кадру без `<result>` |
| `message() -> Optional[str]` | Зрозумілий людині `<result><msg>` | `None` |
| `message_lang() -> Optional[str]` | Мова цього повідомлення: `en`, `uk`, `ua`, `ru` | `None` |
| `is_success() -> bool` | `True` для будь-якого коду 1xxx | `False` |
| `is_pending() -> bool` | `True` лише для 1001 — прийнято, завершується офлайн | `False` |
| `is_greeting() -> bool` | `True`, коли цей кадр є `<greeting>` | `False` |
| `cl_trid() -> Optional[str]` | Повернений назад клієнтський ідентифікатор транзакції | `None` |
| `sv_trid() -> Optional[str]` | Власний ідентифікатор операції в реєстрі | `None` |

Зберігайте `sv_trid()` поруч з об'єктом, якого стосувалася команда. Саме за ним підтримка знаходить
операцію. `message()` — це банер результату: у відповіді на poll це щоразу те саме стале речення, а
текст сповіщення — це `queue_message()`.

## Ідентичність об'єкта — для будь-якого об'єкта

Ці методи відповідають однаково для домену, хоста чи контакту.

| Метод доступу | Повертає | Коли відповідь нічого не несе |
|---|---|---|
| `object_name() -> Optional[str]` | Об'єкт, якого стосується ця відповідь: доменне ім'я, ім'я хоста або **ідентифікатор** контакту | `None` |
| `roid() -> Optional[str]` | Власний ідентифікатор об'єкта в реєстрі | `None` |
| `sponsor() -> Optional[str]` | `clID` — реєстратор, якому об'єкт належить зараз | `None` |
| `created_by() -> Optional[str]` | `crID` — реєстратор, який його створив | `None` |
| `created_date() -> Optional[str]` | `crDate`, як його записав реєстр | `None` |
| `updated_by() -> Optional[str]` | `upID` — хто змінив його востаннє | `None`, коли його ніколи не змінювали або коли ви не є його власником |
| `updated_date() -> Optional[str]` | `upDate` | `None`, коли ніколи не змінювали |
| `transfer_date() -> Optional[str]` | `trDate` — коли він востаннє змінив власника | `None`, коли не змінював жодного разу |
| `auth_info() -> Optional[str]` | Трансферний код із `<authInfo><pw>` | `None`, коли реєстр його не віддав |
| `statuses() -> List[str]` | Значення статусів: `["ok"]`, `["clientHold", "pendingTransfer"]` … | `[]` |

`object_name()` береться із самого блоку об'єкта, тож на `contact:info` він дає ідентифікатор
контакту, а не особисте ім'я реєстранта. Це також те, як ви читаєте ідентифікатор, згенерований
реєстром для контакту з `create_auto()`, — та відповідь є єдиним місцем, де він з'являється.

`auth_info()` — це код, який дозволяє **будь-якому** реєстратору забрати у вас домен. Ніколи не
записуйте його в журнал, ніколи не вкладайте у звернення до підтримки і змінюйте його після того, як
передали клієнту.

`updated_by()` варто звіряти з власними записами: зміна, якої ви не робили, означає, що вона прийшла
з боку реєстру або від дії підтримки, а не з вашої системи.

## Домен

| Метод доступу | Повертає | Коли відповідь нічого не несе |
|---|---|---|
| `expiry_date() -> Optional[str]` | `exDate`, рівно так, як його записав реєстр | `None` |
| `registrant() -> Optional[str]` | Ідентифікатор реєстранта | `None` |
| `contacts() -> Dict[str, List[str]]` | Контакти за ролями: `{"admin": ["c-1"], "tech": ["c-1", "c-2"]}`. Реєстранта тут **немає** | `{}` |
| `contacts_for(role: str) -> List[str]` | Ідентифікатори в одній ролі, збіг без урахування регістру | `[]`, коли цієї ролі ніхто не тримає — цілком законна відповідь |
| `admin_contacts() -> List[str]` | Адміністративні контакти | `[]` |
| `tech_contacts() -> List[str]` | Технічні контакти | `[]` |
| `billing_contacts() -> List[str]` | Білінгові контакти | `[]` |
| `all_contacts() -> List[str]` | Кожен ідентифікатор, прикріплений у будь-якій якості, включно з реєстрантом, без дублікатів | `[]` |
| `nameservers() -> List[str]` | Імена серверів імен, у нижньому регістрі, якою б моделлю EPP реєстр не скористався | `[]` |
| `nameserver_addresses() -> Dict[str, List[Dict[str, str]]]` | Вбудовані glue-адреси за іменем сервера імен: `{"ns1.example.com.ua": [{"ip": "192.0.2.1", "version": "v4"}]}` | `{}` |
| `subordinate_hosts() -> List[str]` | Об'єкти хостів, що живуть **під** цим доменом, у нижньому регістрі | `[]` |
| `rgp_status() -> List[str]` | Значення статусу RGP, напр. `["redemptionPeriod"]` (RFC 3915) | `[]` |
| `license() -> Optional[str]` | Номер торгової марки або ліцензії з власного розширення реєстру | `None` |
| `prices() -> Dict[str, Dict[str, str]]` | Підказки про ціну продовження та відновлення з `domain:info`, за операціями: `{"renewal": {"value": "…", "currency": "UAH"}}` | `{}` |
| `price_channel() -> Optional[str]` | Непрозорий ідентифікатор, що називає рядок опублікованого реєстром каталогу цін, з якого взято ці ціни | `None` |
| `registrar_of_record() -> Optional[str]` | Ідентифікатор, який WHOIS і RDAP реєстру публікують як реєстратора | `None` |
| `transfer() -> Optional[Dict[str, str]]` | Трансфер повністю — див. нижче | `None`, коли відповідь не несе `trnData` |
| `transfer_status() -> Optional[str]` | Лише статус: `"pending"`, `"serverApproved"`, `"clientRejected"` … | `None` |
| `ds_records() -> List[Dict[str, object]]` | DS-записи DNSSEC: `[{"keyTag": …, "alg": …, "digestType": …, "digest": "…"}]` (RFC 5910) | `[]` |
| `key_records() -> List[Dict[str, object]]` | Ключі DNSSEC: `[{"flags": …, "protocol": …, "alg": …, "pubKey": "…"}]` | `[]` |
| `is_signed() -> bool` | Чи присутні хоч якісь дані DNSSEC | `False` |

```python
info = client.domain.info("example.com.ua")

info.nameservers()              # ["ns1.example.com.ua", "ns2.example.com.ua"]
info.tech_contacts()            # ["acme-ns1"]
info.subordinate_hosts()        # ["ns1.example.com.ua"]
```

`nameservers()` покриває обидві моделі EPP — посилання на об'єкт хоста і ім'я, вбудоване разом зі
своїми glue-адресами, — бо клієнт, який читає лише одну з них, побачить порожній список проти
реєстру, що користується іншою, і зробить висновок, що делегування в домену немає взагалі.
`nameserver_addresses()` повертає glue-адреси лише там, де реєстр вбудував їх у відповідь; порожній
результат тут **не** означає, що домен не делеговано, — він означає, що адреси треба забрати через
`host.info()` для кожного імені.

`subordinate_hosts()` — це те, що варто перевірити перед видаленням: реєстр відмовляється видаляти
домен, поки під ним живуть об'єкти хостів.

`transfer()` відповідає, хто запитав, коли, хто має діяти і до якого моменту:

```python
t = client.domain.transfer("query", "example.com.ua")
t.transfer()
# {'status': 'pending', 'requested_by': 'ACME', 'requested_at': '2026-08-14T10:00:00Z',
#  'acting_client': 'EXAMPLE', 'act_by': '2026-08-19T10:00:00Z', 'expiry_date': '2028-04-01T09:15:00Z'}
```

Сам лише `transfer_status()` каже, що трансфер очікує, але не каже, чий він і скільки у вас часу, —
а `act_by` є тим строком, після якого реєстр вирішує за вас.

`registrar_of_record()` — це не `sponsor()`. `sponsor()` називає обліковий запис, якому належить
об'єкт, — ваш, усередині вашої власної реселерської ієрархії; `registrar_of_record()` називає
сторону, яку публікує реєстр, а для реселера це хтось інший.

## Хост

| Метод доступу | Повертає | Коли відповідь нічого не несе |
|---|---|---|
| `host_addresses() -> List[Dict[str, str]]` | Glue-адреси цього об'єкта хоста: `[{"ip": "192.0.2.1", "version": "v4"}, …]` | `[]` |

Glue-адреси має лише хост усередині зони, яку він обслуговує. Для зовнішнього сервера імен реєстр не
повертає жодної, і це нормально, а не відсутня відповідь. Адреси прив'язані до самого об'єкта хоста,
тож glue-адреси домену за кожним сервером імен лишаються в `nameserver_addresses()`, де видно, яка
адреса якому імені належить.

## Контакт

| Метод доступу | Повертає | Коли відповідь нічого не несе |
|---|---|---|
| `email() -> Optional[str]` | Адреса електронної пошти | `None` |
| `voice() -> Optional[str]` | Номер телефону у формі EPP `+CC.NNNN` | `None` |
| `fax() -> Optional[str]` | Номер факсу, тієї самої форми | `None` |
| `postal_info() -> Dict[str, Dict[str, object]]` | Адреси за формами: `"int"` (ASCII) та `"loc"` (локальне письмо). Кожна містить `name`, `org`, `street` (список), `city`, `sp`, `pc`, `cc` | `{}` |
| `disclose() -> Optional[Dict[str, object]]` | `{"flag": True, "elements": ["email", "voice"]}` (RFC 5733) | `None`, коли контакт не висловлює вподобання і діє сама лише політика реєстру |

Контакт може нести одну поштову форму або обидві. Читайте `"int"`, коли потрібне щось, що безпечно
надрукувати будь-де; читайте `"loc"` для адреси в тому вигляді, в якому її написав сам реєстрант.

У `disclose()` `flag` `True` означає, що перелічені елементи **можна** публікувати, а `False` — що їх
треба приховати; усе неперелічене отримує протилежне до прапорця. Список без прапорця нічого не
означає, тож ніколи не читайте одне без другого. Поштові `name`, `org` і `addr` з'являються для
кожної форми окремо, як `name:int` чи `addr:loc`.

## Check і гроші

| Метод доступу | Повертає | Коли відповідь нічого не несе |
|---|---|---|
| `availability() -> Dict[str, bool]` | Уся мапа `*:check`: ім'я чи ідентифікатор → доступність | `{}` |
| `is_available(name: str) -> Optional[bool]` | Доступність одного імені, збіг без урахування регістру | **`None`** — відповідь про нього нічого не сказала, а це не «зайнято» |
| `unavailable_reason(name: str) -> Optional[str]` | Чому ім'я недоступне: `"In use"`, `"Reserved"` | `None`, коли воно доступне або коли реєстр не назвав причини |
| `fees() -> Dict[str, object]` | Таблиця цін RFC 8748 — див. нижче | `{}` |
| `fee_for(name: str, operation: str, years: int = 1) -> Optional[str]` | Одна котирувана ціна, точним десятковим рядком | `None`, коли відповідь такого котирування не несла |
| `fee_class(name: Optional[str] = None) -> Optional[str]` | Тарифний клас від реєстру: `"premium"`, `"standard"` | `None`, коли відповідь не оголосила жодного |
| `is_premium(name: Optional[str] = None) -> bool` | Чи оцінене ім'я поза стандартним переліком | `False` |
| `charged_fee() -> Optional[Dict[str, str]]` | Що команда, яка щось змінила, справді списала: `{"currency": "UAH", "fee": "100.00"}` | `None` |
| `fee_amount() -> Optional[str]` | Лише сума з `charged_fee()` | `None` |
| `fee_currency() -> Optional[str]` | Лише валюта з `charged_fee()` | `None` |
| `balance() -> Optional[Dict[str, str]]` | `{"creditLimit": …, "balance": …, "availableCredit": …}` | `None`, коли це не відповідь про баланс |
| `credit_limit() -> Optional[str]` | Кредит, наданий понад нульовий баланс | `None` |
| `current_balance() -> Optional[str]` | Кошти на обліковому записі просто зараз | `None` |
| `available_credit() -> Optional[str]` | Те, що ви справді можете витратити: баланс плюс залишок кредиту | `None` |

`fees()` має ключами імена плюс ключ `_currency` для валюти котирування:

```python
r = client.domain.check(["example.com.ua"], fee={"create": [1, 2, 5]}, currency="UAH")
r.fees()
# {'_currency': 'UAH',
#  'example.com.ua': {
#      'avail': True,
#      'reason': None,
#      'class': 'premium',                       # є лише тоді, коли реєстр його оголосив
#      'commands': {'create': {'years': 1, 'fee': '100.00'}},
#      'periods': [{'op': 'create', 'years': 1, 'fee': '100.00'},
#                  {'op': 'create', 'years': 2, 'fee': '195.00'},
#                  {'op': 'create', 'years': 5, 'fee': '480.00'}]}}

r.fee_for("example.com.ua", "create", 5)      # '480.00'
```

Запит однієї операції на кілька періодів повертає по одному котируванню на період. `commands`
зберігає перше з них, тож той, хто читає `commands["create"]`, усе одно отримає відповідь; `periods`
містить усі, а `fee_for()` — це те, чим ви дістаєте потрібне. `transfer` і `restore` читайте назад за
один рік — це однорічні операції, про скільки б років ви не питали. Суми тут наведено для прикладу,
це не тариф реєстру.

`avail` `False` у записі йде разом із `reason`: зона не обслуговується або валюта, яку ви запитали,
не є тією, в якій реєстр призначає ціни, — але ніколи не перерахована навмання.

`is_premium()`, що повертає `False`, не є обіцянкою стандартної ціни; це означає, що відповідь не
оголосила окремого класу. Тарифікуйте з `fees()`, а саму команду обмежуйте погодженням тарифу, щоб
ім'я з іншою ціною отримало відмову 2004, а не виставило вам різницю. Див. [Баланс](balance.md).

## Poll

| Метод доступу | Повертає | Коли відповідь нічого не несе |
|---|---|---|
| `message_id() -> Optional[str]` | Ідентифікатор повідомлення в черзі, який передається в `poll.ack()` | `None` — у цій відповіді сповіщення немає |
| `message_count() -> int` | Скільки повідомлень лишається в черзі | `0` |
| `queue_message() -> Optional[str]` | **Текст сповіщення**, з `<msgQ><msg>` | `None` |
| `queue_message_lang() -> Optional[str]` | Мова сповіщення: `uk`, `ru`, `en` | `None` |
| `queue_date() -> Optional[str]` | Коли сповіщення поставлено в чергу | `None` |
| `pending_action_data() -> Optional[Dict[str, object]]` | Результат операції, яку реєстр обробив офлайн | `None`, коли сповіщення його не несе |

**Сповіщення — це `queue_message()`, а не `message()`.** `message()` повертає банер результату
команди — «Command completed successfully; ack to dequeue», — однаковий у кожній відповіді на poll.
Читання сповіщення через `message()` віддає вам той сталий рядок, тоді як справжній вміст
відкидається, а підтвердження, що йде слідом, знищує його в реєстрі назавжди.

`pending_action_data()` — це те, як відкладена команда звітує про себе. Ви надсилаєте `create`,
отримуєте 1001 зі svTRID, а відповідь надходить пізніше в чергу:

```python
notice = client.poll.request()
pan = notice.pending_action_data()
# {'object': 'example.com.ua', 'success': True,
#  'clTRID': 'PYTHON-SDK-20260814101500-4821-0007',
#  'svTRID': 'SRV-19700101103512-24191-00007',
#  'date': '2026-08-14T10:20:00Z'}
```

| Ключ | Чому він важить |
|---|---|
| `success` | **Єдине, що каже, чи спрацювало.** Довколишній 1301 означає «ось повідомлення», а не «ваша операція вдалася» |
| `svTRID` / `clTRID` | Ідентифікатори транзакції **початкової** команди. Зіставте svTRID із тим, який вам дали разом із 1001, щоб знати, на яку відкладену операцію це відповідь, — poll є чергою, і це не конче найсвіжіша з них |
| `date` | Коли дію завершено, а не коли ви опитали чергу |
| `object` | Доменне ім'я або ідентифікатор контакту, якого це стосувалося |

Див. [Poll](poll.md) щодо самої черги та правила порядку, яке не дає загубити сповіщення.

## Безпека сесії та привітання

| Метод доступу | Повертає | Коли відповідь нічого не несе |
|---|---|---|
| `security_events() -> List[Dict[str, str]]` | Попередження RFC 8807 про **цю сесію** — кожне з `text` і тими з полів `type`, `name`, `level`, `exDate`, `value`, `duration`, `lang`, які несе подія | `[]` на здоровій сесії |
| `service_obj_uris() -> List[str]` | Привітання: об'єктні сервіси, які оголошує сервер | `[]` |
| `service_ext_uris() -> List[str]` | Привітання: сервіси розширень, які оголошує сервер | `[]` |

```python
greeting = client.connect()
if Namespaces.FEE in greeting.service_ext_uris():
    ...                                  # ця точка підключення котирує ціни
```

Порожній `security_events()` — це чиста сесія, тож будь-який запис вважайте приводом діяти. Сервер
повертає їх лише клієнту, який узяв участь у розширенні, — див.
[Сесія → Безпека входу](session.md#безпека-входу-rfc-8807).

## Діагностика при збої

| Метод доступу | Повертає | Коли відповідь нічого не несе |
|---|---|---|
| `ext_values() -> List[Dict[str, object]]` | Кожен `<extValue>`, розібраний: `element`, `namespace`, `text`, `values`, `xml`, `reason`, `lang` | `[]` |
| `error_reasons() -> List[str]` | Лише тексти `<extValue><reason>` | `[]` |

`error_reasons()` дає вам формулювання; `ext_values()` дає **предмет**, а на команді з п'ятьма
іменами саме він вам і потрібен — «EPP 2302: Object exists» лишає вас гадати, яке з п'яти, а
відповідь лежить у `<extValue>`.

```python
for ext in response.ext_values():
    print(ext["element"], ext["text"], "—", ext["reason"])
# name bad..name — Invalid label
```

Елемент, що спричинив помилку, зазвичай є листком, і тоді відповідь — це `text`. Коли ж це
контейнер, `text` порожній, бо контейнер не має власних символьних даних: `values` містить нащадків
за іменами, а `xml` — елемент у тому вигляді, в якому він надійшов, якщо ви волієте розібрати його
самі.

Та сама інформація доходить до вас і через виняток: `CommandException.subject()` та `.reasons()`.
Див. [Помилки](errors.md).

## Прямий доступ

| Метод доступу | Повертає | Коли відповідь нічого не несе |
|---|---|---|
| `value(local_name: str) -> Optional[str]` | Перший елемент будь-де з таким локальним іменем, обрізаний по краях | `None` |
| `values(local_name: str) -> List[str]` | Кожен елемент із таким локальним іменем, обрізаний по краях | `[]` |
| `res_data() -> Optional[ET.Element]` | Елемент `<resData>` — для власного розбору | `None` |
| `raw -> str` | Властивість: XML відповіді рівно так, як він надійшов | кадр присутній завжди |
| `root -> ET.Element` | Властивість: розібраний корінь `ElementTree` | присутній завжди |
| `Response.from_xml(xml: str) -> Response` | Метод класу: розібрати кадр, який ви здобули самі | підіймає `ConnectionException` на некоректному XML |

`value()` і `values()` — це загальна форма, на якій збудовано іменовані методи доступу; беріть їх,
коли розширення реєстру несе щось, чого цей посібник не називає:

```python
response.value("exDate")        # те саме, що expiry_date()
response.values("hostObj")      # кожен <domain:hostObj> у відповіді
```

`Response.from_xml()` відхиляє кадр із DOCTYPE навідріз, через `ConnectionException`. Відповідь EPP
його ніколи не має, а парсер, що розгортає внутрішні сутності, — це те, як вороже налаштована точка
підключення перетворює кадр у межах бюджету 1 MiB на клієнта, якому забракло пам'яті.
