# Команди

Поверхня команд загалом: де живуть методи, що вони всі повертають, як відповідь зіставляється із
запитом, що її спричинив, як вимкнути підіймання винятків і як надіслати кадр, якого бібліотека не
моделює.

## Де живуть команди

Усе, що доступне після успішного `login()`, висить на чотирьох властивостях-ресурсах і одному методі
клієнта:

```python
client.domain     # доменні команди RFC 5731
client.contact    # контактні команди RFC 5733
client.host       # хостові команди RFC 5732
client.poll       # черга повідомлень
client.balance()  # власний запит облікового запису від реєстру
```

Кожна властивість будується один раз і використовується повторно, тож `client.domain` — це щоразу
той самий об'єкт, і тримати посилання на нього нормально.

## Повний покажчик команд

Кожен метод тут надсилає рівно одну команду EPP і повертає [`Response`](responses.md). Подробиці —
аргументи, приклади, що повертається — на сторінках об'єктів.

### Домени — [domains.md](domains.md)

| Метод | EPP |
|---|---|

| `info(name: str, auth_info: Optional[str] = None, hosts: str = "all")` | `<info>` |
| `create(name, *, years=None, registrant=None, contacts=None, nameservers=None, auth_info=None, license=None, sec_dns=None, fee=None)` | `<create>` |
| `update(name, *, add=None, rem=None, chg=None, restore=False, license=None, sec_dns=None, fee=None)` | `<update>` |
| `renew(name: str, cur_exp_date: str, years: int = 1, fee=None)` | `<renew>` |
| `restore(name: str, fee=None)` | `<update>` + RFC 3915 `rgp:restore` |
| `delete(name: str)` | `<delete>` |
| `transfer(op: str, name: str, auth_info=None, years=None, fee=None)` | `<transfer op="…">` |
| `create_builder(name: str)` | [білдер](builders.md) для `create` |
| `update_builder(name: str)` | [білдер](builders.md) для `update` |

### Контакти — [contacts.md](contacts.md)

| Метод | EPP |
|---|---|
| `check(ids: List[str])` | `<check>` |
| `info(contact_id: str, auth_info: Optional[str] = None)` | `<info>` |
| `create(contact_id, *, name=None, org=None, street=None, city=None, sp=None, pc=None, cc=None, type="int", postal_infos=None, voice=None, fax=None, email=None, auth_info=None, disclose=None)` | `<create>` |
| `create_auto(**options)` | `<create>` з `Contact.AUTO_ID` як ідентифікатором — реєстр генерує ідентифікатор сам |
| `update(contact_id, *, add_statuses=None, rem_statuses=None, chg=None)` | `<update>` |
| `delete(contact_id: str)` | `<delete>` |
| `transfer(op: str, contact_id: str, auth_info: Optional[str] = None)` | `<transfer op="…">` |

`Contact.AUTO_ID` — це зарезервований ідентифікатор, який просить реєстр обрати ідентифікатор
контакту замість того, щоб називати його самому. Згенерований ідентифікатор надходить у відповіді, і
**ця відповідь — єдине місце, де він з'являється**: прочитайте його через `object_name()` і
збережіть.

## Що повертає команда

Кожна команда повертає `Response` — ніколи `None` і ніколи голий dict. Об'єкт загортає розібрану
відповідь і відповідає на запитання про неї; [Відповіді](responses.md) описують кожен метод доступу.

```python
response = client.domain.create("example.com.ua", years=1, registrant="acme-01")
response.code()          # 1000
response.is_success()    # True для будь-якого 1xxx
response.is_pending()    # True для 1001
response.object_name()   # "example.com.ua"
response.sv_trid()       # ідентифікатор цієї операції в реєстрі — збережіть його
```

| Код | Значення | Що робить бібліотека | Що робите ви |
|---|---|---|---|
| `1000` | виконано | повертає `Response` | продовжуйте |
| `1001` | прийнято, завершується офлайн | повертає `Response`; `is_success()` і `is_pending()` обидва `True` | **не надсилайте повторно.** Результат надійде пізніше як poll-сповіщення |
| `1300` / `1301` | poll: порожньо / повідомлення чекає | повертає `Response` | див. [Poll](poll.md) |
| `1500` | сесія завершується | повертає `Response` із `logout()` | роз'єднуйтесь |
| `2xxx` | відмовлено; нічого не змінено | підіймає виняток, якщо ви цього не вимкнули | див. [Помилки](errors.md) |

**Саме на 1001 спотикаються.** Команду прийнято, і вона обробляється офлайн — завжди для трансферу
та для інших операцій залежно від зони. Ставтеся до цього як до успіху в процесі: запишіть svTRID,
стежте за чергою poll щодо результату і ніколи не надсилайте команду ще раз «про всяк випадок».
Відповідне сповіщення несе `pending_action_data()`, чий `svTRID` і прив'язує його до команди, яку ви
надіслали.

Дати й гроші у відповіді — це **власні рядки сервера**: `2027-04-01T09:15:00Z`, `"100.00"`, — ніколи
не `datetime` і ніколи не `float`. Так зроблено навмисно, і причини варто знати, перш ніж будувати
на цьому: див. [Відповіді](responses.md#дати-та-гроші).

## Клієнтські ідентифікатори транзакцій

Кожна команда несе `clTRID`, який обираєте ви і який сервер повертає назад; кожна відповідь несе
`svTRID`, який призначає реєстр.

Бібліотека штампує clTRID на кожному кадрі автоматично:

```
PYTHON-SDK-20260816093012-4821-0001
│       │              │    └── лічильник, свій для кожного об'єкта клієнта
│       │              └─────── ідентифікатор процесу
│       └────────────────────── позначка часу UTC
└────────────────────────────── Config.cltrid_prefix
```

Ідентифікатори з одного процесу мають спільний сталий середній сегмент і лишаються унікальними між
одночасними процесами. Змініть префікс через `Config.cltrid_prefix`, щоб упізнавати власний трафік у
спільному журналі, і тримайте його коротким: протокол обмежує весь ідентифікатор 64 символами.

**Зберігайте svTRID поруч з об'єктом, якого стосувалася команда.** Це значення, за яким підтримка
знаходить операцію; clTRID не означає нічого ні для кого, крім вас. Записуйте обидва, на кожній
команді, включно з тими, що вдалися, — саме з ними ви порівнюєте, коли пізніша не вдасться.

### Відповіді зіставляються зі своїми командами

Кожна відповідь звіряється з clTRID, який надіслала її команда. Розбіжність означає, що потік байтів
розсинхронізувався — випадковий незапитаний кадр або дві команди в польоті одночасно, — і бібліотека
підіймає `ConnectionException` та закриває з'єднання замість того, щоб віддати вам чужий результат.

Робить вона це через наслідки того, що буває без такої звірки: відповідь, яка належить попередній
команді, інакше не відрізнити від відповіді на цю, а для продовження це означає, що
`renew("example2.com.ua")` поверне 1000 із датою завершення терміну реєстрації домену a — і обидва будуть
затарифіковані. Щойно зсуви розійшлися, кожен наступний кадр у потоці теж під підозрою, тому
з'єднання вичерпується, а не просто отримує зауваження. Перепідключіться і увійдіть знову.

Саме тому ви й надсилаєте на з'єднанні по одній команді за раз. Для пропускної здатності відкривайте
більше сесій; не накладайте команди в одній.

## Перемикач throw_on_failure

Типово будь-який код відповіді від 2000 і вище підіймає виняток — клас залежить від коду, див.
[Помилки](errors.md). Повідомлення називає предмет, коли реєстр його вказав, тож відмова всередині
пакета з п'яти імен скаже, про яке саме ім'я йшлося.

```python
client.throw_on_failure(False)      # повертає клієнта, тож викликається ланцюжком

response = client.domain.check(["example.com.ua"])
if not response.is_success():
    log.warning("EPP %d: %s", response.code(), response.message())
```

`throw_on_failure(False)` вимикає підіймання винятків для об'єктних команд, а
`throw_on_failure(True)` вмикає його назад. Двоє підіймають виняток у будь-якому разі, бо натомість
немає корисного `Response`, який можна було б віддати:

- **`login()`**, який підіймає виняток на будь-якому коді, крім 1000. Немає сесії, в яку можна було
  б продовжити.
- **`poll.drain()`**, коли відповідь на poll — це ні сповіщення, ні порожня черга. Прочитати це як
  «спорожнено» означало б повідомити про успіх, тоді як не прочитано нічого.

Вимкнути перемикач означає, що помічати збій тепер ваша справа. `create`, чиї 2104 ви не перевірили,
— це домен, який ваша система вважає зареєстрованим.

## Власні кадри

Усе, чого високорівневий API не моделює, можна зібрати через `Frame` і надіслати через
`client.request()`. Це запасний хід для розширення реєстру, специфічного для вашого облікового
запису, а не те, що потрібне звичайній інтеграції.

```python
from epptools import Frame, Namespaces

frame = client.frame()                       # <command> з уже проштампованим clTRID
check = frame.ns(frame.verb("check"), Namespaces.DOMAIN, "domain:check")
frame.ns(check, Namespaces.DOMAIN, "domain:name", "example.com.ua")

response = client.request(frame)             # або client.request(raw_xml_string)
print(response.availability())
```

| Член | Що робить |
|---|---|
| `client.frame()` | Новий `Frame` із уже згенерованим clTRID на ньому. |
| `Frame.command(cltrid)` | Кадр із clTRID, який обираєте ви. |
| `frame.verb(name)` | Додає дієслово команди — `check`, `info`, `create`, `update`, `renew`, `transfer`, `delete`, `poll`, `login`, `logout` — і повертає його. |
| `frame.extension()` | Додає `<extension>` один раз і повертає його; викликайте скільки завгодно разів. |
| `frame.epp(parent, name, text=None, attrs=None)` | Додає елемент у базовому просторі імен `epp-1.0`. |
| `frame.ns(parent, ns_uri, qname, text=None, attrs=None)` | Додає елемент із простором імен, напр. `frame.ns(parent, Namespaces.DOMAIN, "domain:name", "example.com.ua")`. |
| `frame.to_xml()` | Серіалізує кадр. Безпечно викликати не один раз — запишіть у журнал, потім надішліть. |
| `frame.root` | Підлеглий елемент `ElementTree` — для всього, чого не покривають помічники. |
| `client.request(frame_or_xml)` | Надсилає `Frame` або сирий рядок XML і повертає розібраний `Response`. |

Будівник кадрів гарантує порядок нащадків за RFC 5730 — вміст команди, потім необов'язковий
`<extension>`, потім `<clTRID>` останнім — і встановлює текст на вузлах елементів, а не склеює
рядки, тож значення, яке містить `&` чи `<`, екранується, а не дає кадр, на який сервер відповідає
2001.

`Namespaces` містить константи URI, тож жодного з них не доведеться набирати руками: `EPP`,
`DOMAIN`, `CONTACT`, `HOST`, `SECDNS` (RFC 5910), `RGP` (RFC 3915), `FEE` (RFC 8748), `LOGINSEC`
(RFC 8807), а також `DEFAULT_OBJ_URIS` і `DEFAULT_EXT_URIS`.

Кадр, зібраний вами, отримує те саме поводження, що й зібраний бібліотекою: повернений clTRID
звіряється, відповідь розбирається в `Response`, а код помилки підіймає виняток, якщо ви цього не
вимкнули. Використовуйте ті URI з `Namespaces`, які привітання справді оголосило, — у розширенні,
якого сервер не обслуговує, буде відмовлено з 2103.

### Власні розширення вашого реєстру

Кожен URI у `Namespaces` визначений якимось RFC і однаковий у будь-якого реєстру у світі. З ВЛАСНИМИ
розширеннями реєстру — ліцензією на торгову марку, ціною, балансом облікового запису — це вже не так,
і константи для них там не буде: немає значення, яке було б правильним більш ніж для одного реєстру.

Вони **визначаються з `<greeting>`**. Будь-який сервер перелічує те, що підтримує, ще до того як ви
щось надішлете, тому одразу після `connect()` клієнт уже знає:

```python
client.connect()

client.registry_ext_uri()      # наприклад 'http://registry.example/epp/registry-1.0', або None
client.registry_balance_uri()  # наприклад 'http://registry.example/epp/balance-1.0', або None
```

`None` означає, що цей сервер такого розширення не оголошує, — це факт про сервер, а не помилка.
Команди, яким розширення потрібне, про це кажуть, а не здогадуються: `domain.create` з `license`,
`host.delete` з `force` і `balance()` підіймають `ConfigException`, називаючи, що саме знадобилося, і
перелічуючи, що сервер запропонував. У цій відмові й полягає суть. Розширення, надіслане у просторі імен,
якого сервер не знає, **ігнорується, а не відхиляється**, — тобто здогадка повернулася б як
`1000 OK` з мовчки невстановленою ліцензією.

Визначення зіставляє останній сегмент оголошеного URI — `.../registry-1.0`, `urn:…:balance`, — і це
домовленість, якої реєстри дотримуються, а не правило, дотримання якого хтось примушує. Якщо реєстр
називає свої розширення інакше, задайте їх самі — тоді привітання не питають:

```python
config = Config(
    host="epp.registry.example", clid="EXAMPLE", password="...",
    registry_ext_uri="urn:example:params:xml:ns:myreg-1.0",
    registry_balance_uri="urn:example:params:xml:ns:myreg-balance-1.0",
)
```
