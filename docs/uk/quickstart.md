# Швидкий старт

Одна повна програма: підключитися до реєстру, увійти, поставити два запитання, які нічого не
коштують, прочитати свій баланс і коректно закрити сесію. Скопіюйте її, підставте власні облікові
дані, запустіть. Розбір після неї пояснює кожен рядок.

## Встановлення

```bash
pip install epptools
```

Прямо з GitHub із прив'язкою до тегу релізу, якщо ви волієте не залежати від PyPI:

```bash
pip install "epptools @ git+https://github.com/epptools/python-sdk@v1.1.1"
```

Узагалі без пакування? Покладіть теку пакета `epptools/` поруч зі своїм кодом і зробіть
`import epptools`. Більше встановлювати нічого не треба: бібліотека користується лише стандартною
бібліотекою Python.

## Що потрібно перед початком

| Що | Звідки береться |
|---|---|
| Хост і порт | Видаються разом з обліковим записом. `epp.registry.example`, порт **700**. |
| Ваш clID | Ваш ідентифікатор реєстратора, напр. `EXAMPLE`. |
| Пароль | Видається з обліковим записом. Змінюється через `<login>`, ніколи поштою. |
| Файл CA реєстру | Файл `.pem`. На порту 700 сервер пред'являє сертифікат від власного приватного CA реєстру, тож він обов'язковий — див. [Сесія](session.md#tls-і-сертифікат). |
| IP-адреса зі списку дозволених | Підключатися можна лише з адрес, зареєстрованих для цього clID. |

Будуйте на тестовій особі реєстру, перш ніж спрямовувати щось на бойове середовище.

## Уся програма

```python
"""Перша програма на EppTools: підключитися, запитати, вийти. Тут ніщо не тарифікується."""

import logging
import os
from decimal import Decimal

from epptools import Client, Config
from epptools.exceptions import CommandException, EppException

logging.basicConfig(level=logging.INFO)

config = Config(
    host="epp.registry.example",
    clid="EXAMPLE",
    password="your-secret",
    port=700,                 # типове значення; змінюйте, лише якщо точка підключення переїде
    lang="en",                # повідомлення про результат: en | uk | ua | ru
    ca_file=os.environ.get("EPP_CA", "/path/to/registry-ca.pem"),
)

client = Client(config, logger=logging.getLogger("epp"))

try:
    greeting = client.connect()
    print("server:", greeting.value("svID"))

    login = client.login()
    for event in login.security_events():
        print("session %s (%s): %s" % (event["level"], event["type"], event["text"]))

    name = "example.com.ua"
    check = client.domain.check([name], fee={"create": 1})
    available = check.is_available(name)
    if available is None:
        print("the registry said nothing about", name)
    elif available:
        print("%s is free; a create would cost %s %s" % (
            name, check.fee_for(name, "create", 1), check.fees().get("_currency")))
    else:
        print("%s is taken: %s" % (name, check.unavailable_reason(name)))

    info = client.domain.info(name)
    print("expires:", info.expiry_date())
    print("nameservers:", info.nameservers())
    print("svTRID:", info.sv_trid())

    money = client.balance()
    print("available credit:", Decimal(money.available_credit() or "0"))

    client.logout()
except CommandException as exc:
    print("the registry refused: EPP %d — %s" % (exc.epp_code, exc))
except EppException as exc:
    print("client-side failure:", exc)
finally:
    client.disconnect()
```

Очікуваний вивід для імені, яке вже комусь належить:

```
server: Registry EPP Server
example.com.ua is taken: In use
the registry refused: EPP 2201 — EPP 2201: Authorization error
```

Третій рядок — це програма, що працює правильно: `domain.info` для домену, який вам не належить,
відхиляється, виняток несе код, а `finally` все одно закриває сокет. Спрямуйте її на ім'я, яким ви
володієте, — і замість цього надрукуються два рядки `info`.

## Рядок за рядком

**1 — Імпорти.** `Client` і `Config` — це весь вхід до бібліотеки; обидва експортуються з кореня
пакета. Винятки живуть у `epptools.exceptions`. `CommandException` — це те, як виглядає відмова
реєстру виконати команду; `EppException` — його базовий клас, який перехоплює все, що бібліотека
підіймає, тож між двома `except` не лишається нічого необробленого. Див. [Помилки](errors.md).

**2 — `logging.basicConfig`.** Необов'язково і варте того з першого ж запуску. Логер, який ви
передаєте клієнту, друкує один рядок на команду з кодом відповіді та обома ідентифікаторами
транзакцій, а на рівні `DEBUG` — увесь кадр. Паролі та `authInfo` приховуються ще до того, як щось
буде записано, — див. [Сесія → Журналювання](session.md#журналювання).

**3 — `Config(...)`.** Незмінні налаштування підключення. `host`, `clid` і `password` обов'язкові й
не мають типових значень; усе решта має. `port=700` і так є типовим значенням, тут воно виписане
лише для наочності. `lang` задає мову всіх повідомлень про результат, які сервер надсилає в цій
сесії. `ca_file` — те, на чому спотикаються при першому запуску: точка підключення пред'являє
сертифікат приватного CA, системне сховище довіри цього CA не містить, і без цього файла
рукостискання не проходить перевірку. Кожне поле описано в
[Сесія → Config](session.md#config-поле-за-полем).

**4 — `Client(config, logger=...)`.** Створення клієнта нічого не відкриває. Його безпечно збудувати
під час імпорту, а підключитися пізніше.

**5 — `client.connect()`.** Відкриває TLS-сокет і читає незапитане `<greeting>` сервера, яке
повертає як `Response`. Привітання перелічує простори імен об'єктів і розширень, які обслуговує ця
точка підключення; вхід, що йде слідом, оголошує рівно їх, тож вашій сесії ніколи не відмовлять
через запит сервісу, якого сервер не пропонує. `greeting.value("svID")` дістає з нього один елемент
за локальним іменем.

**6 — `client.login()`.** Надсилає `<login>` з вашими clID і паролем (RFC 5730). Повертає `Response`
входу; усе, крім 1000, підіймає виняток — `AuthenticationException` для 2200 і конкретніший клас для
решти: 2502 — це обмеження на кількість сесій, а не хибний пароль, і виправляються ці два випадки
протилежно.

**7 — `login.security_events()`.** RFC 8807. Сервер повертає те, що радить вам виправити в цій
сесії: клієнтський сертифікат за тижні до завершення строку, застарілу версію TLS, слабкий набір
шифрів. На здоровій сесії список порожній, тож будь-який запис вважайте приводом діяти.
Альтернатива дізнатися про сертифікат, що спливає, тут — дізнатися про нього того ранку, коли він
перестане працювати. Див. [Сесія → Безпека входу](session.md#безпека-входу-rfc-8807).

**8 — `client.domain.check([name], fee={"create": 1})`.** Одна команда `<check>` (RFC 5731) з
причепленим блоком тарифів RFC 8748, тож доступність і ціна надходять за один обмін із сервером.
`check` нічого не змінює і нічого не коштує, тому це безпечна перша команда для живого облікового
запису.

**9 — `check.is_available(name)`.** Тризначний навмисно: `True`, `False` або `None`, коли відповідь
нічого про це ім'я не сказала. `None` — це не «зайнято», і рядок, який далі реєструє ім'я, не має
тлумачити його так.

**10 — `check.fee_for(name, "create", 1)`.** Котирувана ціна однієї операції на один період, як
власний точний десятковий рядок реєстру — ніколи не float, бо `0.1 + 0.2` у двійковій рухомій комі
не дорівнює `0.3`, і гроші, підсумовані так, розповзаються. `check.fees()` повертає всю таблицю за
іменами разом із ключем `_currency`. Ціни в цьому посібнику наведено для прикладу. Див.
[Баланс](balance.md).

**11 — `client.domain.info(name)`.** `<info>` для одного домену. `expiry_date()` дає дату завершення
терміну реєстрації рівно так, як її записав реєстр (`2027-04-01T09:15:00Z`), рядком, а не
`datetime`: саме реєстр вирішує, на який календарний день припадає продовження, а переформатування
через локальний часовий пояс — це те, як клієнт починає продовжувати з розрахунку на попередній
день. `nameservers()` повертає імена незалежно від того, якою з двох моделей EPP реєстр їх виражає.

**12 — `info.sv_trid()`.** Власний ідентифікатор реєстру для цієї операції. Зберігайте його поруч з
об'єктом, якого стосувалася команда. Це значення, за яким підтримка знаходить операцію; ваш clTRID
не означає нічого ні для кого, крім вас.

**13 — `client.balance()`.** Власний запит балансу від реєстру. `available_credit()` — це те, що ви
справді можете витратити: баланс плюс залишок кредиту, точним десятковим рядком, тому він проходить
через `Decimal`, а не через `float`. Див. [Баланс](balance.md).

**14 — `client.logout()`.** Коректно завершує сесію; сервер відповідає 1500 і закриває з'єднання.
Якщо його пропустити, сесія займатиме один зі слотів ваших одночасних сесій, доки сервер не
завершить її за тайм-аутом, і наступному підключенню можуть відмовити з 2502 через слот, яким ви вже
не користуєтесь.

**15 — `except CommandException`.** Реєстр відповів кодом помилки. `exc.epp_code` — це той код, а
`exc.response` — повна розібрана відповідь. Перехоплюйте вужчі підкласи там, де правильний наступний
крок відрізняється: `InsufficientFundsError` має зупиняти пакет, а не пропускати одне ім'я.

**16 — `finally: client.disconnect()`.** Закриває сокет за будь-яких обставин. `Client` є також
контекстним менеджером (`with Client(config) as client:`), який роз'єднується на виході, — але він
не підключається, не входить і не надсилає за вас `<logout>`, тож тримайте виклик `logout()`
усередині блока.
