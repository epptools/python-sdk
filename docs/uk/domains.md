# Домени

Усе під `client.domain`. Об'єкти доменів відповідають **RFC 5731**, і кожен метод на цій сторінці
відповідає рівно одній команді EPP у каналі передачі, тож власний посібник реєстру та RFC описують
той самий обмін з боку сервера.

Кожен метод повертає [`Response`](responses.md). За замовчуванням код відповіді 2000 або вищий
викидається як виняток ще до того, як ви побачите відповідь, — див. [Помилки](errors.md) щодо
таксономії та щодо `throw_on_failure(False)`, якщо ви волієте читати `code()` самотужки.

Спершу повна програма, щоб фрагментам нижче було на що спертися:

```python
from epptools import Client, Config
from epptools.exceptions import EppException

client = Client(Config(
    host="epp.registry.example",
    clid="EXAMPLE",
    password="your-secret",
    ca_file="/etc/ssl/registry-ca.pem",
))

try:
    client.connect()
    client.login()

    check = client.domain.check(["example.com.ua"])
    if check.is_available("example.com.ua"):
        created = client.domain.create("example.com.ua", years=1, registrant="C1")
        print("registered until", created.expiry_date())
    else:
        print("taken:", check.unavailable_reason("example.com.ua"))

    client.logout()
except EppException as exc:
    print("EPP error:", exc)
finally:
    client.disconnect()
```

## Методи

| Метод | Команда EPP |
|---|---|
| `check` | `<check><domain:check>` |
| `info` | `<info><domain:info>` |
| `create` | `<create><domain:create>` |
| `update` | `<update><domain:update>` |
| `delete` | `<delete><domain:delete>` |
| `renew` | `<renew><domain:renew>` |
| `transfer` | `<transfer op="…"><domain:transfer>` |
| `restore` | `<update><domain:update>` + `<rgp:restore op="request"/>` |

`create_builder()` та `update_builder()` збирають ті самі дві команди крок за кроком; вони описані
в розділі [Білдери](builders.md) і формують ідентичний кадр.

## check

```python
client.domain.check(names: List[str],
                    fee: Optional[Dict[str, Any]] = None,
                    currency: Optional[str] = None) -> Response
```

Питає, чи можна зареєструвати імена. По одному `<domain:name>` на ім'я і, за бажанням, причіпний
блок `<fee:check>` (RFC 8748) у `<extension>`, який заразом питає ціну, — половину з комісіями
повністю розібрано на сторінці [Баланс і ціни](balance.md).

**Щонайбільше 10 імен на команду.** Одинадцяте реєстр відхиляє з 2001, тож формуйте пакети по
десять.

```python
r = client.domain.check(["example.com.ua", "taken.com.ua"])

r.availability()          # {'example.com.ua': True, 'taken.com.ua': False}
r.is_available("example.com.ua")        # True
r.unavailable_reason("taken.com.ua")    # 'in use'
```

`is_available()` повертає `None`, коли відповідь узагалі нічого не сказала про це ім'я. Це не те
саме, що «зайняте», і рядок, який реєструє домен, не має ставитися до цього однаково:

```python
free = r.is_available("example.com.ua")
if free is None:
    raise RuntimeError("the check said nothing about this name — ask again before registering")
if free:
    client.domain.create("example.com.ua", years=1, registrant="C1")
```

| Код | Значення |
|---|---|
| 1000 | відповідь отримано; читайте `availability()` — недоступне ім'я це звичайний 1000, а не помилка |
| 2001 | понад 10 імен в одній команді |
| 2004 | причіпний блок комісії запитав операцію, яку реєстр не тарифікує |
| 2306 | понад 20 записів про комісії в одній команді |
| 2307 | зона не обслуговується |

## info

```python
client.domain.info(name: str,
                   auth_info: Optional[str] = None,
                   hosts: str = "all") -> Response
```

Читає домен. Як реєстратор-власник ви отримуєте повний запис. Як не-власник ви отримуєте публічну
підмножину (ім'я, roid, статуси, дати, власник) — і повний запис натомість, якщо передасте
`auth_info` домену. Передати *неправильний* код це 2202; не передати жодного помилкою не є.

`hosts` задає атрибут `hosts` елемента `<domain:name>` і обирає, які відомості про сервери імен
повернуться (RFC 5731 §3.1.2):

| Значення | Повертає |
|---|---|
| `"all"` | і делеговані сервери імен, і підпорядковані хости (за замовчуванням) |
| `"del"` | лише сервери імен, яким делеговано цей домен |
| `"sub"` | лише хости, що живуть під цим доменом |
| `"none"` | нічого з цього |

```python
info = client.domain.info("example.com.ua")

info.object_name()          # 'example.com.ua'
info.roid()                 # власний ідентифікатор об'єкта в реєстрі
info.expiry_date()          # '2027-04-01T09:15:00.0Z' — власний рядок реєстру
info.created_date()         # crDate            info.created_by()   # crID
info.updated_date()         # upDate, або None  info.updated_by()   # upID, або None
info.transfer_date()        # trDate, або None, якщо домен ніколи не змінював власника
info.sponsor()              # clID — обліковий запис, якому він належить
info.registrar_of_record()  # ідентифікатор, який публікують WHOIS/RDAP, коли це інша сторона

info.registrant()           # 'C1'
info.contacts()             # {'admin': ['EXAMPLE-C2'], 'tech': ['EXAMPLE-C3']}
info.tech_contacts()        # ['EXAMPLE-C3']  — також admin_contacts(), billing_contacts()
info.contacts_for("Tech")   # той самий список; роль зіставляється без урахування регістру
info.all_contacts()         # усі ідентифікатори, включно з реєстрантом, без повторів

info.statuses()             # ['ok'] або ['clientHold', 'clientTransferProhibited', ...]
info.nameservers()          # ['ns1.example.com.ua', 'ns2.example.com.ua']
info.nameserver_addresses() # вбудовані glue-адреси за іменем сервера (порожньо в моделі hostObj)
info.subordinate_hosts()    # хости, що живуть ПІД цим доменом
info.auth_info()            # секрет для трансферу — ніколи не пишіть його в журнал
info.license()              # номер торгової марки або ліцензії, або None
info.rgp_status()           # ['redemptionPeriod'], поки домен видалено, але ще можна відновити
info.is_signed()            # True, коли повернулися дані DNSSEC
info.ds_records()           # [{'keyTag': 12345, 'alg': 13, 'digestType': 2, 'digest': '…'}]
info.key_records()          # [{'flags': 257, 'protocol': 3, 'alg': 13, 'pubKey': '…'}]
info.prices()               # {'renewal': {'value': '180.00', 'currency': 'UAH'}, …}
info.price_channel()        # непрозорий ідентифікатор каталогу, до якого належать ці ціни
```

Три речі, неправильне прочитання яких коштує грошей або даних:

- **Дати — це власні рядки реєстру**, ніколи не `datetime`. Реєстр вирішує, на який календарний
  день припадає продовження; переформатування через локальний часовий пояс — це те, як клієнт
  починає показувати попередній день і продовжувати домен саме на нього.
- **Викуп живе в `rgp_status()`**, а не в `statuses()`. Домен за кілька днів до остаточного
  видалення може повідомляти звичайний `ok` у `statuses()`, і клієнт, який читає лише це, не бачить
  нічого підозрілого, доки ім'я не зникне.
- **Порожній `nameserver_addresses()` не означає, що домен не делеговано.** Він несе лише вбудовані
  glue-адреси. У моделі об'єктів хостів імена повертаються самі по собі; беріть список із
  `nameservers()`, а адреси — окремим [`host.info`](hosts.md#info) на кожне ім'я.

| Код | Значення |
|---|---|
| 1000 | відповідь отримано |
| 2202 | ви не власник, а наданий `auth_info` неправильний |
| 2303 | такого домену немає |

## create

```python
client.domain.create(name: str, *,
                     years: Optional[int] = None,
                     registrant: Optional[str] = None,
                     contacts: Optional[Dict[str, str]] = None,
                     nameservers: Optional[List[Nameserver]] = None,
                     auth_info: Optional[str] = None,
                     license: Optional[str] = None,
                     sec_dns: Optional[Dict[str, Any]] = None,
                     fee: Optional[FeeAgreement] = None) -> Response
```

Реєструє домен. **Це платна команда**: комісія за create стягується в разі успіху.

Кожен параметр після `name` передається лише за іменем, тож помилка в написанні стає `TypeError`
у вашому редакторі, а не відсутнім елементом у каналі передачі.

| Параметр | Тип | Іде в канал передачі як |
|---|---|---|
| `years` | `int` | `<domain:period unit="y">`; повністю опускається, якщо ви його не передали, і тоді реєстр застосовує власне значення за замовчуванням |
| `registrant` | `str` | `<domain:registrant>` |
| `contacts` | `{роль: ідентифікатор}` або `{роль: [ідентифікатор, …]}` | по одному `<domain:contact type="роль">` на ідентифікатор |
| `nameservers` | `[ім'я, …]` або `[{"name": …, "addresses": [...]}, …]` | `<domain:ns>` із `<domain:hostObj>` або `<domain:hostAttr>` |
| `auth_info` | `str` | `<domain:authInfo><domain:pw>` |
| `license` | `str` | `<extension><registry:create><registry:license>` |
| `sec_dns` | `dict` | `<extension><secDNS:create>` (RFC 5910) |
| `fee` | `str` або `{"amount", "currency"}` | `<extension><fee:create>` (RFC 8748) |

Повна реєстрація з використанням усіх них:

```python
created = client.domain.create(
    "example.com.ua",
    years=2,
    registrant="C1",
    contacts={"admin": "EXAMPLE-C2", "tech": ["EXAMPLE-C3", "EXAMPLE-C4"]},
    nameservers=["ns1.example.com.ua", "ns2.example.com.ua"],
    auth_info="D0main-Pw!",
    license="TM-2026-000123",                       # якщо ваш реєстр його вимагає
    sec_dns={"ds_data": [{"key_tag": 12345, "alg": 13,
                          "digest_type": 2, "digest": "49FD46E6C4B45C55D4AC"}]},
    fee="200.00",                                 # межа, а не ціна
)

created.code()          # 1000, або 1001, коли реєстр ставить реєстрацію в чергу
created.object_name()   # 'example.com.ua'
created.created_date()  # crDate
created.expiry_date()   # exDate — збережіть це; renew() має процитувати це назад
created.fee_amount()    # '200.00' — те, що було насправді списано
```

### years

Цілі роки, у межах діапазону зони (1–10 за замовчуванням), і отримана дата завершення терміну
реєстрації не може перетнути горизонт реєстру. Період поза діапазоном це 2004; менший за мінімум
зони — 2306.

### registrant і contacts

`contacts` приймає **або один ідентифікатор на роль, або кілька**:

```python
contacts={"admin": "EXAMPLE-C2", "tech": ["EXAMPLE-C3", "EXAMPLE-C4"]}
```

Кожен ідентифікатор стає власним елементом `<domain:contact type="tech">` — саме це дозволяє
RFC 5731 і саме це реєстр розбирає назад у список на кожну роль. Порожні або `None`-ідентифікатори
відкидаються, а не надсилаються як порожні елементи. Реєстр приймає щонайбільше 8 ідентифікаторів
в одній ролі (понад це — 2306) і 16 загалом.

Які ролі зона *вимагає* — це власне правило зони; create без обов'язкової ролі це 2003.

### nameservers, в обох моделях

RFC 5731 робить `<domain:ns>` вибором між двома способами назвати сервер імен, і реєстр бере один
або інший. Запитайте свій, який саме:

```python
# Об'єкти хостів: ім'я посилається на хост, який ви створили заздалегідь (див. hosts.md).
nameservers=["ns1.example.com.ua", "ns2.example.com.ua"]

# Вбудовані glue-адреси: ім'я приходить разом зі своїми адресами, без жодного об'єкта хоста.
nameservers=[
    {"name": "ns1.example.com.ua", "addresses": ["203.0.113.10", "2001:db8::10"]},
    {"name": "ns2.example.com.ua", "addresses": ["203.0.113.11"]},
]
```

IPv4 та IPv6 розрізняються за самим записом адреси, тож кожна отримує правильний атрибут
`ip="v4"` / `ip="v6"` без ваших вказівок.

**Ці дві моделі не можна змішувати в одній команді.** Список, що містить і звичайний рядок, і
словник, викидає `ValidationException` ще до того, як щось буде надіслано, — схема все одно відхилила
б кадр, і відхилила б його голим 2001, який не називає жодного поля, а це значно гірше налагоджувати.

Домен, створений узагалі без серверів імен, є легітимним і повідомляє обчислений статус `inactive`.
Це не помилка; це означає, що домен ще не делеговано.

### auth_info

`<domain:authInfo>` є обов'язковим у `domain:create`, тож елемент вирушає завжди. Передайте код — і
він стане секретом для трансферу; пропустіть його — і буде надіслано порожній `<domain:pw/>`, що
просить реєстр застосувати власну політику зони і згенерувати код. Прочитайте згенерований код назад
через `client.domain.info(name).auth_info()`.

Наданий вами код має задовольняти політику надійності зони — мінімальну довжину і кількість класів
символів — інакше create буде відхилено з 2306.

Будь-хто, хто має цей код, може перевести домен до іншого реєстратора. Поводьтеся з ним як з
обліковими даними: ніколи не пишіть його в журнал і встановлюйте новий після того, як передали
його клієнтові.

### Ліцензія

Деякі реєстри не реєструють окремі імена без номера торговельної марки або ліцензії — найчастіше це
короткі й дорогі імена безпосередньо під доменом верхнього рівня. Він надсилається у **власному**
розширенні реєстру, і його простір імен клієнт читає з `<greeting>`, тож реєстру, який такого
розширення не оголошує, замість кадру, який той би проігнорував, буде кинуто `ConfigException`. Див.
[Команди](commands.md#власні-розширення-вашого-реєстру).

Яким саме іменам він потрібен — це політика реєстру, а не протоколу, тож питайте у свого. Пропуск
обов'язкового зазвичай це 2003; ліцензія, надіслана туди, де на неї не чекають, — 2306.

### DNSSEC під час create

`sec_dns` будує блок `<secDNS:create>` (RFC 5910). Дві форми запису, і обидві можуть бути присутні:

```python
sec_dns={
    "ds_data": [
        {"key_tag": 12345, "alg": 13, "digest_type": 2, "digest": "49FD46E6C4B45C55D4AC"},
        # DS-запис може нести DNSKEY, з якого його обчислено, якщо реєстр це приймає:
        {"key_tag": 54321, "alg": 13, "digest_type": 2, "digest": "A1B2C3D4E5F60718293A",
         "key_data": {"flags": 257, "protocol": 3, "alg": 13, "pub_key": "AwEAAb…"}},
    ],
    "key_data": [{"flags": 257, "protocol": 3, "alg": 13, "pub_key": "AwEAAb…"}],
    "max_sig_life": 1209600,
}
```

Кожен ключ приймається також у власному camelCase-написанні з RFC: `dsData`, `keyData`, `keyTag`,
`digestType`, `pubKey`, `maxSigLife`. **Будь-що інше викидає `ValidationException`**, називаючи
найближчий ключ, який воно розпізнає. Ця відмова і є суттю: ключ параметра, якого ніхто не читає,
мовчки відсутній у кадрі, реєстр відповідає 1000 на ту команду, яку справді отримав, — і у вас
непідписаний домен, який кожна частина вашої системи вважає підписаним.

Сам по собі `max_sig_life` не породжує нічого — `<secDNS:create>` потребує принаймні одного
DS-запису або запису ключа, тож `sec_dns` без записів просто не потрапляє в кадр, а не
надсилається недійсним порожнім блоком.

Реєстр приймає SHA-256 (`digest_type` 2) і SHA-384 (`digest_type` 4), до 6 DS-записів на домен, і
відхиляє дублікати. Команда DNSSEC у зоні, яка не пропонує DNSSEC, це 2103 або 2306.

### fee

Необов'язковий, і це **межа, а не ціна**: «я погоджуюся заплатити щонайбільше стільки». Без нього
реєстр стягує власну ціну і команда виконується. З ним вища реальна ціна відхиляє команду з 2004
і не стягує нічого. Див. [Баланс і ціни](balance.md#обмеження-того-що-ви-погоджуєтеся-заплатити).

| Код | Значення |
|---|---|
| 1000 | зареєстровано |
| 1001 | поставлено в чергу; результат надходить як [poll-сповіщення](poll.md) |
| 2003 | бракує обов'язкового елемента — ролі, якої вимагає зона, або ліцензії, якої вона вимагає |
| 2004 | період поза діапазоном, або погоджена комісія не покриває ціну |
| 2005 | значення некоректне (погана мітка, погана адреса) |
| 2103 | DNSSEC не пропонується в цій зоні |
| 2104 | недостатньо коштів — викидається як `InsufficientFundsError`; зупиніть пакет |
| 2302 | уже зареєстровано |
| 2306 | правило реєстру відхиляє значення: слабкий `auth_info`, забагато контактів в одній ролі, ліцензія там, де вона не застосовується |
| 2307 | зона не обслуговується |

## update

```python
client.domain.update(name: str, *,
                     add: Optional[Dict[str, Any]] = None,
                     rem: Optional[Dict[str, Any]] = None,
                     chg: Optional[Dict[str, Any]] = None,
                     restore: bool = False,
                     license: Optional[str] = None,
                     sec_dns: Optional[Dict[str, Any]] = None,
                     fee: Optional[FeeAgreement] = None) -> Response
```

Update в EPP — це **дельта, а не заміна**. Те, чого ви не згадали, лишається точно таким, як було, а
те, до якого з трьох блоків належить зміна, і є всією семантикою команди.

### add і rem

Обидва приймають ті самі три ключі, і обидва будують блок лише тоді, коли ви їм щось дали:

| Ключ | Тип | Дія |
|---|---|---|
| `ns` | список, у будь-якій моделі серверів імен | делегувати цим серверам імен / припинити делегування |
| `contacts` | `{роль: ідентифікатор}` або `{роль: [ідентифікатор, …]}` | прикріпити / відкріпити контакти в ролі |
| `statuses` | `[str, …]` | встановити / зняти клієнтський статус |

```python
client.domain.update(
    "example.com.ua",
    add={"ns": ["ns3.example.com.ua"],
         "contacts": {"tech": "EXAMPLE-C4"},
         "statuses": ["clientHold"]},
    rem={"ns": ["ns2.example.com.ua"],
         "statuses": ["clientTransferProhibited"]},
)
```

Клієнтські статуси, які ви можете встановлювати, — це `clientHold`, `clientDeleteProhibited`,
`clientUpdateProhibited`, `clientTransferProhibited` та `clientRenewProhibited`. Відповідники
`server*` належать реєстру, і команда, що намагається встановити такий, відхиляється. `clientHold`
виводить домен з DNS — ім'я перестає розв'язуватися, — тож це зміна, яку варто підтверджувати, а не
прапорець, який варто перемикати.

### chg

`chg` змінює два поля домену, що мають одне значення:

| Ключ | Дія |
|---|---|
| `registrant` | передати домен іншому власникові |
| `auth_info` (або `authInfo`) | замінити секрет для трансферу |
| `clear_auth_info` (або `clearAuthInfo`) | прибрати секрет для трансферу зовсім |

```python
client.domain.update("example.com.ua",
                     chg={"registrant": "EXAMPLE-C9", "auth_info": "New-Str0ng!"})
```

Будь-який інший ключ викидає `ValidationException`, з підказкою, коли помилка схожа на одрук. Тихо
проігнорований ключ — це зміна, яка не відбулася за фасадом 1000, і ви ніяк не дізнаєтеся про це з
відповіді, бо з погляду реєстру ви ніколи про неї не просили.

Зміну реєстранта багато зон трактують як зміну власності з власними правилами, тож відмова там
зазвичай є політикою (2306), а не некоректною командою.

### Відкликання скомпрометованого коду трансферу

Якщо секрет для трансферу витік, встановлення порожнього вам не допоможе: порожній пароль — це
все одно значення, яке той, хто його має, може пред'явити, і домен лишається рівно так само
рухомим. У протоколі є окрема форма для прибирання — `<domain:authInfo><domain:null/>` — і саме її
надсилає `clear_auth_info`:

```python
# Коду більше немає. Жоден код не зрушить цей домен, доки ви не встановите новий.
client.domain.update("example.com.ua", chg={"clear_auth_info": True})

# Пізніше, коли клієнтові законно знадобиться код знову:
client.domain.update("example.com.ua", chg={"auth_info": "Fresh-C0de!"})
```

Встановити й прибрати в одній команді — це суперечність, якої схема виразити не може, тож передача
одночасно `auth_info` та `clear_auth_info` викидає `ValidationException`, а не обирає щось одне
мовчки.

Зауважте також, що реєстр рахує вік коду: він придатний для трансферу протягом 30 днів з моменту,
коли його **встановлено**, а не з моменту, коли трансфер починається. Код, виданий сьогодні і
використаний через п'ять тижнів, відхиляється з 2202, навіть якщо він збігається, — доведеться
встановити новий.

### DNSSEC під час update

Update несе дельту `<secDNS:update>`, і це інша форма, ніж блок для create:

```python
# Замінити один ключ іншим однією командою, без проміжку, коли домен лишається непідписаним.
client.domain.update("example.com.ua", sec_dns={
    "rem": {"ds_data": [{"key_tag": 12345, "alg": 13,
                         "digest_type": 2, "digest": "49FD46E6C4B45C55D4AC"}]},
    "add": {"ds_data": [{"key_tag": 54321, "alg": 13,
                         "digest_type": 2, "digest": "A1B2C3D4E5F60718293A"}]},
})

# Повністю зняти підпис.
client.domain.update("example.com.ua", sec_dns={"rem_all": True})

# Замінити весь набір ключів: прибрати все і додати новий набір разом.
client.domain.update("example.com.ua", sec_dns={
    "rem_all": True,
    "add": {"ds_data": [{"key_tag": 54321, "alg": 13,
                         "digest_type": 2, "digest": "A1B2C3D4E5F60718293A"}]},
})

# Змінити лише час життя підпису.
client.domain.update("example.com.ua", sec_dns={"max_sig_life": 1209600})
```

| Ключ | Дія |
|---|---|
| `add` | відображення з `ds_data` та/або `key_data`, що додається до того, що домен уже має |
| `rem` | та сама форма; кожне поле має точно збігатися із записом, який зберігає реєстр |
| `rem_all` (або `remAll`) | прибрати всі ключі |
| `max_sig_life` (або `maxSigLife`) | задати час життя підпису в секундах; може подорожувати самотою |

В update записи живуть **усередині `add` та `rem`**. `ds_data` на верхньому рівні — це написання
для create, і в дельті воно не має значення.

`sec_dns={}` не надсилає жодного `<secDNS:update>`. Порожній блок був би 2003 за те, що читається як
відсутність дії, — а це саме той випадок, у який потрапляє клієнт, що будує блок беззастережно й
заповнює його лише інколи.

Прибрати конкретний запис і прибрати все неможливо виразити однією командою; те саме стосується
[білдера update](builders.md), який відхиляє це поєднання поіменно.

### Ліцензія та комісія під час update

`license=` надсилає `<registry:update><registry:license>`, щоб змінити номер торгової марки. `fee=` обмежує
платний update так само, як і create.

| Код | Значення |
|---|---|
| 1000 | застосовано |
| 1001 | поставлено в чергу; результат надходить через [poll](poll.md) |
| 2003 | бракує обов'язкового параметра, або команда взагалі не несе жодної зміни |
| 2004 | значення поза діапазоном, або погоджена комісія не покриває ціну |
| 2005 | значення некоректне |
| 2303 | такого домену немає |
| 2304 | статус це забороняє (`clientUpdateProhibited`, `serverUpdateProhibited`, трансфер, що очікує) |
| 2305 | асоціація це забороняє |
| 2306 | правило реєстру відхиляє значення: слабкий `auth_info`, зміна реєстранта, якої зона не дозволяє |

## delete

```python
client.domain.delete(name: str) -> Response
```

```python
info = client.domain.info("example.com.ua")
if info.subordinate_hosts():
    raise RuntimeError("hosts still live under this domain: %s" % info.subordinate_hosts())

client.domain.delete("example.com.ua")
```

Що саме *робить* delete, залежить від того, коли ви його надішлете. У межах вікна add-grace (5 днів
від реєстрації) домен видаляється негайно. Після цього він переходить у `redemptionPeriod` на
30 днів — видно в `rgp_status()`, а не в `statuses()` — і протягом цього часу його можна повернути
через [restore](#restore). Далі він проводить 5 днів у `pendingDelete`, і ім'я вивільняється.

Спершу перевірте `subordinate_hosts()`, як вище: реєстр відмовляється видаляти домен, поки під ним
живуть об'єкти серверів імен, а 2305 постфактум — це зайвий обмін кадрами.

| Код | Значення |
|---|---|
| 1000 | видалено або переведено у викуп |
| 1001 | поставлено в чергу; результат надходить через [poll](poll.md) |
| 2303 | такого домену немає |
| 2304 | статус це забороняє (`clientDeleteProhibited`, `serverDeleteProhibited`) |
| 2305 | під доменом досі існують підпорядковані хости |

## renew

```python
client.domain.renew(name: str,
                    cur_exp_date: str,
                    years: int = 1,
                    fee: Optional[FeeAgreement] = None) -> Response
```

Продовжує реєстрацію. **Платна.** `cur_exp_date` вирушає як `<domain:curExpDate>` і має дорівнювати
поточній даті завершення терміну реєстрації домену — це запобіжник протоколу проти продовження
домену, який хтось уже продовжив, поки ваше уявлення про нього застаріло.

Цитуйте цю дату з реєстру, ніколи з власної календарної арифметики:

```python
info = client.domain.info("example.com.ua")
current = info.expiry_date()            # напр. '2027-04-01T09:15:00.0Z'

renewed = client.domain.renew("example.com.ua", current, 1, fee="180.00")   # піде '2027-04-01'

renewed.expiry_date()   # НОВА дата завершення — збережіть її
renewed.fee_amount()    # '180.00'
renewed.fee_currency()  # 'UAH'
```

`<domain:exDate>` — це мітка часу, а `<domain:curExpDate>` — дата, і денну частину бібліотека бере
за вас: такою, якою її написав сервер, без розбору і без переведення часових поясів. Це зроблено
навмисно: мітки часу в EPP — в UTC, і дата завершення в реєстру теж у UTC, тож клієнт, який
переформатовує її через місцевий пояс, для кожного домену, що завершується близько опівночі, влучає
на добу в той чи інший бік і далі продовжує за датою, якої в реєстру немає. Переводьте в місцевий
час там, де показуєте, а не перед надсиланням назад.

Нова дата завершення не може перетнути власний горизонт реєстру — зазвичай це десять років.

Розбіжність це 2105, і 2105 — та відповідь, яку варто обробити окремо: вона означає, що дата
завершення домену не така, як ви думали, а це проблема звіряння, а не те, що виправить повторна
спроба.

| Код | Значення |
|---|---|
| 1000 | продовжено |
| 2004 | період поза діапазоном, або погоджена комісія не покриває ціну |
| 2104 | недостатньо коштів — `InsufficientFundsError` |
| 2105 | `cur_exp_date` не збігається, або домен не підлягає продовженню |
| 2303 | такого домену немає |
| 2304 | статус це забороняє (`clientRenewProhibited`, трансфер, що очікує) |
| 2306 | правило реєстру відхиляє запит |

## transfer

```python
client.domain.transfer(op: str,
                       name: str,
                       auth_info: Optional[str] = None,
                       years: Optional[int] = None,
                       fee: Optional[FeeAgreement] = None) -> Response
```

`op` — одне з `request`, `approve`, `reject`, `cancel`, `query`, і йде в канал передачі як атрибут
`op` елемента `<transfer>`. Які з них ви можете надсилати, залежить від того, на якому боці
трансферу ви перебуваєте.

```python
# Бік, що приймає: попросити домен, процитувавши код, який клієнт отримав від реєстратора, що втрачає.
r = client.domain.transfer("request", "example.com.ua", "the-code", 1, fee="180.00")

r.code()                # 1001 — трансфер вирішується згодом, а не зараз
t = r.transfer()
t["status"]             # 'pending'
t["requested_by"]       # reID — реєстратор, який попросив
t["requested_at"]       # reDate
t["acting_client"]      # acID — реєстратор, який має відповісти
t["act_by"]             # acDate — КРАЙНІЙ СТРОК
t["expiry_date"]        # дата завершення, яка діятиме після завершення трансферу
```

```python
# Бік, що втрачає: poll-сповіщення повідомило, що хтось хоче домен, яким ви володієте.
client.domain.transfer("approve", "example.com.ua")
client.domain.transfer("reject", "example.com.ua")

# Бік, що приймає, передумав, поки запит ще очікує:
client.domain.transfer("cancel", "example.com.ua")

# Будь-який бік, будь-коли — повідомляє, на якій стадії запит, і нічого не змінює:
client.domain.transfer("query", "example.com.ua").transfer_status()   # 'pending'
```

Три речі про `act_by`, від яких залежить, чи збережете ви домен:

- **Мовчання завершує трансфер.** Після строку реєстр *підтверджує* його — він його не скасовує.
  Реєстратор, що втрачає домен і підшиває сповіщення замість того, щоб на нього відповісти, втрачає
  домен, а вікно становить 5 днів.
- Обидва реєстратори дізнаються про кожен крок через [poll](poll.md). Сповіщення про трансфер — це
  те, на що відповідають, а не те, що записують.
- Поки встановлено `pendingTransfer`, жодна інша операція з доменом не приймається.

`years` надсилає `<domain:period>`, і це справа зони, а не ваш вибір: у регламентних зонах трансфер
включає обов'язкове продовження на один рік, тож `1` (або пропуск) — єдине прийнятне значення, а
будь-яке інше це 2004. У зонах з безплатним трансфером ви не вказуєте його взагалі — літеральний `0`
не є меншим періодом, а є порушенням схеми, бо тип елемента починається з 1, і кадр відхиляється як
2001 ще до того, як спрацює будь-яка політика.

`auth_info` несе код. У зоні, яка не використовує кодів трансферу, не вказуйте його.

| Код | Значення |
|---|---|
| 1000 / 1001 | прийнято; 1001 означає, що результат надійде згодом через [poll](poll.md) |
| 2004 | значення `years`, якого зона не приймає |
| 2106 | об'єкт не підлягає трансферу (заблокований або заборонений статусом) |
| 2201 | ви не є стороною, яка може надіслати цю операцію |
| 2202 | `auth_info` неправильний або перевищив свій 30-денний строк придатності |
| 2300 | трансфер уже очікує (на повторному `request`) |
| 2301 | трансфер не очікує (на `approve`/`reject`/`cancel`/`query`) |
| 2303 | такого домену немає |
| 2304 | статус це забороняє |

## restore

```python
client.domain.restore(name: str, fee: Optional[FeeAgreement] = None) -> Response
```

Повертає домен, що перебуває в `redemptionPeriod` (RFC 3915). **Платна**, і ціна відновлення
зазвичай у кілька разів перевищує реєстрацію.

Це зручна обгортка над `update`: `restore(name, fee)` — це точно
`update(name, restore=True, fee=fee)`, що надсилає `domain:update` без жодного блоку add, rem чи chg
і з розширенням `<rgp:update><rgp:restore op="request"/>`.

```python
info = client.domain.info("example.com.ua")
if "redemptionPeriod" not in info.rgp_status():
    raise RuntimeError("not in redemption; nothing to restore")

r = client.domain.restore("example.com.ua", fee={"amount": "1200.00", "currency": "UAH"})

r.code()             # 1000 відновлено зараз, або 1001 відновлено згодом
r.expiry_date()      # дата завершення після відновлення
r.fee_amount()       # скільки це коштувало
```

**Відновлення має бути єдиним вмістом команди.** Поєднання `restore=True` зі зміною `add`, `rem`,
`chg`, ліцензії чи DNSSEC у тому самому `update` відхиляється з 2306; переспрямуйте сервери імен
другою командою, коли домен уже повернувся.

1001 тут є нормальним у деяких зонах: реєстр відкладає відновлення, позначає домен як
`pendingUpdate`, і результат надходить як poll-сповіщення. Не надсилайте команду повторно — друга
команда, поки перша ще в дорозі, це те, як комісія за відновлення сплачується двічі.

| Код | Значення |
|---|---|
| 1000 | відновлено |
| 1001 | поставлено в чергу; результат надходить через [poll](poll.md) |
| 2104 | недостатньо коштів — `InsufficientFundsError` |
| 2303 | такого домену немає |
| 2304 | домен не в періоді викупу, вікно закрилося, або статус забороняє update |
| 2306 | відновлення було не єдиною операцією в команді |

## Коли команда перетворення зривається, а ви не знаєте, чи вона відбулася

Обірване з'єднання або тайм-аут читання посеред `create`, `renew`, `transfer` чи `restore` лишає
по-справжньому невідомий результат: реєстр міг виконати команду і списати з вас гроші ще до того,
як відповідь загубилася.

**Не повторюйте команду наосліп.** Сліпа повторна спроба — це те, як домен реєструється і
оплачується двічі. Замість цього запитайте реєстр, як є насправді: `domain.info()` для create, а
для renew — порівняйте `expiry_date()` з тим, чого ви очікували. Повторюйте лише тоді, коли об'єкт
справді перебуває в тому стані, з якого ви починали. [Помилки](errors.md) розглядають це повністю.
