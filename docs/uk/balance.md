# Баланс і ціни

На цій сторінці живуть дві речі, і вони відповідають на два грошові питання, які має будь-яка
інтеграція: **що я можу витратити** і **скільки це коштуватиме**.

Перше — це `client.balance()`, власний запит реєстру про обліковий запис. Друге — **розширення
комісій RFC 8748**, яке їде причепом на командах, що ви й так надсилали: `check` може запитати ціну,
а `create`, `renew`, `transfer` чи `restore` можуть нести межу того, що ви погоджуєтеся заплатити.

Кожна сума в цьому посібнику є ілюстративною. Тариф реєстру публікує сам реєстр.

## Гроші — це рядок

**Кожен показник на цій сторінці повертається як точний десятковий рядок, ніколи як `float`.**
`0.1 + 0.2` у двійковій рухомій комі не дорівнює `0.3`, і баланс, підсумований або порівняний у
такий спосіб, дрейфує — тихо і в тому напрямку, якого ніхто не помічає аж до звіряння. Тримайте
рядок для зберігання і використовуйте `decimal.Decimal` для арифметики:

```python
from decimal import Decimal

spendable = Decimal(client.balance().available_credit() or "0")
if spendable < Decimal("500.00"):
    stop_the_batch()
```

## Команда балансу

```python
client.balance() -> Response
```

Надсилає команду `<info>` у власному просторі імен балансу реєстру, який читається з `<greeting>` —
див. [`client.registry_balance_uri()`](commands.md#власні-розширення-вашого-реєстру). Вона не платна,
нічого не змінює, і її безпечно запускати за розкладом.

```python
money = client.balance()

money.balance()            # {'creditLimit': '1000.00', 'balance': '250.50',
                           #  'availableCredit': '1250.50'}
money.credit_limit()       # '1000.00'
money.current_balance()    # '250.50'
money.available_credit()   # '1250.50'
```

| Аксесор | Повертає | Коли відповідь нічого не несе |
|---|---|---|
| `balance() -> Optional[Dict[str, str]]` | Усі три показники одразу, за ключами `creditLimit`, `balance`, `availableCredit` | `None`, коли це не відповідь про баланс |
| `credit_limit() -> Optional[str]` | Кредит, який реєстр надає **понад** нульовий баланс | `None` |
| `current_balance() -> Optional[str]` | Кошти на обліковому записі просто зараз | `None` |
| `available_credit() -> Optional[str]` | Те, що ви справді можете витратити — баланс плюс невикористаний кредит | `None` |

Ці три не є взаємозамінними, і той, за яким варто пропускати пакет, — третій:

- `current_balance()` може дорівнювати нулю, а ви й досі здатні реєструвати домени, бо кредитна
  лінія нікуди не поділася.
- `credit_limit()` — це стеля, а не гроші. Він не зменшується, коли ви витрачаєте.
- `available_credit()` — це число, яке досягає нуля тієї миті, коли наступна платна команда починає
  зриватися з 2104.

`balance()` повертає `None` на будь-якій відповіді, що не є відповіддю про баланс, тож випадковий
виклик на не тій відповіді дає вам `None`, а не хибне число.

| Код | Значення |
|---|---|
| 1000 | відповідь отримано |
| 2103 | ця точка підключення не обслуговує розширення балансу |

Запит балансу не описаний у жодному RFC, тож реєстр може його й не пропонувати — і клієнт знає про
це ще до надсилання, з привітання. `balance()` підіймає `ConfigException`, а не надсилає кадр, який
сервер проігнорує, тож можна й просто спитати:

```python
client.connect()
if client.registry_balance_uri() is None:
    ...                     # запиту про рахунок тут немає; попросіть реєстр про нього
```

### Стежте за ним

Читайте баланс перед пакетом, а не після того, як він зірветься. 2104 посеред запуску викидає
[`InsufficientFundsError`](errors.md#ієрархія-винятків), і кожна наступна платна команда в цьому
запуску зривається так само, тож цикл перемелює свою чергу, породжуючи однакові збої, доки ви його
не спините.

Реєстр також попереджає вас, перш ніж на рахунку скінчаться кошти, і це попередження надходить як
[poll-сповіщення](poll.md#попередження-про-низький-баланс). Отже, спорожнення черги — частина
білінгу, а не лише реєстрацій.

## Звідки береться ціна

Три різні відповіді на три різні питання:

| Питання | Як питаєте | Що читаєте |
|---|---|---|
| Скільки коштуватиме мені це ім'я? | `domain.check(names, fee={...})` | `fees()`, `fee_for()` |
| За скільки продовжується домен, який я вже тримаю? | `domain.info(name)` | `prices()`, `price_channel()` |
| Скільки списала та команда? | будь-яка команда перетворення | `charged_fee()`, `fee_amount()` |

Перше — це RFC 8748 і основна частина цієї сторінки. Розширення необов'язкове з обох боків: без
аргументу `fee=` нічого не змінюється, і реєстр стягує власну ціну.

## Запит ціни під час check

```python
client.domain.check(names: List[str],
                    fee: Optional[Dict[str, Any]] = None,
                    currency: Optional[str] = None) -> Response
```

`fee` зіставляє **операцію** з **кількістю років**, на які її тарифікувати. Він додає причіпний блок
`<fee:check>` у `<extension>`, тож доступність і ціна надходять за один обмін кадрами:

```python
r = client.domain.check(["example.com.ua"], fee={"create": 1, "renew": 1})

r.is_available("example.com.ua")                 # True
r.fee_for("example.com.ua", "create", 1)         # '100.00'
r.fee_for("example.com.ua", "renew", 1)          # '90.00'
r.fees()["_currency"]                            # 'UAH'
```

Операції, які ви можете назвати, — це `create`, `renew`, `transfer`, `restore`, `update` та
`delete` — по одному `<fee:command name="…">` на кожну, з `<fee:period unit="y">`.

Період менший за один рік виразити неможливо: тип періоду в схемі починається з 1, і `0`, який ви
передасте, буде надіслано як `1`, а не як кадр, що його реєстр відхилить.

Решта `check` — обмеження в десять імен на команду, `availability()`, `is_available()`, що повертає
`None`, — описана в розділі [Домени → check](domains.md#check).

### Ціла таблиця цін за одну команду

**Список** років питає ту саму операцію на кожному періоді, тож таблиця цін із п'яти рядків коштує
один обмін кадрами замість п'яти:

```python
table = client.domain.check(["example.com.ua"],
                            fee={"create": [1, 2, 3, 5, 10], "renew": [1, 2]},
                            currency="UAH")

table.fee_for("example.com.ua", "create", 5)     # '480.00'
table.fee_for("example.com.ua", "create", 10)    # '940.00'
table.fee_for("example.com.ua", "renew", 2)      # '175.00'
```

**Кадр несе щонайбільше 20 записів про комісії.** Записи рахуються по всіх операціях разом, тож
приклад вище використовує сім із них: п'ять періодів create і два періоди renew.

Понад двадцять — і бібліотека викидає `ValidationException`, не надіславши нічого:

```python
client.domain.check(["example.com.ua"], fee={"create": list(range(1, 22))})
# ValidationException: a fee query carries at most 20 entries; this one has 21
```

Відмова тут, а не в каналі передачі, — це різниця між повідомленням, яке називає обмеження, і 2306,
який не називає нічого. Обмеження доступне як `MAX_FEE_COMMANDS` в `epptools.commands`, якщо ви
волієте формувати пакети за константою, а не за числом.

### transfer і restore — операції на один рік

Скажемо прямо, бо запитувати інакше означає марнувати записи і хибно читати відповідь:

> **`transfer` та `restore` тарифікуються на один рік, скільки б років ви не запитали.** Відповідь
> повторює той період, який справді було протарифіковано, тобто один.

```python
r = client.domain.check(["example.com.ua"], fee={"transfer": [1, 2, 5]})

r.fee_for("example.com.ua", "transfer", 1)   # '180.00' — це відповідь
r.fee_for("example.com.ua", "transfer", 5)   # None — на п'ять років нічого не тарифікували
```

Питайте ці дві на один рік і читайте їх назад на один рік. `fee_for()` зіставляє за періодом у
*відповіді*, тож пошук на періоді, якого реєстр не котирував, повертає `None`, а не показник із
сусіднього рядка.

У регламентних зонах трансфер також несе обов'язкове продовження на один рік, і це окреме питання,
відмінне від періоду тарифікації, — див. [Домени → transfer](domains.md#transfer).

### Явне зазначення валюти

`currency` просить котирування у названій вами валюті. Вона вирушає у верхньому регістрі, в
`<fee:currency>`:

```python
r = client.domain.check(["example.com.ua"], fee={"create": 1}, currency="UAH")
r.fees()["_currency"]        # 'UAH'
```

Пропустіть її — і отримаєте власну валюту реєстру. Валюта, в якій реєстр **не** тарифікує,
повертається як недоступний запис із причиною, і ніколи як перерахований здогад, бо перерахунок,
якого реєстр не робив, — це число, яке ніхто не визнає:

```python
r = client.domain.check(["example.com.ua"], fee={"create": 1}, currency="XXX")
entry = r.fees()["example.com.ua"]
entry["avail"]      # False
entry["reason"]     # 'Currency not supported'
```

Передавайте `currency` разом з `fee`. Самої по собі реєстру нічого тарифікувати.

## Читання відповіді

`fees()` повертає всю таблицю за ключами-іменами, плюс ключ `_currency`:

```python
r.fees()
# {'_currency': 'UAH',
#  'example.com.ua': {
#      'avail': True,
#      'reason': None,
#      'class': 'premium',                      # присутній, лише коли реєстр його оголосив
#      'commands': {'create': {'years': 1, 'fee': '100.00'},
#                   'renew':  {'years': 1, 'fee': '90.00'}},
#      'periods': [{'op': 'create', 'years': 1,  'fee': '100.00'},
#                  {'op': 'create', 'years': 5,  'fee': '480.00'},
#                  {'op': 'create', 'years': 10, 'fee': '940.00'},
#                  {'op': 'renew',  'years': 1,  'fee': '90.00'}]}}
```

| Ключ | Що містить |
|---|---|
| `_currency` | Валюта, в якій наведено кожне котирування в таблиці |
| `avail` | Чи можна було взагалі протарифікувати це ім'я; `False` іде разом із `reason` |
| `reason` | Чому ні: зона не обслуговується, у цій валюті не тарифікують, операція не пропонується |
| `class` | Клас комісій реєстру, присутній, лише коли реєстр його оголосив |
| `commands` | По одному запису на операцію — **перший** запитаний період |
| `periods` | Кожне котирування, у тому порядку, в якому їх несла відповідь |

`commands` має ключем саму лише операцію, тож містить один запис на операцію, скільки б періодів ви
не запитали. `periods` містить їх усі. Коли ви запитували кілька періодів, читайте `periods` — або
дозвольте `fee_for()` дістати потрібне:

| Аксесор | Повертає | Коли відповідь нічого не несе |
|---|---|---|
| `fees() -> Dict[str, object]` | Таблицю вище | `{}`, коли відповідь не несла даних про комісії |
| `fee_for(name, operation, years=1) -> Optional[str]` | Одне котирування як точний десятковий рядок | `None`, коли для цього поєднання нічого не котирували |
| `fee_class(name=None) -> Optional[str]` | `'premium'`, `'standard'` … | `None`, коли відповідь не оголосила класу |
| `is_premium(name=None) -> bool` | Чи тарифікується ім'я поза стандартним переліком | `False` |

```python
r = client.domain.check(["rare.com.ua"], fee={"create": 1})

if r.is_premium("rare.com.ua"):
    price = r.fee_for("rare.com.ua", "create", 1)
    require_operator_approval("rare.com.ua", price, r.fee_class("rare.com.ua"))
```

**`is_premium()`, що повертає `False`, не є обіцянкою стандартної ціни.** Це означає, що відповідь
не оголосила жодного особливого класу. Списуйте з `fees()` і обмежуйте саму команду перетворення —
про що йдеться в наступному розділі.

Недоступне ім'я — це звичайний 1000 з `avail: False`, а не помилка. Запис про комісію для імені,
яке реєстр не тарифікує, такий самий: звичайний, отриманий у відповіді й такий, що несе свою
причину.

## Обмеження того, що ви погоджуєтеся заплатити

Кожна команда перетворення, яку можна оплатити, приймає необов'язковий аргумент `fee`. Це **не
ціна, яку ви встановлюєте**. Реєстр стягує власну ціну; погодження — це найбільше, що ви згодні
заплатити:

> Якщо реальна ціна **вища** за погоджену вами, команду відхиляють з **2004** і **не стягують
> нічого**.

У цьому й полягає весь сенс надсилати погодження. Зміна тарифу, преміальне ім'я, котирування, яке у
вашому кеші застаріло на добу, — будь-що з цього мовчки візьме з вас різницю, якщо ви не надішлете
погодження, і відхилить команду навпростець, якщо надішлете.

```python
client.domain.create("example.com.ua", years=1, registrant="C1", fee="100.00")
client.domain.renew("example.com.ua", "2027-04-01", 1,
                    fee={"amount": "90.00", "currency": "UAH"})
client.domain.transfer("request", "example.com.ua", "the-code", 1, fee="180.00")
client.domain.restore("example.com.ua", fee="1200.00")
client.domain.update("example.com.ua", chg={"registrant": "EXAMPLE-C9"}, fee="50.00")
```

| Форма | Значення |
|---|---|
| `fee="100.00"` | до 100.00 у власній валюті реєстру |
| `fee={"amount": "100.00", "currency": "UAH"}` | до 100.00, і саме в цій валюті |

| Команда | Елемент, у якому подорожує погодження |
|---|---|
| `domain.create` | `<fee:create>` |
| `domain.renew` | `<fee:renew>` |
| `domain.transfer` | `<fee:transfer>` |
| `domain.update` | `<fee:update>` |
| `domain.restore` | `<fee:update>` — у каналі передачі відновлення є `domain:update` (RFC 3915) |

Сума має бути простим десятковим числом — цифри, за бажанням крапка і ще одна-дві цифри. `'100,00'`,
`'$100'` та `'1 000.00'` викидають `ValidationException` ще до того, як щось буде надіслано, бо
альтернатива — голий 2001, який не називає жодного поля і надходить уже після того, як команду
спробували виконати:

```python
client.domain.create("example.com.ua", years=1, registrant="C1", fee="100,00")
# ValidationException: fee amount must be a plain decimal like '100.00' (got '100,00')
```

`fee="0"` — це законне погодження («ця операція безплатна»), і воно надсилається саме так.

[Білдери](builders.md) несуть те саме під назвою, яка прямо говорить, що це:

```python
(client.domain.create_builder("example.com.ua")
    .years(1)
    .registrant("C1")
    .max_fee("180.00", "UAH")            # межа, на яку ви погоджуєтеся, а не ціна, яку ви задаєте
    .send())
```

### Що означає відмова з кодом 2004

2004 на команді перетворення, що несе погодження про комісію, означає: **ціна реєстру вища за
надіслане вами число, тож він не зробив нічого.** Домен не зареєстровано, продовження не відбулося,
і жодні гроші не рухалися. Це безпечна відмова, і правильна реакція — з'ясувати реальну ціну і
ухвалити рішення, а не прибрати межу й надіслати знову:

```python
from epptools.exceptions import CommandException

try:
    client.domain.create("example.com.ua", years=1, registrant="C1", fee="100.00")
except CommandException as exc:
    if exc.epp_code != 2004:
        raise
    quote = client.domain.check(["example.com.ua"], fee={"create": 1})
    price = quote.fee_for("example.com.ua", "create", 1)
    if approved_by_operator("example.com.ua", price):
        client.domain.create("example.com.ua", years=1,
                             registrant="C1", fee=price)
```

2004 — це також відповідь, коли період поза діапазоном, тож читайте повідомлення і `exc.reasons()`,
а не припускайте, що причиною була комісія.

Зверніть увагу на форму цього потоку: межу перевстановлено зі **свіжого котирування** і лише після
того, як хтось вирішив, що нова ціна прийнятна. Повторна спроба з прибраною межею повністю нищить
цей механізм — це те саме, що ніколи її не надсилати.

## Що насправді списала команда перетворення

Успішна команда перетворення, що несла погодження про комісію, повторює у відповіді, скільки вона
списала. Читайте це і зберігайте разом з об'єктом і svTRID:

```python
r = client.domain.renew("example.com.ua", "2027-04-01", 1, fee="180.00")

r.fee_amount()      # '180.00'  — те, що було насправді списано
r.fee_currency()    # 'UAH'
r.charged_fee()     # {'currency': 'UAH', 'fee': '180.00'}
r.expiry_date()     # нова дата завершення
r.sv_trid()         # ідентифікатор цієї операції в реєстрі
```

| Аксесор | Повертає | Коли відповідь нічого не несе |
|---|---|---|
| `charged_fee() -> Optional[Dict[str, str]]` | `{'currency': …, 'fee': …}` | `None` |
| `fee_amount() -> Optional[str]` | Саму лише суму | `None` |
| `fee_currency() -> Optional[str]` | Саму лише валюту | `None` |

`None` тут не означає «було безплатно»: реєстр, який не повторює розширення у відповіді, дає `None`,
хоча гроші з вас усе одно списано. Період звіряють ваш власний запис про те, скільки команда мала
коштувати, плюс баланс облікового запису — повторене значення є підтвердженням, а не реєстром
операцій.

---

## За якою ціною продовжується домен, який ви вже тримаєте

`domain:info` може нести власні цінові підказки реєстру для конкретного домену:

```python
info = client.domain.info("example.com.ua")

info.prices()          # {'renewal': {'value': '180.00', 'currency': 'UAH'}, …}
info.price_channel()   # '7' — з якого рядка опублікованого каталогу вони походять
```

Це діє на **домен**, а не на зону: ім'я, зареєстроване роки тому, може сидіти на іншому ціновому
каналі, ніж той, який використала б нова реєстрація в тій самій зоні, а `price_channel()` — це
непрозорий ідентифікатор, що зіставляє його з рядком каталогу. `prices()` дорівнює `{}`, коли
відповідь нічого не несла.

## Котирування, обмеження, реєстрація, звіряння

```python
from decimal import Decimal

from epptools import Client, Config
from epptools.exceptions import CommandException, InsufficientFundsError

name = "example.com.ua"

client = Client(Config(host="epp.registry.example", clid="EXAMPLE",
                       password="your-secret", ca_file="/etc/ssl/registry-ca.pem"))
client.connect()
client.login()

# 1. Чи можемо ми взагалі щось собі дозволити?
if Decimal(client.balance().available_credit() or "0") < Decimal("500.00"):
    raise SystemExit("top up before running the batch")

# 2. Доступність і ціна за один обмін кадрами.
quote = client.domain.check([name], fee={"create": [1, 2]}, currency="UAH")
if quote.is_available(name) is not True:
    raise SystemExit("%s: %s" % (name, quote.unavailable_reason(name) or "no answer"))

price = quote.fee_for(name, "create", 1)
if price is None:
    raise SystemExit("the registry quoted no create price for %s" % name)

# 3. Реєструємо, погоджуючись рівно на те, що було процитовано, і не більше.
try:
    created = client.domain.create(name, years=1, registrant="C1", fee=price)
except InsufficientFundsError:
    raise SystemExit("out of credit — stop the batch, top up, resume")
except CommandException as exc:
    if exc.epp_code == 2004:
        raise SystemExit("price moved since the quote; re-quote before retrying")
    raise

# 4. Звіряємо з тим, що було процитовано.
charged = created.fee_amount()
if charged is not None and Decimal(charged) != Decimal(price):
    alert_billing(name, quoted=price, charged=charged, sv_trid=created.sv_trid())

client.logout()
client.disconnect()
```

Гілка з 2004 — саме та, яку варто зберегти: це механізм у дії. Нічого не зареєстровано і нічого не
списано, а рішення про нову ціну належить людині або правилу, а не повторній спробі.

## Коди відповіді

| Код | Де | Значення |
|---|---|---|
| 1000 | `balance()`, `check` | відповідь отримано |
| 2004 | команда перетворення | погоджена комісія не покриває ціну — **нічого не списано** — або період поза діапазоном |
| 2004 | `check` | причіпний блок комісії запитав операцію, яку реєстр не тарифікує |
| 2103 | будь-де | ця точка підключення не обслуговує використане вами розширення |
| 2104 | команда перетворення | недостатньо коштів — викидається як `InsufficientFundsError`; зупиніть пакет |
| 2306 | `check` | понад 20 записів про комісії в одній команді |
| 2307 | `check` | зона не обслуговується |
